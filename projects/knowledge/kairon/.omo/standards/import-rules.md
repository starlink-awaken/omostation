# Kairon 跨包依赖边界规范

> 定义 kairon 包之间的允许/禁止 import 规则。
> 遵循"依赖根 → 共享层 → 业务层 → 外部集成层"的分层原则。

---

## 允许的跨包 import

```
✓ core-models → 任何包           （依赖根 — 核心模型定义）
✓ shared-lib   → 任何包           （共享工具 — 通用函数与类型）
✓ llm-gateway  → 需要 LLM 能力的包（LLM 抽象层统一接口）
```

## 禁止的跨包 import

```
✗ eidos ← kos                    （反向依赖 — 知识层不依赖记忆层）
✗ 业务层 → 外部集成层            （层级倒挂 — 业务不直接耦合外部服务）
✗ 循环依赖                        （A → B → A 模式禁止）
```

## 推荐的分包依赖原则

1. **单向依赖流**: `依赖根 → 共享层 → 业务层 → 接口层`
2. **接口隔离**: 跨包调用优先通过接口/协议（Protocol/ABC），避免直接导入具体实现
3. **共享能力优先提取**: 出现 2+ 使用者的功能，提取到 `shared-lib`
4. **LLM 调用统一**: 所有 LLM 调用通过 `llm-gateway` 统一接口

## 分层示意

```
┌─────────────────────────────────────────────┐
│  业务层                                      │
│  agora, minerva, kos, ontoderive, eidos, ... │
├─────────────────────────────────────────────┤
│  共享层                                      │
│  core-models, shared-lib, llm-gateway        │
├─────────────────────────────────────────────┤
│  接口/协议层                                  │
│  symphony-protocol, engine-core (接口)         │
└─────────────────────────────────────────────┘
```

## 违规处理

- **硬性违规**（循环依赖、反向依赖）：CI gate 阻止合入
- **软性违规**（违反推荐原则）：PR 需附带说明理由
