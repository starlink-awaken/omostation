# DigitalBrainOS Conductor 作战手册

## 目的

本手册定义 Conductor 如何驱动 DigitalBrainOS 的规划和执行，覆盖人类、本地 CLI、多 AI Agent。

## Conductor 循环

```text
感知 → 定框 → 拆解 → 分派 → 监控 → 集成 → 评估 → 记录
```

## 1. 感知

收集当前状态：

- active 任务包
- 文件变化
- 阻塞依赖
- 可用 Agent/工具
- 相关项目状态
- 最新决策

## 2. 定框

把用户意图转成：

- 战略目标
- 成功标准
- 约束
- 风险等级
- 必须产出的工件

## 3. 拆解

创建任务包，确保：

- 写入范围互不重叠
- owner role 清晰
- 验收标准明确
- 校验方法明确
- 依赖顺序明确

## 4. 分派

选择执行路径：

| 路径 | 适用场景 |
|---|---|
| 本地执行 | 简单文件、文档、脚本 |
| Codex | 代码库实现和审查 |
| Claude | 叙事设计、审查、推理 |
| Gemini/Qwen/Ollama | 替代分析或隐私摘要 |
| AgentMesh | Agent 执行路由 |
| Agora/MCP | 工具和服务调用 |

## 5. 监控

追踪：

- 任务包状态
- 产物路径
- 执行耗时
- 冲突
- 风险事件
- 校验失败

## 6. 集成

把输出合并到：

- 蓝图文档
- Schema
- Adapter
- Backlog
- ADR
- 复盘记录

## 7. 评估

检查：

- 是否满足验收标准
- 是否符合对象模型
- 是否存在治理风险
- 是否有校验证据
- 是否影响下游

## 8. 记录

更新：

- 任务包状态
- 决策记录
- 路线图
- 失败或复盘笔记
- 边界变化时更新资产地图

## 反模式

- 没有任务包就分派 Agent
- 写入范围重叠
- 没有校验就接受输出
- 让 CLI 输出未经审查直接成为真相
- 高风险操作绕过审批
