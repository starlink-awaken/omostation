# P95: 产出/收敛平衡的迭代节奏（复盘产入口）

## 陷阱表

| 陷阱 | 症状 | 对策 |
|------|------|------|
| 修想象中的问题 | 迭代选题来自推测而非数据 | 每轮入口必须是上轮复盘/首跑的实证发现 |
| 管道自指盲区 | 治理框架自身缺陷无人治 | 框架的每个组件都用框架自己的流水线审（v3 fuzzy 假阳性由管道使用过程抓出）|
| 自动晋升=自动入册 | 阈值触发的草案直接进规则库 | HITL 是流水线第五步的实体职责：判证据、敢退回（v5 退回 excerpt 不足的两条）|
| 一次治完 | "还有 79 条占位 justification"引发全量回填冲动 | 有数据的先评（gate-roi/pitfall/escape 画像），评审即回填时机（ADR-0443 Q14）|

## 纪律

1. **复盘产入口**：每轮复盘的最后一段必须是下一轮的实证入口清单——没有入口就没有下一轮。
2. **首班验证**：任何"管道"交付必须在真实生产数据上跑通一次才算 done（演练≠首班）。
3. **幂等自证**：周期管道跑两次，第二次应 fed 0 / bumped N（同坑聚合）——确定性证据。
4. **缺陷下沉规律**：健康迭代中，缺陷发现位置应从业务层逐步沉到治理层自身（观测数据→决策→知识管道→管道算法）——停滞在某层说明该层有未偿债。
5. **run 快照不可变**：workflow 改 verification 命令只影响新 run；旧 run 用 start 时快照——改命令后需幂等重跑而非改历史。

## 实证

- v1（#2744）：首跑照出 unspecified 33/71、pitfall 断头路、调度断链
- v2（#123/#2751/#2752）：减法 -184 行、风暴拆弹 42 日期、severity 引擎修正后**决策复核**（删不是因为尺子坏）
- v3（#2782）：add-A 三连事故五步入册第 81 条规则；暴露 fuzzy 假阳性
- v4（#2789）：词级交集修复；真数据演练三段全通（fed2/bumped3/promoted2）
- v5：主树首班同数字（确定性）；幂等自证（二跑 fed0/bumped5）；HITL 退回证据不足草案 ×2；excerpt 质量缺陷立为新入口

## 反模式

- 为节奏而迭代（入口清单空了还硬找活——停也是纪律）
- 复盘不写数字（"效果不错"不是验收）
- 演练冒充首班（/tmp 演练是验证语义，主树生产跑才是首班）
