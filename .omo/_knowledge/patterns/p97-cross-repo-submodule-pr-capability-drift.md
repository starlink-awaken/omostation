# P97 — Cross-Repo Submodule PR capability-registry Drift

**Pattern observed**: 2026-09-04 in BET-Y1Q4-HITL-01 (PR #3077).

## Problem

When a main-repo PR depends on a submodule-side change (e.g., main `bin/cockpit` calling a new submodule CLI), the main-repo's `docs/generated/capability-registry.yaml` is generated by scanning submodule sources. But CI checks out the PR with **origin/main's submodule pointer**, not the author's local submodule checkout. This causes:

- Author's local `gen-capability-registry.py --check` → PASS (uses author's local submodule)
- CI's `gen-capability-registry.py --check` → FAIL (uses origin/main's submodule, which lacks the new feature)

## Symptom

```
capability-registry drift (SSOT 同步)    FAIL
   ❌ 能力注册表漂移；运行 make sync-capability-registry 修复
```

## Root Cause

CI workflow uses `actions/checkout@v4` with `submodules: recursive` which fetches submodule pointers **from the PR's gitlinks** (which are origin/main's, not the author's). The capability-registry is generated against author's local submodule state, mismatch.

## Fix Pattern

1. **DO NOT bump submodule pointer** to point at the submodule PR commit (P97/P79 gitlink-ancestry gate will reject, requiring `gate-known-debt.yaml` fingerprint which is anti-pattern)
2. **Sync capability-registry to match the CI's view**: i.e., against origin/main's submodule state
3. After submodule PR merges, **then** bump the main repo's submodule pointer (with helper script)

```bash
# In worktree:
git fetch origin main
for sub in projects/*/; do
  sha=$(git rev-parse "origin/main:$sub")
  git -C "$sub" checkout "$sha"
done
make sync-all-docs
git add projects/* docs/generated/capability-registry.yaml
git commit -m "chore(docs): sync capability-registry to match submodule@origin/main"
```

## When to Apply

- ANY main-repo PR that adds code depending on a submodule-side change
- BEFORE creating the main-repo PR, sync docs against `git checkout origin/main` view
- DO NOT bump submodule pointer in main-repo PR if submodule-side PR is still open

## Counter-Pattern (Avoid)

```bash
# ❌ Anti-pattern: bump submodule pointer to point at the still-open submodule PR
git -C projects/cockpit checkout <submodule-PR-commit>
# This will:
# 1. Pass locally with [gitlink-regress: ...] exemption fingerprint
# 2. FAIL on PR push (P97 DIVERGED check)
# 3. Even if it passed, the submodule's PR may not merge, leaving the pointer dangling
```
