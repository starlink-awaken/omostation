# BET-Y1Q3-T10-110 retrospective

## Q1. What was intended?

Physically remove exactly two retired runner logs from Documents after T10-109
made them visible, while proving all human `_inbox` content unchanged and
retaining executable rollback.

## Q2. What happened?

The canonical quarantine primitive gained exact cache selection, full-root
classification, non-target guards, completed verification, and rollback. The
capability merged before host apply. Two identical plans and two no-handle
checks preceded one apply. Postflight and delayed verification passed, and the
root-oneoff registry records only this transaction.

## Q3. What changed during implementation?

TDD exposed the expected missing APIs. Diff review then found a more serious
manifest trust boundary: rollback could have trusted an outside-Documents
source path. A failing regression test was added before tightening source,
Documents, and target containment. This converted a plausible implementation
into a fail-closed recovery contract.

The legacy runtime default was preserved. Exact cache behavior activates only
when include paths and artifact kinds are supplied together.

## Q4. What was the surface accounting?

One existing library, two existing test files, one existing migration registry,
one BET record, one specification, one plan, one report, one retro, and one
waiver participate. No CLI file, registry family, dispatcher, ontology,
artifact kind, or control plane was added.

## Q5. What remains?

`root-oneoff-assets` is still pending because its historical eight-file
rollback package is missing and unrelated root/_inbox scope remains. The wider
Documents audit still contains large family-dashboard, learning external-tool,
Zotero, archive-contract, and other registered debt.

The next slice must be chosen from current family evidence; it must not treat
this two-file transaction as proof that the whole root-oneoff family is retired.

## Q6. What value is proven?

Engineering correctness, exact relocation, rollback availability, and
non-target preservation are proven. Principal-bound user value is not. The
system is more truthful and Documents contains two fewer machine artifacts,
but overall physical purity remains unproven.
