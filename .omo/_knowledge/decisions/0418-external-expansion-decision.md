# ADR-0418: 对外扩展决策 — 默认不做

## Context

按 [BET-Y3H2-T1-01](../../../docs/plans/3y-bet-ledger.yaml) 要求，在三年数据基础上对"是否服务他人"做一次明确决策。

## 源材料：三年规划 §2.1 边界（不做什么）

| 不做 | 理由 |
|------|------|
| 多租户 / 组织协作 / SaaS 化 | "一个人的" |
| 通用 Agent 平台 / Agent 市场 | 供给侧扩容 |
| 无人类出口的自动化 | 无法验收即无法证伪 |

## 三年数据（2026-08-18 实测）

| 维度 | 数值 | 对外含义 |
|------|------|---------|
| 项目数 | 18 | 已超单人可持有极限 |
| ADR | 418 份（含本轮 3 份） | 治理资产密度高但未对外输出 |
| 活跃服务端口 | 7 个 | 全部本地 127.0.0.1 监听 |
| 外部用户 | 0 | 无 SaaS / 无 API / 无文档站点 |
| 对外 PR/issue | 0 | 无社区互动证据 |

## Decision

**默认不做对外扩展。** 维持"一个人的业务操作系统"定位。

### 理由

1. **表面积已超限**：18 项目 / 72.6 万行 src / 418 ADR —— 系统已超单人可持有极限，对外扩展会加速崩溃。
2. **无验收能力**：对外服务需要 SLA / 支持 / 文档 —— 当前连内部"建议→采纳"度量都未建立。
3. **愿景锚定**：§0.3 愿景明确"一个人的"，对外扩展与愿景直接冲突。
4. **机会成本**：对外扩展的投入会挤占 Y1 收敛主轴（减法 + 接通两端）。

### 唯一例外（条件触发）

若以下条件**全部**满足，可重开评估：
- 连续 12 周周产出 ≥ 5 条被采纳（ADR-0416 证伪条件反向达成）
- 修订率连续两年下降（ADR-0417 S2 达成）
- 表面积净负增长达成（S3 冗余清零）

预计最早重开窗口：2028 Q2。

## Consequences

- 不做：多租户、API 开放、文档站点、社区运营、商业化
- 做：继续深耕单人操作系统，Y1 收敛 → Y2 深化 → Y3 复利
- 本 ADR 在 2028 Q2 前不可推翻（除非上述三条件提前达成）
