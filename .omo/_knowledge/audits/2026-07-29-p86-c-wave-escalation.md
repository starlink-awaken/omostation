## 送卡建议 (供人类决策, 非代批)

### 建议 1: 产能目标按任务类型分层 (非一刀切 60)
- **独立并行类** (independent+well_defined): 协作有正收益 (批次1 5.4x), 可设进取目标
- **物理依赖类**: 协作无用, 目标取决于人类/硬件节奏 (非 agent 数量)
- **工程工作量表** (如 BOS-STDIO): 协作可并行加速, 但量级是硬约束
- **对抗/强耦耦合类**: 协作机制有边界 (B1), 修复前不计入产能

### 建议 2: ADR-0247 协作主轴 amend 适用边界
协作是**特定任务类型的加速器**, 非通用生产方式. 主轴地位可保留, 但需 amend:
- 适用: independent + well_defined 批量
- 不适用: 物理依赖 / 串行分析 / 强耦合协商
- 不一刀切推广, 也不一刀切否定

### 建议 3: P84 "月度 ≥60 任务 ≥90% 完成率" 假设
该假设建立在"协作普遍正收益"上, 已被 A1+A3+批次2 challenge:
- 协作正收益仅在 independent+well_defined 证实 (单点, 批次1)
- 产能主瓶颈是物理/工作量 (A3), 协作非瓶颈
- 建议: 待 A2 协作收益地图出来后, 按类型分层重设目标

## A2 批次3 补充 (2026-07-29, coupled+write+negotiated 真 dispatch)

批次3 新数据 (`.omo/_knowledge/audits/2026-07-29-p86-a2-batch3-coupled-write.md`):
- 协作墙钟 **115s** vs 单 agent **140s** → 协作墙钟**优 18%**
- 但**协作质量劣**: 3 haiku 只 1/3 有效产出, 单 agent 完整深入 (7 tool_uses, 源码定位)
- → **协作墙钟优 ≠ 质量优**

**对 C 波的强化**:
产能目标若只看墙钟会**高估协作**. coupled+write+negotiated 协作"快但浅",
连贯深入任务单 agent 更优. 协作适用面比 A1 预测更窄 — 不只看任务类型, 还看**质量要求**.

**4 数据点协作收益地图 (A2 定论, 详见批次3/4 文档)**:
| 类型 | 协作收益 | 质量 |
|------|---------|------|
| independent+none (批次1 简单批量) | 优 5.4x | 协作优 |
| ordered+read (批次2 分析) | 劣 1.7x | — |
| coupled+write (批次3 方案设计) | 优 18% 墙钟 | 劣 (1/3 有效) |
| independent+write (批次4 check 设计) | **劣 73%** | **全空 (0/3)** |

**定论 (4 数据点)**: 协作正收益**仅"简单独立批量" (批次1)** 证实.
分析/方案/思考性设计协作要么墙钟劣要么质量劣. **协作适用面极窄**.

**建议更新 (供人类)**:
- 60 任务/月假设 (协作普遍正收益) **被否定**, 按任务类型分层
- 简单批量 (doc 修复/格式化/as_of): 协作可加速 (批次1 5.4x)
- 思考性任务 (设计/分析/审查/调试): **单 agent 更优** (协作墙钟劣 + 质量劣)
- ADR-0247 协作主轴 amend: "简单批量加速器", 非通用生产方式
- **绝大多数真实任务是思考性的 → 单 agent 为默认, 协作是例外**
