# BET-Y1Q3-T10-89 retrospective

## Q1. What was intended?

Repair the Workspace-owned Cockpit projection in the native ZCode config while
preserving unrelated client settings and leaving active Documents state alone.

## Q2. What happened?

The existing atomic installer replaced only the managed Cockpit entry. The
checker now returns `ok`, the config remains mode `0600`, and a protected
rollback copy is retained. No ZCode restart or state migration occurred.

## Q3. What was discovered?

ZCode has 18 configured MCP servers and the drift was isolated to the Cockpit
projection. ZCode is actively using the Documents SQLite database plus WAL/SHM;
the native `~/.zcode/v2` database is a different older state set, so copying or
repointing client state without quiescence would be unsafe.

## Q4. Surface accounting

Workspace gained one protected config rollback copy and one corrected native
config projection. No Documents file, SQLite state, WAL/SHM, credential, log,
checkpoint, certificate, provider, or unrelated server changed. The required
D2 tracked-surface receipt remained: `src_loc=949423` (`+223011`),
`test_loc=481466` (`+130612`), `src_files=4218`, `test_files=2320`,
`adr_total=393`, `gac_required=28`, `bin_scripts=710`, `standards=56`, and
`collab_scenarios=5`; `test_loc` did not decline.

## Q5. What should the next agent know?

Treat client-state relocation as a separate high-risk task. First obtain a
quiescent ZCode process, then snapshot and migrate the complete SQLite
sidecar/config state with restart verification. Public-runtime and root-oneoff
families still have missing historical rollback packages and must remain
pending.
