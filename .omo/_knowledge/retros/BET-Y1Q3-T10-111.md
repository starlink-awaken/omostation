# BET-Y1Q3-T10-111 retrospective

## Q1. What was intended?

Move canonical ownership of the mature family dashboard source from Documents
to the existing family-hub repository without importing household/runtime data,
cutting consumers, or preserving a second product owner.

## Q2. What happened?

A deterministic importer selected 265 source files, excluded runtime/private
classes, sanitized twenty private-text files, and published immutable receipts.
The imported Next.js package now has explicit Documents/state roots,
fail-closed document writes, synthetic build data, unit/build/E2E coverage, and
child CI. Family-hub PR #3 merged and replayed from child main.

## Q3. What changed during implementation?

The first two custom clone attempts were degraded because custom onboarding did
not produce the governance provenance needed by root workflow bootstrap. The
delivery switched to the established governance profile and initialized
family-hub on demand.

The host PATH preferred a broken Homebrew npm Bun shim over the valid official
Bun binary. Diagnosis proved the project was not at fault. Verification used
the official binary without changing host PATH. The plan also used `bun test`,
which invokes Bun's native runner; the correct project contract is
`bun run test` for Vitest. Ledger verification was corrected accordingly.

Review found three important gaps before push: state paths did not reject
symlink escapes, imported deployment configuration still mounted the legacy
Documents root read-write, and the importer lacked adapted-target verification.
Each received a failing test before repair.

The first root BET verification timed out when Python imported `pydantic_core`
immediately after a Bun build in the same command. Sampling proved a dynamic
loader wait rather than a test failure. Isolated import and pytest passed; the
verification contract was reordered to run Python before Bun, and the complete
BET verifier then passed.

## Q4. What happened to the source tree?

The selected source fingerprint remains unchanged. Running Vitest once in the
legacy source to prove inherited failures rewrote one excluded
`node_modules/.vite/vitest/.../results.json` cache by two bytes. The full-tree
fingerprint therefore changed while count and canonical source remained stable.
The evidence reports this explicitly and adapted verification distinguishes
selected truth from excluded cache drift.

## Q5. What remains?

Root main still needs to adopt the child commit through a gitlink PR and replay.
Phase B must relocate real generated state and introduce OMO-mediated write
proposals. Phase C must cut Cockpit/consumers, observe the real journey, and
retire the old app/caches through a recoverable transaction.

## Q6. What value is proven?

Engineering ownership, privacy-safe import, explicit read/write boundaries,
and synthetic journey reproducibility are proven at child main. Live user value
and operational cutover are not proven.
