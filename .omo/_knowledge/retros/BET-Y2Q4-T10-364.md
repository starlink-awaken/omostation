# Retro — BET-Y2Q4-T10-364

## 1. 意图（intended）

`BET-Y2Q4-T10-354` 的收口回执登记了残留面：发布器的契约守卫
`_check_template_data_consistency` 只扫 `template.html` 一个文件，而被服务的
前端资产是 11 个 JS —— 资产层读 `D.<field>` 的缺席字段没有任何判据覆盖，
正是 T10-354 那类缺陷（页面渲染为空 / NaN）的复发入口。

本 BET 三件事：① 守卫覆盖面扩到「模板 + 全部被服务 JS 资产」，保持只告警不阻断；
② 清掉 omostation 侧 `workbench_ui` 的 `D.pending_publications` 死引用；
③ 把跨仓与跨资产的其余缺席字段登记入回执。

## 2. 实况（happened）

**实测读数**（2026-11-27，线上 release + 采集器 payload 111 顶层键，
测量命令见回执 §2.1）：

| 面 | refs | missing |
|----|------|---------|
| 被服务的 `template.html` | 55 | **0** |
| `data_access.js` | 10 | `safety_boundaries` |
| `ui_extensions.js` | 15 | `events` / `live_sources` / `submodules_summary` |
| `workbench_ui.js` | 16 | `local_server` / `pending_publications` / `safety_boundaries` |

其余 8 个资产 refs 为 0 或全部在场。7 处缺席全是可选链 / 三元写法：不崩，但恒空。

**改动**：

  `_scan_dashboard_asset_contract()`，守卫在同一 code root 下逐个 `*.js` 报缺席字段；
  模板面语义不变（同一 root、同一正则、同一告警文案）。
- `bin/panorama/assets/host/panorama-collect-main.py.asset`：与源文件逐字节镜像
  （宿主跑的是这份 asset，发布时若不同步会把宿主回退成旧守卫）。
- `bin/panorama/assets/host/workbench_ui.js.asset`：删掉 `D.pending_publications`
  死分支（该字段已在 T10-354 从 payload 退役，线上 114 键无此项）。
- `tests/unit/test_panorama_asset_contract_guard.py`：5 个用例钉住判据
  （缺席被报出 / 全在场不报 / null 字段算缺席 / 资产面告警 / 模板面不回归）。

**验证**：单测 5 passed；干跑守卫（线上 release + 线上 payload）打出 3 条资产面
告警、7 个字段；被服务模板面 missing 仍为 0。

**宿主部署**：合并为 `8b2a7351`（PR #5648 squash）后执行
`zhixing-host-sync.py publish --file workbench_ui.js --file panorama-collect-main.py`
（从 origin/main 对齐检出，发布 `ok: true`，两份资产 sha 与源一致）。发布后刷新作业
随即失败 `projection_collector_not_at_bound_commit` ⇒ 采集器自校验「执行中的字节 ==
生产者代码根（`code-main`）HEAD 上的字节」不成立 ⇒ 不再发布 revision ⇒ live server
`CODE_DRIFT` ⇒ 静态资源 503。**已回滚**（`zhixing-host-sync restore` + 两次 kickstart），
宿主复原到发布器原版 release `8f43efed…`：`code_drift: false` / `BOUND_FRESH` /
静态资源 200 / revision 按 240 s 继续发布；本次新建的 release 目录与切换历史指针
一并清除。详见回执 §5。

## 3. 差距与坑（learned）

1. **扫描面必须等于被管面**：守卫读 `ZHIXING_DASHBOARD_CODE_ROOT`，但这个变量在
   **两种上下文里指向不同的面** —— 发布链注入的是被服务的 release 根（读数 = 被服务面），
   宿主刷新作业（launchd `com.omostation.panorama-dashboard-refresh`）注入的是
   `~/.local/share/zhixing-dashboard`（宿主仓工作树 = 发布**源**面）。两个面的 JS 逐字节相同，
   但 `template.html` 不同（宿主仓 `09dcb25bbf76` vs 被服务 `0fd5ce5deff4`）⇒
   运行时告警里的模板面读数不等于浏览器加载的那份模板，**模板面结论只有发布链上下文可信**；
   资产面结论两面同源，成立。宿主根那份陈旧 `template.html` 扫它是**假警报**面。
2. **资产层 `D` 就是 payload 顶层**：11 个资产里 4 个有 `const D = window.D || {}`
   之类绑定，`D.<field>` 读的就是 payload 顶层键 —— 扫资产与扫模板同口径，
   不需要为 JS 另立一套判定规则。
3. **asset 副本是宿主的真身**：`bin/panorama/assets/host/*.asset` 经
   `bin/gac/zhixing-host-sync.py` 的 `HOST_FILES` 发布到宿主；只改仓内源文件不动
   asset 副本，部署时会把宿主回退成旧版本 —— 交付必须源 + 镜像同批。
4. **BET id 是跨会话共享命名空间**：本轮最初取号 `BET-Y2Q4-T10-360`，与
   laowang 当晚 in-flight 的同号 BET 撞车（`agent-workflow start` 被 root-gate /
   bet 锁正确拦下）；台账没入 main 时看不出冲突。**取号前必须查两处**：main 台账
   已用号 + 交付面 `.omo/_delivery/agent-workflows/` 里 in-flight run 的 `bet_id`。
5. **`start` 失败会漏锁**：`bet-execution` 的 scopes 是 `[bet:{id}, root-gate]`，
   先拿到 bet 锁再撞 root-gate 失败时，`acquire_locks` 的 `except WorkflowError`
   分支不回滚已拿的锁 ⇒ 留下无主的 bet 锁（本次由 `bin/gac/fix-orphan-locks.py`
   识别并归档清理）。这是工具缺陷，已登记待裁。
6. **台账的派生计数让「插一条 BET」与并发前进的 main 必然撞车**：台账带
   `meta.total_bets` 派生计数，插入一条 BET 就要把它从 N 改成 N+1，而并发
   agent 合并另一条 BET 时同样改这一行 ⇒ 两侧改同一行 ⇒ GitHub 侧 merge
   冲突（实测：唯一冲突是 `meta.total_bets` 609 vs 608，bet 列表本身合得干净）。
   **正解不是把上游 merge 进交付分支**（本仓明令禁止 rebase/merge/pull 吸收上游），
   而是按仓库既有的 successor 路径重放：`gac-worktree.sh claim` 以
   `origin/main` 为基点开新 worktree，把变更搬过去重做 ⇒ 新分支的基点 = 当前
   main，计数行只有一侧改，PR 直接可合。
7. **发布面有一条没写进契约的前置条件：采集器字节必须等于生产者代码根 HEAD 上的字节**。
   `panorama-collect.py:505-519` 的 `collect_projection_producer_identity()` 自校验
   「正在执行的采集器 == `code-main` HEAD 的 `bin/panorama/panorama-collect.py`」，
   不等即抛 `projection_collector_not_at_bound_commit` 并**主动拒绝运行**。而
   `code-main`（及运行时安装位）由 `bin/ssot/anchor-install-root.sh` 推进、当前锚在
   `92183b49`（origin/main 的祖先）⇒ 「用比 code-main 更新的提交发布采集器」必然
   打断刷新作业 ⇒ 投影过期 ⇒ live server 全路由 503。**发布顺序必须是
   「先重锚 code-main，再发布资产」**，两步只做一步就会自伤。本轮实测自伤一次并回滚复原。
   纪律：动宿主发布面前先量 `code-main` 的 HEAD 与待发布提交的关系；
   `zhixing-host-sync publish` 只保证字节落地，不保证生产者身份绑定成立。
