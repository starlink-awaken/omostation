## Q3 过程中发现的与 plan 不符的事实（打假）?

### 1. 前会话残留导致两个不同版本同时存在
**症状**: `write` 工具报错 "file modified since last read", 但实际上我并没有读过这文件 — 后来发现 4326 字节版本与我的 write 内容完全不同。
**根因**: 前一会话 (`2026-09-05T19:34`) 在我的 worktree 路径下已经写过 `cold-backup-drill.sh` + `restore-cold-snapshot.sh`, 但未 `git add`, 所以是 untracked。我的 `write` 工具试图写入时因 timestamp 冲突被拒绝。
**判断**: 那两个 untracked 文件虽然是我之前的 work-in-progress, 但脚本逻辑差异较大 (`rsync --files0-from=-` 在 macOS BSD rsync 上失败)。
**决策**: 选 **重写** (更稳的 tar 直流式, 跨 BSD/GNU), 保留 restore 脚本骨架 (修复 BSD `mktemp` 兼容性)。

### 2. macOS BSD `rsync --files0-from=-` 不支持
**症状**: 旧版 `cold-backup-drill.sh` 静默 exit 1 (`set -euo pipefail` 触发)。
**根因**: macOS 系统 rsync 是 BSD 版本, `--files0-from=-` (从 stdin 读) 是 GNU 扩展。
**绕开方法**: 重写为 `git ls-files -z | tr '\0' '\n' > list; tar -cf - -T list`, 完全绕过 rsync, 单一 tar 命令完成 staging + 打包。

### 3. macOS BSD `mktemp /tmp/foo-XXXXXX.suffix` 失败
**症状**: `restore-cold-snapshot.sh --verify-only` 报 `mktemp: mkstemp failed on /tmp/restore-XXXXXX.tar: File exists`。
**根因**: BSD `mktemp` 要求 template **以** `XXXXXX` 结尾, 不能带后缀。
**绕开方法**: `DECRYPTED_TEMPLATE="$(mktemp -t restore-XXXXXX)"; DECRYPTED="${DECRYPTED_TEMPLATE}.tar"`, 两步式模板。

### 4. 工作区 submodules 大量 missing
**症状**: dry-run 输出 17 条 `⚠️ missing: projects/<submodule>`。
**根因**: worktree 创建时 submodules 没有 init (PASW 默认行为, 用 .subtrees/ 隔离), git ls-files 中 submodule 路径在工作树无对应实体文件。
**判断**: 这是 worktree 隔离机制的预期行为, 不是 bug。生产环境 (裸机) 应当 `git submodule update --init`, 脚本不强制要求。

### 5. 后台任务 50 个上限
**症状**: 多个 bash 命令被自动转后台, 部分命令报 "maximum number of background jobs (50) reached"。
**根因**: 之前 batch 长任务占用, mcp shell session 计数累积。
**绕开方法**: 简单等待或切到同步运行 — 不阻塞交付链。
