# BET-Y1Q4-T10-167 retro — 3Y BET ledger schema hardening

## Summary

- Registered a governed BET with an accepted specification and a fixed write-surface
  boundary before changing the ledger loader or mutation path.
- Added one structural contract in `bin/plan/bet-ledger.py` and reused it from
  `bin/gac/ledger-safe-insert.py`.
- The contract now rejects malformed root sections, non-mapping BET entries,
  non-`BET-*` identifiers, duplicate BET IDs, misplaced BET-shaped mappings, and
  multi-document or syntactically invalid YAML with bounded location context.

## Q1 — Intended

Make the ledger fail closed on structural corruption without moving or rewriting
user-authored BET content. Keep existing transition, dependency, completion-evidence,
and portfolio semantics unchanged.

## Q4 — Findings

- The previous safe inserter validated insertion position but parsed the ledger
  before any shared structural guard, which allowed malformed fixtures to raise
  tracebacks or silently accept misplaced content.
- The loader previously merged YAML documents and silently ignored archive parse
  failures. The main ledger now requires one document; optional archive parsing
  reports diagnostics instead of falling back silently.
- Workflow WorkPacket tests use intentionally minimal BET-only fixtures. The
  shared parser therefore exposes an explicit compatibility mode for that
  consumer while the CLI and mutation path retain the complete production root
  contract.
- Ruff still reports pre-existing findings in unrelated legacy sections of
  `bet-ledger.py`; this change does not reformat those areas.
