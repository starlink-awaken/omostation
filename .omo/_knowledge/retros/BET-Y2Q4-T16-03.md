# BET-Y2Q4-T16-03 retro

## 1. 本意要发生什么

按 ADR-0203 受管流程，为已实测的新发现「Panorama `CODE_ROOT` 指向陈旧检出导致门禁与台账读数失真」立独立单：
落一份 spec + 一条新 bet 台账条目（`BET-Y2Q4-T16-03`），给出 A/B/C/D 修复决策矩阵供 principal 裁定，不代决。

## 2. 实际发生了什么

- **`start --bet` 需要条目先存在**：`start project-doc-change --bet BET-Y2Q4-T16-03` 报
  `agent-workflow: BET_NOT_FOUND: BET-Y2Q4-T16-03`。根因在 `bin/plan/bet-ledger.py::prepare_bet_execution()`
  的 `_bet_for_execution()` —— start 要先解析 objective + 校验 spec binding，故台账条目必须已存在。
  而要创建该条目的正是本单 ⇒ 顺序被迫调整为「先落 spec + 台账条目 → 再 start/claim」，
  这与 ADR-0203 D2「先 start 再改」在**新 bet 首轮**上结构性冲突。本单走前者，并在回报里显式标注此偏离。
- **spec frontmatter 不能照骨架写 `status: draft`**：`bet-ledger.py` 的 `validate_accepted_specification()`
  在 lint 时要求绑定 spec 的 `status == "accepted"`、`schema_version == specification/v1`、
  `bet_id` 与 binding 一致；doc-governance 的 `accepted-specifications` 面又要求
  `[status, lifecycle, owner, last-reviewed]`。⇒ 采用同批已绿邻居的 frontmatter（accepted / contract / owner / last-reviewed）。
- **「插入器合法」≠「台账合法」（与 BET-Y2Q4-T10-225 同一形状，本轮再现）**：
  `bin/gac/ledger-safe-insert.py --dry-run` 通过、正式插入成功（`bets` 535→536，`meta.total_bets` 同步为 536），
  但随后 `bin/plan/bet-ledger.py lint` 报 `ERROR BET-Y2Q4-T16-03: 缺字段 verify`。
  两套字段集不一致：插入器校验 binding 四键 / 三轴 / digest；lint 校验 9 个必填字段
  （`track/window/title/appetite/status/goal/done_when/verify/workflow/write_surfaces`，见 `bet-ledger.py:2969-2980`）。
  ⇒ 补 `verify` 后 lint 绿（`OK -- 536 bets, 16 tracks, no errors`）。
- **`claim` 需要 affected-graph receipt**：本单是根级文档改动，用
  `affected-graph.py --changed-projects workspace-root --output runtime/affected/t16-03-receipt.json`；
  receipt 输出父目录不得含 symlink，故落真实目录 `runtime/affected/`（用完即删、不进 commit）。
- **`closeout` 被 vision→retro chain 拒**：`agent-workflow: closeout blocked by vision→retro chain (missing_retro)`，
  需 `chain_bind.retro_path_for()` 指向的 `.omo/_knowledge/retros/BET-Y2Q4-T16-03.md` 存在。
  ⇒ 补本 retro（governance 要求的 run 证据，非绕过）后 closeout 通过。

## 3. 判据 / 纪律

- **新 bet 首轮无法满足「先 start 后改」**：`start --bet` 本身要求条目存在。纪律上要么承认「立单 = start 的结构性前置」，
  要么给 `start` 增加一条不解析 objective / 不校验 binding 的 draft 通道；本单取前者并留痕，未改工具。
- **插入器与 lint 是两套判据**：`ledger-safe-insert.py` 放行 ≠ 台账合法；插入后**必跑** `bin/plan/bet-ledger.py lint`。
- **受影响根用 `workspace-root`**：根级文档改动不对应任何 `docs/layer-contract.yaml` 里的项目名。

## 4. 未决

- 决策矩阵 A/B/C/D 待 principal 裁定；本单不代决，也不改任何 plist / launchctl / 克隆。
