## 2. 实际发生什么

范围被实测纠正了两次，方向相反：

1. **收窄**：任务描述说"两个 tests/unit 本地红"，实测该文件只有 1 条红（`1 failed, 859 passed`），
   另 859 条绿。
2. **扩宽**：交付前跑了一次全量 `pytest tests/unit`（839s，**16 failed / 1848 passed**），量出
   第二处独立红 —— `test_projection_reader_resolution.py::test_probe_heartbeat_monitor_reports_absent_projections_without_failure`。
   它的根因不是 host 而是**日历**：fixture 写死 `generated_at: 2026-09-29T00:00:00Z`，投影登记表配的是
   相对窗口 `sla_hours: 72`，于是 2026-10-02 起无条件变红，被测代码一行没动。同形状另两处那天恰好
   没断言 `ok` 才没红。
3. 全量还量出 14 个可指认的范围外用例名，分属三类**不同机制**（装置性子模块未 init / registry
   `status: proposed` 与用例断言 `active` 的基线分歧 / 顺序依赖）。它们没被顺手改，各立任务 #107–#109。

判据自己也红过一轮：第一版机器面写成 `grep -rn "generated_at:[ ]202" tests/unit`，期望 `CLEAN` ——
实测命中我新加的 `_fresh_ts()` docstring 里那句事故描述（那行不含 `_fresh_ts` 字样，`grep -v _fresh_ts`
排除不掉）。改成锚在写点上（`"write_text.*generated_at:[ ]20"`）才成立，并在 spec §4 明确它是
**必要而非充分**条件：多行 fixture 里的 `generated_at` 可以不出现在 `write_text` 同一行，语义面靠
逐文件分类表覆盖（含 `generated_at` 的 9 个文件逐个判"绝对值是否与 now/SLA 比较"）。

工具面：`claim` 现在要求 `--affected-hash`（值必须是 `bin/gac/affected-graph.py --output` 产出的 receipt 文件），
而 `--output` 的父目录链拒绝 symlink —— `.omo/_delivery/**` 是 symlink，所以 receipt 落到
`.artifacts/`（`.gitignore:11`，不进仓）。

## 3. 因此改变了什么

- **"测兜底先物化"从口头约定变成可复制形状**：`_fake_checkout()` 在 `tmp_path` 下造一个自带
  `projects/omo/src/omo/{__init__.py,omo_paths.py}` 与投影登记表的假检出，源字节 `shutil.copyfile`
  取本仓真文件。之所以必须这样，是因为 `omo_paths.WORKSPACE_ROOT = _MODULE_DIR.parents[3]` 由
  `__file__` 推导，`OMOSTATION_ROOT` 对它无效 —— 想伪造"检出的 legacy 面"，模块就得物理在那边。
- 每条"移走写目标"的契约都配了正向落点断言（canonical 不存在 × legacy 存在），补一条两面皆无时
  返回缺失 canonical 的用例，把 `projection_path` docstring 那句"absent is not a failure"钉在两个方向。
- 台账 516 → 517 bets，`BET-Y2Q4-T10-222` 带 spec binding（`content_digest sha256:943322b6…`）。
- 新增三类被登记而非被抹平的红（#107 感知、#108 基线红、#109 顺序依赖）。

## 4. 教训

1. **"只有 N 条红"这类断言，先全量枚举再写进契约。** 本轮两次收窄/扩宽都靠实测纠正；如果只按
   领任务时的描述写完就交付，`done_when` 会留下一句被自己数据否证的话（T10-215 已记过同形教训：
   每条契约先跑一次再写进去 —— 这条是它的推广版：每条**范围**声明也要先量一次）。
2. **绝对时间戳 × 相对窗口 = 定时炸弹**，而且它红的时候没有任何代码变化可读，最容易被人
   误当成"环境出问题"或直接把断言删掉。判别量不是"文件里有绝对日期"，而是那个值是否参与
   `now`/SLA 比较；显式注入 `now=datetime(...)` 的静态 fixture 是**正确形状**，不能为了统一一并改掉。
3. **负向对照必须在交付物上量，不能只在草稿上量。** 变异对照（抽掉 `legacy.write_text` 该行）
   在 commit 之后重跑，`git checkout --` 还原的目标才是交付 blob；否则"会红"这件事可能验证的是
   一个没被提交的版本。
4. **装置性红 vs 真红的分辨法**：`git submodule status` 行首 `-` = 未 init。本轮 9 条
   `No module named 'collectors'` / sys.path 缺口全是 `SKIP_SUBMODULE_INIT=1` 的产物，canonical 工作区
   同用例绿。不先测这一步，会把 9 条背景噪声当成本轮回归，或反过来把自己的真红混进去一起"降级"。
5. **登记不等于修复，但漏登记等于抹平。** 三条范围外红各立任务并在 spec §5 写明"为什么不修"，
   下一轮才不会被"顺手改成绿的"重新引入。
