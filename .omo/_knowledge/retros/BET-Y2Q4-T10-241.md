# BET-Y2Q4-T10-241 retro — 投影绑定的真正闸门在发布器，不在投影

## 做对了什么

- **先定位闸门再动手**：`/health` 的 `code_drift` 只是症状；顺着
  `projection_status=CODE_DRIFT` 查到发布器日志里连续 `projection_dashboard_not_current_main`，
  根因是本地提交没推送（HEAD != origin/main）。推送一次，全链路自愈。
- **不重发 projection 的非目标要按语境读**：DCP-20 禁止的是「手工重发绕开门禁」；
  身份门合法满足后让正规发布器重发投影，是 AC-02/AC-05 的唯一解。规范冲突时以验收条款为准。
- **迁移前的 dry-run 校验**：release worktree 的 bundle SHA 与 manifest 逐字节比对，
  比对通过才切 `current`；plist 先备份再改写，回滚路径写进回执。
- **并发安全检查**：动手前查了 publisher 进程与锁文件，确认无其他 agent 在跑全量刷新。

## 教训

- **`launchctl kickstart -k` 不重读 plist**：服务重启后 argv 仍是旧入口。必须
  `bootout` + `bootstrap` 显式序列，并用 `launchctl print` 的 arguments 复核 ——
  只看 `ps -p <pid> -o args=` 不够（macOS ps 可能显示解析后的路径）。判据是
  launchd 自己加载的 argv + 进程 cwd。
- **gitignore 是发布机制的一等公民**：`releases/` worktree 和 `current` 指针落在部署仓根，
  若不 gitignore，发布器的 `status --porcelain --untracked-files=all` 干净树门禁直接失败。
  新增「落在代码仓里的运行态」时，先问它会不会弄脏 `git status`。
- **worktree 的 gitdir 指针可能悬空**：`git worktree add` 后若 .git 文件指向不存在的
  metadata 路径，`git worktree remove` 报 "does not point back"；修指针或
  `rm -rf` 目录 + `git worktree prune` 即可，别慌。
- **测试预失败要分类**：`test_zhixing_host_sync.py` 2 例失败是 #4724 加 `--file` 后
  测试未同步（origin/main 预存，T10-236 写面），与本轮无关；在回执里明确分类，
  不顺手修（那是另一个 pending BET 的写面）。
