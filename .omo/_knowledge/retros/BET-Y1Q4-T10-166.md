# Retro: BET-Y1Q4-T10-166 — ASD 五核心面板数据契约与验收

## Summary

T10-163 (panorama dashboard) 已经交付 5 大面板, 但缺数据契约。本 BET 补:
- 每面板的 provenance (字段来源)
- 每面板的 freshness (采集时间 + staleness 阈值)
- 每面板的 degradation (0=fresh, 1=partial, 2=stale-blink, 3=missing)
- 顶层 provenance_global 标记 `never_yields_green: true` (PARTIAL≠PASS 铁律)

## What went well

- 直接 patch `panorama-collect.py`, 加 helper `_with_provenance()` + `collect_with_provenance()`
- 5 个面板统一数据结构: `{provenance, freshness, degradation}` 三元组
- HTML 顶部新增 `<section id="degbar">` 一行展示降级状态, 颜色分级 (绿/黄/红/删除线)
- 复用现有 panorama 架构, 零架构调整

## What was learned

- "never-yields-green" 是 ASD 的关键铁律 — 数据缺失/陈旧绝不能等同于 PASS
- 5 分钟 staleness 阈值与 panorama 自身刷新周期匹配 (cron 5min)
- degradation 4 档分类比单纯 boolean 更精准, UI 可按颜色直观区分

## What to improve

- 当前 degradation 仅基于 age, 未考虑 schema mismatch (未来若 schema 升级)
- panel_metadata 在 JSON 输出里不展开, 可在 --detail flag 加
