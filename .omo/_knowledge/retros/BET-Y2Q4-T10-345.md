# Retro — BET-Y2Q4-T10-345

## 1. 意图（intended）

`omo.resident.dispatch.dispatch_task` 每次调用都无条件新建一份 TaskObject JSON、一张 Action
Desk 卡片、一次隔离工作树请求。巡检投影探针与大屏 triage 是**周期性重报同一条件**的生产者，
于是 `.omo/_truth/task-center/dispatches/` 无界增长。本 BET 要在**生成侧**加一道按 objective
新鲜度的折叠：同一 objective 在 TTL 窗口内已有档案时复用既有 `task_id`，不新建任何东西，
返回值补 `deduplicated=True` 且保住 `interact.py:501` 直接下标读取的四个键。

不改目录的跟踪性、不删存量、不改写既有 JSON —— 这三条是刻意的边界（trackedness 分叉
BET-Y2Q4-T10-289 已登记为未裁，存量清理与 `.gitignore` 变更属 principal 权限）。

## 4. 教训（lessons）

1. **`git -C <子模块>` 的前置条件不是「目录存在」，而是「该目录的 `.git` 真能解析到自己的
   gitdir」**。T10-343 记的是「目录不存在 ⇒ 向上解析」，这次是更强的第二种形态：**目录在、
   `.git` 文件在、gitdir 目标残缺** ⇒ 照样静默向上解析到根仓，`checkout` 的作用对象变成整个
   worktree。判据：`git -C <sub> rev-parse --show-toplevel` 的输出必须**等于那个子模块路径**，
   不等就别写。更稳的做法是不用 `git -C`，改走 `git submodule update --init <path>` /
   `git ls-tree` / `git submodule status` 这类以路径为参数的命令。
2. **恢复之所以零代价，是因为交付物已全部 commit**。这条和 T10-343 的教训 #2 是同一件事，
   第二次验证：在 worktree 里尽早 commit（本地可逆动作）是唯一真正生效的保险。
3. **判据选型要先量「有没有写入方」**。这道折叠最初想过按 `status` 判定（更直觉），实测
   33 份里 30 份状态由执行侧手写、且无任何写入方标记终态，才发现按状态等于永久抑制。
   「声明 ≠ 执行」在这里的表现是：**状态字段存在 ≠ 状态字段有人维护**。
4. **实机 canary 要包含「不追溯存量」这条诚实读数**。若只测 `HIT True`，就会把「窗口只约束
   未来」讲成「历史重复被消除」——那是虚报。
5. **digest 与字段修复同笔落**。CI 只报了缺 `owner`，但真正完成条件里还绑着 `content_digest`；
   改被 digest 绑定的文档，digest 同笔改，一次推对。
6. **pre-push 对「子模块未初始化」有两套相反语义，绕门禁前先数清有几个 gate**。
   `bin/ssot/sync-submodules-push.sh` 把无 `.git` 的检出当合法跳过；
   `bin/ssot/n-gate.py`（`submodule-reachability`）对同一路径直接判
   `unreachable: submodule working tree missing` 并 exit 1。于是「删掉半截检出」这种
   看起来让检查变干净的动作，实际只是把红从第一个 gate 搬到第二个 gate，还多花 250s 墙钟。
   判据：`rg -n "submodule" .githooks/pre-push` 数清 blocking 项，再决定是补检出还是别的。
