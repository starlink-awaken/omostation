## 2. 实况（happened）

- 根因确认走的是「调用方 argv vs 被调用方 parser」的直接对撞：跑一次真脚本拿 rc=2
  与 `unrecognized arguments: --json` 原文，比读十遍代码可靠。
- 反 stub 自证：新用例把 stub 抓到的 argv 原样喂给仓内真脚本，`5 passed → 6 passed`，
  并在**重建后的内容**上重跑反证（回塞 `--json` → `2 failed` rc=2 → 逐字节复原 → `6 passed`）。
- 两次门禁红都不是代码回归，都是环境/规则形状：
  - CI `gac-gate`：新 spec 缺必填 `owner` → `missing_frontmatter:accepted-specifications
    count=1` 无预算覆盖。修字段的同时必须重算台账 `content_digest`
    （`905ba008… → c08ff737…`），否则换一个坑（`COMPLETION_FILE_DIGEST_MISMATCH`）。
  - 本地 `check-evidence-freshness`：claim 空检出 → `import_failed`；物化后 → `84.5 < 90`，
    因为 claim 不带 state 面的 `.omo/state/system.yaml`。同一检查在 canonical `PASS 100.0`，
    在我没碰过的 `ws-readme` 里报同一条错 —— 判据泄漏 host 状态，不是我的 diff。
- **我自己造成的一次实质损害（必须记账）**：为补 `projects/metaos`，执行了
  `git -C projects/metaos checkout -f -q --detach <sha>`，而该目录当时**根本不存在**。
  `git -C` 向上一层解析到根仓，于是这条命令把**主 worktree 的 HEAD detach 到子模块 commit**、
  索引换成外来 171 个文件，`checkout -f` 顺带丢弃了 3 个未提交文件的修改。
  恢复路径：`git checkout -f <branch>`（零跟踪文件缺失，85 是 `git ls-files` 引号假象）
  + 从 `/tmp` 备份复原 asset + 按记忆重建 test 编辑 + `ledger-safe-insert.py` 重放台账条目
  + spec（未跟踪，幸存）。代价：反证必须在新建内容上重跑才算数。

## 4. 教训（lessons）

1. **`git -C <子模块路径>` 前必须先确认该目录存在且带 `.git`**。目录缺失时它**静默向上解析到
   根仓**，`checkout -f` 一类命令的作用对象就变成了整个主 worktree。已有条目写的是
   「未初始化子模块 `git -C` 向上解析」，我当时读成了「未初始化 = 有目录无内容」，
   没覆盖「目录压根不存在」这种更强的形态 —— 更强的形态照样咬人。
   纪律化：**对子模块用 `git submodule status` / `--ignore-submodules=none` 一类以路径为参数的
   命令读，用 `git -C` 写之前先 `[ -e <path>/.git ]`**。
2. **未提交的修改在这个仓里等于没有**。这次若已 commit，损害是零。恢复之所以可行，
   纯粹因为顺手 `cp` 了 asset 备份 + 台账有 `ledger-safe-insert.py` 可重放 + spec 恰好未跟踪。
   交付型改动应尽早 commit（在本仓 worktree 里，commit 是本地可逆动作，不需要额外授权）。
3. **测量假象要认清**：`git ls-files | while read` 的缺失计数（85）是引号/空格造成的，
   `git ls-files -z` + python 才是零。判据报警先 print 原始行 —— 这条老规则这次救了我，
   让我没在「工作树被毁」的错误判断上继续乱写。
4. **改被 digest 绑定的文档，digest 同笔改**。CI 红的那条只报了缺 `owner`，
   但真正的完成条件里还藏着「spec 内容变了必须重算 digest」。收口时一次性核对，
   比等 `COMPLETION_FILE_DIGEST_MISMATCH` 再回来强。
5. **环境类门禁失败要说成环境**：补齐 metaos、复原 uv.lock、detach 归位 gitlink 都做了，
   剩下 `84.5 < 90` 的根因是 claim 不带 state 面输入 —— 不绕钩子、不自签豁免、
   不把报告从 canonical 拷过来（那等于为一次没在这棵树上发生过的运行伪造收据）。
