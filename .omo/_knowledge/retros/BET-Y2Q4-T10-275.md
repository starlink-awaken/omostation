# BET-Y2Q4-T10-275 retro

台账：`docs/plans/3y-bet-ledger.yaml` `BET-Y2Q4-T10-275`
规格：`docs/superpowers/specs/2026-10-28-bet-275-lib-wrapper-root-self-resolution.md`

## 1. 本意（intended）

ADR-0456 B4b 把常驻族的**入口**改到了安装位，T10-266 已把这件事的判据写死：入口在 A 树、
执行的码面在 B 树 = 没改道。本轮领的是这条判据指出的残差里最小的一个面 —— 三个 launchd wrapper
把检出的绝对路径烤进了脚本，改为按 `BASH_SOURCE` 自推根，并给「不许再出现主目录字面量」配一把
能同时产出改前 N 与改后 0 的尺。范围明确排除注册表内容（是否给这三条声明 `runtime_root` 属 #91）。

## 2. 实际发生（happened）

三个文件各加两行自推根、把字面量换成 `"$_REPO_ROOT"`；新增 7 条用例（done_when 冻结的 4 条 +
C-1/C-3/`bash -n` 3 条）。三组变异对照全部按改法分别记读数，其中最要紧的是变异 B：
**把检测器摘掉后，「改后 0 处」那条仍绿**，红的只有反基线、自证、反面三条 —— 这实测出「只断言 0」
为什么不足以承重，而不是引用 AGENTS.md 的一句话当结论。

一次差点出事的形状：变异 A 还原用 `cp`，本机 zsh 把它别名成 `cp -iv`，对已存在文件打印
`overwrite … ? not overwritten` 后 rc=1 且**目标逐字节未变** —— 也就是「命令失败但看起来像提示」，
而那一刻树上的文件仍是变异态。改用 `/bin/cp -f` + `shasum -a 256` 与备份对拍才敢说还原成功。
这是 §7⑤ 记过的形状第三次复发，本轮把它从"读到过"变成"自己撞过"。

## 3. 改了什么（changed）

- 仓内：`lib/{agora-daemon,agora-sse,bet-claim-gc}.sh` 的根来源；`lib/` 面 `/Users/` 命中数
  3 → 0（尺：`git grep -c "/Users/" -- 'lib/*.sh'`）。
- 方法：C-3 的「语义不变」有了可判形式 —— 剥注释/`set` 头/自推根两行、把 `$_REPO_ROOT` 代回字面量根、
  剥 shell 引号后逐行比对。引号归一化明写是**语义**等值不是文本等值，否则读起来像 byte-equal。
- 认知：合成违规样本要注入**别人的**路径（`/Users/someone/…`，spec done_when-3 的措辞）。
  我第一版注入的是本机根，于是「窄尺只匹配本机根」这个 spec §5 明令禁止的形状恰好命中不了 ——
  按我自己的 spec 改完后，变异 C 才红得起来（1 failed）。

## 4. 教训（lessons）

1. **反基线的价值在于它能被变异证伪**。写「改前 3 / 改后 0 由同一次扫描产出」时我以为这是形式要求；
   变异 B 的读数是它实质的证明：尺摘掉后唯一还绿的正是那个"看起来最像验收"的断言。
2. **自证样本必须与违规样本不同源**。注入本机根时，自证与反基线共享同一个失效模式（窄尺两条都能过），
   这正是 §7「判据与被验对象不得共享失效模式」在测试设计层的复现。
3. **「码面跟着入口走」的证据只能来自读脚本内容**（T10-266 纪律 ② 的第三次复述）：argv、plist 文本、
   E1 读数都支撑不了这个结论，本轮的运行态实测（同一字节在两棵树各推出自己的根）才是它的正面证据。
4. **本轮交付的是性质，不是读数**。E6 不覆盖这三条（未声明 `runtime_root`），安装位仍是旧字节
   （实测 sha 三份全 DIFF）。凡"仓里改了但机器面没变"的交付，receipt 里必须写清哪一半没动，
   否则下一轮会把本轮读成已改道。
