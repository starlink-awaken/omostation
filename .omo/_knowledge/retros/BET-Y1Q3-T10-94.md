# BET-Y1Q3-T10-94 retrospective

## Q1. What was intended?

Restore T10-92's already accepted root evidence after a later merge tree
dropped it, so the Documents migration registry and BET dependency chain stay
truthful.

## Q2. What happened?

Comparison of `78fb360d4` with current `origin/main` found exactly six missing
T10-92 root artifacts. The four standalone documents were restored exactly;
the registry and ledger were restored selectively, retaining current mainline
changes. No host-side or runtime data was touched.

## Q3. What was discovered?

A successful PR merge is not sufficient proof that its root tree survived a
subsequent merge. The merge commit's tree must be compared with the previous
mainline and downstream BET dependencies must be revalidated after every
concurrent merge.

## Q4. Surface accounting

The recovery adds six root governance artifacts that were absent from current
mainline: four documents plus one registry evidence block and one ledger BET
block. It adds no host files, runtime payloads, submodule pointers, or value
claims.

## Q5. What should the next agent know?

Keep `opc-tools` at `in_progress` and owner parity pending. Treat T10-92 as
restored historical evidence, not as a new migration. Rebase T10-93 only after
this recovery reaches mainline, then verify both the dependency and final merge
tree before closeout.
