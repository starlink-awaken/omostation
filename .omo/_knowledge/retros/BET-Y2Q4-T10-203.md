# BET-Y2Q4-T10-203 复盘（ADR-0456 B1 · profile root convergence）

## Q1 实际耗时 vs appetite？超出比例？

Appetite 1 day，实际墙钟约 1 天，但**分布与预期完全不符**：代码净增量 795 行 / 15 文件，
而交付动作烧掉了 **4 个分支代际**（#4393 → #4397 → #4400 → #4403）。时间几乎全花在
base 前进与子模块 gitlink 冲突解算上，不在改动本身。

教训的形状：这类"只碰路径解析、不碰行为"的 bet，风险不在代码而在**合并窗口**——
本仓 `gh pr merge --auto` 未开启，`submit` 自 WP1 Wave B2 起是 proposal-only（只打印
`MANAGED_SUCCESSOR_REQUIRED` 然后 `exit 2`，不 push 不开 PR），所以 base 前进只能靠
手工轮询 + 新建后继分支，与并发 agent 的 freshness bumper 形成结构性赛跑。

## Q3 过程中发现的与 plan 不符的事实（打假）

1. **plan 说 9 处、实交付 8 处收口 + 1 处设计性排除**。`bin/panorama/panorama-collect.py` 不属于
   checkout 内消费者：它作为单文件部署到仓外、根目录已由 `PANORAMA_ROOT` 拥有、且必须与
   `.asset` 保持字节一致。它只接入 "`OMO_EVENT_LEDGER_DB` 优先" 这一半，不接入 seam。
2. **plan 里的 `omostation.profile.toml` / `OMOSTATION_PROFILE` 本轮刻意不发**。零消费者
   （实测 `OMOSTATION_PROFILE` 在全仓无任何读取方），发出去就是一条会与 B3/B4 现实漂移的假契约。
   本轮交付的 env 面只有 `OMOSTATION_ROOT`（原有）、`OMOSTATION_STATE_ROOT`、`OMO_EVENT_LEDGER_DB`。
3. **`OMO_PRINCIPAL_ID` 不属于本 bet**：并发的 brief/principal 交付占有它，抢它会在生成文件上
   互相回滚。plan 把它列进 profile 是对的，但落地时机在 B3。
4. **`ahead` 与 `DIVERGED` 的判据在读源码前是反直觉的**。`check-submodule-pointer-drift.py:134-181`
   里 `ahead`（子模块 main 是 gitlink 的祖先）**非阻断**，只有 `DIVERGED` 阻断。#4397 变红不是因为
   根指针领先，而是因为我的 omo commit `8b4e80e` 从 `650e08e` 分叉，而 omo main 已到 `c91b203`。
   修法在**子模块侧**（cherry-pick → `0790f89`），不是根侧变通 —— 这个判断只有读了分类器才做得出。
5. **GitHub 的合并判定与本地 ort 可以不一致**：#4400 全绿却 `CONFLICTING / DIRTY`，而
   `git merge-tree --write-tree` 判干净。根因是**两侧都改过同一个 gitlink 到不同 SHA**
   （#4399 "freshness bump 6 gitlinks" 在飞行中移动了根 pin）。此后我改为：先在本地用
   `--from-head` 跑 drift 分类器证明 0 DIVERGED，再基于最新 origin/main 重建，而不是相信 CI 绿 = 可合并。
   注意本地 flag 拼写是 `--from-head`，`--source head` 是另一个脚本的写法。
6. **台账里声明的 verify 命令本身不可执行**（`uv run --with pyyaml python -m pytest` → `No module
   named pytest`）。按"修生成器不修输出"的同一原则，修的是**声明**（补 `--with pytest`），
   不是绕过执行 —— 否则下一条 claim 这个 bet 的 agent 会再撞一次。
7. **846 这个测试数没有意义**：文件只有 7 个 guard，其余 839 是 `pytest.mark.parametrize` 覆盖
   `bin/**/*.py` 的回归扫描。写台账/receipt 时必须说明构成，否则数字会被后来者当成覆盖率误读。
   （另注：本仓 `ls -t` 与 `grep` 被 dust/rg 替换，`--collect-only` 的计数要以实际跑为准。）
8. **门禁自己会脏 `.omo/state/system.yaml`**（纯 `health_score_evidence_generated_at` 时间戳）。
   按 AGENTS.md §7 用 `git diff --name-only origin/main..HEAD` 逐条核对后 restore 剔除 ——
   生成态不随本 bet 的 PR 走，这正是 B5 要结构性消灭的现象。
9. **`.omo/_delivery/agent-workflows/runs/` 是 gitignored 且 per-checkout 的**：`agent-workflow.py:278`
   `WORKSPACE = Path(__file__).resolve().parents[1]`。因此跨 worktree 的后继交付必须搬运 run 记录才能
   close 原来那条 run —— 不是重开一条更好看的 run。已在 receipt 里记录该 lineage。
10. **两处基础设施缺陷（只报告，不处置）**：① 根 `git commit` 后的 hook 会把子模块工作树
    rewind 回旧 pin（表现为 `M projects/omo`，须重新 checkout）；② `gac-worktree.sh bump-pointer`
    对 `0790f89` 误报"不在子模块 remote 上"，而 pre-push 的 `submodule-reachability` 实际接受它。
    ③ 另外 omo 侧存在 single-branch fetch refspec，会破坏 `submodule-sync`；④ 曾有
    `tests/` 断言 `/Users/xiamingxing/...` 字面量（把测试钉死在本机）。这些都需要 principal 决策，
    不在 B1 范围内顺手改。

## Q4 改变了什么 / 教训固化

- **对生产的影响半径为零**：`state_root()` 默认 = `code_root()`，未声明 profile 时所有解析路径
  与合并前逐字节相同；没有任何进程被重启、没有 cron/plist 被改。真正的搬家在 B4，且 B4 的
  前置门禁是 B3 的「registry 集合 == 已安装 label 集合」相等性 —— **做不到就停在 B4 之前**，
  带着 20 个无人管理的 plist 做半程切换严格比现状更糟。
- 自此 `OMOSTATION_STATE_ROOT` / `OMO_EVENT_LEDGER_DB` 是两个**有承载力的变量名**，
  `repo_root` 与 `omo_paths` 由 `test_state_root_env_name_matches_kernel_contract` 钉在一起
  （kernel 不能反向 import 父仓，所以两处各自声明）。
- **护栏必须是测试而不是 lint**：`machine-config-write-lint.py` 于 2026-09-20 被归档，正是
  旧 seam 停在 1 个消费者、以及 9 处默认值各自为政的直接原因。本轮把守卫放进 `tests/unit/`
  （`bin/` 有净新增脚本配额 `check-bin-quota-diff.py`，运维入口一律进 Makefile）。
- **dev 双实例的 git 写冲突不用 flock 解**：`OMO_ALLOW_GIT_WRITE=0` 让 dev profile 下两个会
  自动 commit 的 cron（`capability-registry` 04:05、`check-mcptool-impl-drift.py --report` 05:45）
  退化为只写 state root。
- 交付纪律复述（本 bet 全程踩到）：一 lane 一 commit（`git apply -3 --index` 会预暂存台账而污染
  首个 commit，用 `git reset --soft` + `git restore --staged .` 保内容修 lane）；spec digest 在定稿后
  计算且此后不可改；cherry-pick 跨 base 重放必查 `D` 行。
- 感知面广播另见 `docs/reports/2026-09-26-dev-runtime-profile-root-closeout.md` 与后续
  AGENTS.md / CLAUDE.md / ARCHITECTURE.md / bin/README.md / `.env.example` 更新 ——
  **契约不落进 agent 会读的地方，就等于没交付**（本仓已有两次同类教训：`.omo/state` 生成态、
  以及被归档的 lint）。
