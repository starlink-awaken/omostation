# Retro — BET-Y2Q4-T10-341

## 1. 意图（intended）

T10-292 receipt §7 登记了一条残余：同一 run 补 claim 第二批 scope 时，若其中有 scope 已在第一批
里持有，`claim` 会被拒。本条 BET 的意图是把这条残余收成一次带契约、带用例、带实机 canary 的交付，
且**不许**把 T10-292 已经交付的那一层（run 记录层 A2A 谓词）带走或放宽。

## 2. 实际发生（happened）

残余的根因**不在**登记它时假设的那一层。`claim_run()` 的 A2A 重叠循环按设计跳过自己的 run 文件
（`projects/omo/src/omo/workflow/lifecycle.py:1415` `other_run_file.name == f"{run_id}.yaml": continue`），
所以同 run 补 claim 根本走不到 `expired_lock_scopes` 那道豁免；撞车发生在下一层
`lifecycle_locks.acquire_locks()` 的 `live` 分支——它只分类锁的时效，不比对持锁者身份。

改动 +14 行：`live` 分支在抛错之前先算「这把锁是不是本 run 按同一 scope 自己持有的」，
两个身份同时成立才原地续期（保留 `created_at`、推后 `expires_at`、刷新 `last_heartbeat`、
不新增锁文件）。反例三面各一条用例（别 run、同 run 不同 scope、老格式缺身份），
外加一条回滚面用例（整批失败时本 run 早已持有的锁不得被 unlink）。

交付读数：`58 passed`；变异对照「只摘续期分支」→ `1 failed / 57 passed`，红的恰是正例；
实机 canary `SAME_RUN_RENEW True 1 1`；钉子 `T292_SURFACE_PRESENT True`。
omo#240 三腿全绿并 squash 合并为 `97fae96e9`；根仓 gitlink 同轮 bump。

## 3. 改变的东西（changed）

**认知面**：协调平面里的「自撞」有两层，且它们的两把钟不同。T10-292 处理的是 run 记录层的
`status` 谓词；锁层的 `live` 分支连 `run_id` 都不看。登记残余时把两层当成一层，
所以「按 §7 的说法改 claim_run」这条直觉路径是错的——真正要动的是被它调用的那一层。

**判据面**：锁文件名不能当身份用。`sanitize_lock_name()` + `_bounded_lock_name()`（截断 + sha256
后缀）使「同一文件名」不蕴含「同一 scope」，所以续期条件必须同时比 `run_id` **和** `scope`，
且 payload 解析不出 mapping 时一律 fail-closed。这一点写进契约而不是只写在用例里。

**装置面**：本轮另发现第三种形状（见 §4 第三条），它比本 BET 交付的形状更常在真实工作里发火。

## 4. 教训（lessons）

- **登记残余时写的「在哪一层」是 hypothesis，不是 measurement。** 本轮先按 §7 的文字去找
  `claim_run()`，跑了一遍才看见 `:1415` 那行 `continue` 直接把整条假设否证。判据：写
  「X 层的 Y 分支」之前先跑一次最小复现，让栈自己指认；别按 receipt 的散文开工。

- **正例转绿不能替反例承重。** 变异对照必须按改法分别记读数：本轮只摘续期分支时恰红 1 条，
  其余 3 条仍绿——这证明那 3 条与本改动不共享失效模式，而不是「它们没用」。反过来，
  若 4 条一起红，说明正例写宽了。

- **「锁文件缺席」与「锁文件未过期」在 T10-292 的豁免里同形，这是本轮撞上的第三种形状：**
  `lock_scopes_past_expiry()` 只枚举**存在的**锁文件。一个已交付 BET 的 run 记录若没被翻到终态
  （实测 `20261104T115230Z-project-code-change-d825f60f`：`status: active`、`last_heartbeat` 键缺失、
  `locks:` 仍列 `path_docs_plans_3y-bet-ledger.yaml.lock.yaml` 而该文件已 release 不在磁盘上），
  它 `claims[].paths` 里的那条路径就**永久**阻塞后续 claim——既不过期豁免够不着，
  `prune-locks` 也不认（它扫的是锁文件，锁文件已经不在了）。
  本轮不拆别人锁、不改别人 run 记录，只把 ledger 路径从自己的 claim 里摘掉并如实记录读数；
  该形状另铸 BET。

- **partial worktree 会让 pre-push 的子模块检查换个名字就红。** `sync-submodules-push.sh` 把
  「`.git` 存在但 HEAD unborn」计成 `failed`（阻断），把「`.git` 不存在」计成 `missing`（合法跳过）。
  两者语义相同（都不是本次 diff 造成的），读数却一个是 1 一个是 0。实测本轮为了让 `failed=0`，
  先后要处理 `projects/knowledge/kairon`（补齐 pin）与 `projects/l4-kernel`（让 clone 走完成为
  干净缺席）；而 `git checkout` 触发的 `guard-submodules --fix` 会把手工布置的检出
  当无效目录**先删后建**（AGENTS.md §7 已登记），于是修好的状态在一次分支切换后回到原点。
  纪律：**对齐子模块与切分支不要在同一轮交错做**；要切分支就先切完，再 align，再 push。

- **`git -C <未 init 的子模块>` 会向上解析到父仓**（本轮又一次撞上）：`git -C projects/l4-kernel
  rev-parse HEAD` 返回的是**根仓** commit `292d3a6ab`。如果那段修复脚本没先判 `--show-toplevel`，
  它会对着根仓执行 `fetch` + `checkout --detach`。本轮因脚本对「HEAD 可读」的分支只打印不修，
  才没有真的执行。判据已写在 AGENTS.md，这里补一条：**批量对齐子模块的临时脚本，第一步必须是
  `rev-parse --show-toplevel` 等于目标路径**，不是先 `rev-parse HEAD`。
