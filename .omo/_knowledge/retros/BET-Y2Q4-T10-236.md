## 4 lessons（可复用的一条是什么）

1. **交付面按实测收缩，比按 spec 预列扩张更常见**：spec 写「改 2 行」时没料到上游已改；
   开工前用 `git log -S'<目标语义>'` 判一条折叠是否已落地，能避免把别人的交付重复做一遍
   （PITFALL-GAT-006 的判据版）。
2. **「清单相等」的两种塌法要分开防**：检测器少认一种形状（本轮 11→9 的真实成因）与清单
   多留一条死项，读数都是「绿」。⇒ 相等断言之外必须配一条**点名件**（合成站点被扫出、
   且不在清单内），否则相等只证明了两边同样窄。
3. **substring 判据是假绿温床**：`"0/100" in stdout` 会被 `100/100` 满足，锚定字段
   `**复合健康分**: `0/100`` 才区分「合法的 0」与「被折叠出来的 0」。
4. **共享协调面的锁不能靠拆绕**：并发 active run 持 `project:` 时，`--force-lock` 与
   `prune-locks` 都不是路径（后者阈值 3600s 只看心跳，闲置一小时的活 run 会被判 zombie）。
   把可在复刻树完成的测量先做完，是对锁唯一正确的用法。
5. **worktree 的门禁 FAIL 要逐项命名归类，不能整块当噪音**：本轮三项本地 FAIL 分别是
   子模块未完整物化（`bun run build` 无 build 脚本 / `No module named 'agora'`）、
   机器级 plist 与仓内 registry 的既有漂移（待署名裁定项）、以及主区同项 PASS 的环境差。
   判据：每一类都要给出「主区/CI 对照读数」，否则「本地红」既可能被读成回归，
   也可能把真引入的缺陷一起淹掉。
6. **`git archive` 复刻树 + blob sha 对拍是「不动交付树」做变异的标准装置**：
   变异在复刻树里做，改回后 `git rev-parse <base>:<path>` 两侧一致才算复原；
   这样交付树上的反基线证据永远是零副作用的。
