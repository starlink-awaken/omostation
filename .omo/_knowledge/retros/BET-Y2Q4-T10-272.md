# BET-Y2Q4-T10-272 复盘总结

## 1. 战役背景与目标
ADR-0456 B4b 规定了从 Workspace 向独立安装位与状态根迁移的愿景，其中验收指标要求「指向 Workspace 的 plist 由 43 → 0」。然而在实地工程中，仓库内缺乏可测量的自动化尺子。
本战役目标是构建纯观测 (Observe-Only) 的现实核对尺，让 81 个 plist、39 个指向 Workspace 的存量以及 `EnvironmentVariables.OMOSTATION_STATE_ROOT` 写根落点 100% 透明可视化。

## 2. 核心交付物
1. `bin/mof/gen-service-configs.py`:
   - 增加 E7 写根轴，解析 plist 中的环境变量并分类为 `profile | checkout | install | undeclared | undetermined`。
   - 单测 `tests/unit/test_reality_check_state_root_axis.py` 17 项全绿通过。
2. `bin/gac/launchd-workspace-reality-check.py`:
   - 面向工程运维的宏观透视工具，实测分类 81 个 LaunchAgents，准确报告 39 个指向 Workspace 的服务分布。
3. 契约保障：
   - 严格遵循 Observe-Only，退出码恒为 0，不破坏任何现有宿主常驻守护。

## 3. 经验与教训 (HITL 结晶)
- **Worktree 路径与 Canonical 路径的区分**：在 Worktree 隔离环境下，`code_root()` 返回的是当前临时 worktree 路径，而 LaunchAgents 中写入的硬编码通常是主仓 `canonical_root()`。检测工具必须同时比对两类路径，方能杜绝漏判。
