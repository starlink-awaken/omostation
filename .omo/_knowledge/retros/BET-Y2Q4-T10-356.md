# BET-Y2Q4-T10-356 复盘 —— cron 主仓直提断根 (worktree + 自动 PR)

## 结果

- 债 CRON-CAPABILITY-SYNC-MAIN-DIRECT-COMMIT 修法 (a) 落地: 生成器
  `--publish` 模式 (fetch → 临时 worktree + 子模块 → 生成 → 无漂移即弃 →
  commit/push → gh pr create + merge --squash --auto → 清理), 主仓工作区零接触。
- registry.yaml 命令链换 `--publish`, 债条目 resolve (owner 裁定 a 于 2026-11-26)。
- 端到端「无漂移跳过」路径真跑通过 (rc=0, 2:15, 残留 worktree=0)。

## 坑 (供后续 BET 避让)

1. **worktree add 不带子模块** —— 首跑 `--publish` 在临时 worktree 里
   `NativeInspectionError: source_unprovable` 崩掉: 生成器扫 `projects/*`
   子模块源 (agora 等), 裸 worktree 里子模块是空目录。凡是扫子模块源的
   脚本, 临时 worktree 场景必须 `submodule update --init --depth 1` 补腿
   (实测 ~83s, 本地对象库复用, 非网络全量)。
2. **管道吞 rc** —— `cmd | tail; echo $?` 拿到的是 tail 的退出码, 首跑
   traceback 明明失败却显示 rc=0。端到端验证必须直采 rc (`cmd; echo $?`
   先落文件) 或 `PIPESTATUS[0]`。
3. **验证边界要诚实** —— 无漂移路径端到端真跑; 有漂移→PR 路径的 gh 链
   (create + merge --squash --auto) 用本 BET 自己的 PR 走同款命令佐证,
   首个真实判例留给次日 04:05 cron 首跑, `tail runtime/cron/capability-registry-sync.log`
   回查。不谎称两路径都已实测。
4. **装载面时序依赖** —— crontab 重装必须等 PR merge 之后: 装早了
   origin/main 的生成器还没有 `--publish` flag, 次日 04:05 argparse 直接
   报错。声明面 (registry.yaml) 与装载面 (crontab) 之间隔着 merge 事件。
5. **digest 纪律** —— spec frontmatter 补 `status: accepted` 一行, sha256
   就变了, 台账 digest 重算重绑一次。frontmatter 定稿在前, digest 在后。
