# BET-Y2Q4-T10-240 retro — DCP-20: 代码完成≠交付, id 会撞车, verify 会骗人

## 1 intended — 本来打算做什么

关闭 Zhixing 通用 GET 路由的执行型副作用（DCP-20 本体），并把这条 BET
按规范以 `delivery_accepted + deployment_state: BLOCKED_G0_M0` 收口。
原以为车道跑完三次 bet-execution 就能直接 complete。

## 2 happened — 实际发生了什么

代码 2026-10-08 就写完测完（115 测试过、独立复核 CLEAR），但**收口收不动**,
一路挖出五件事：

1. **代码从未提交**：`EXECUTION_OPERATIONS` 只存在于车道工作树的暂存区,
   main 与 BET 分支 tip 都没有。三次 blocked run 的"blocked"是真的——
   `complete` 的 `merged_reachable_commit` 不存在。
2. **T10-236 id 撞车**：DCP-20 的 ledger 条目/spec/waiver **从未上 main**
   （登记 PR #4686 被关），而 #4688 把 ADR-0456 B5 条目以 T10-236 注册上了 main。
   车道暂存条目被 wip-guard 快照进特性分支（ccecdd571）后无人认领。
3. **verify 命令三处笔误**：`python3 -m pytest` 系统 python 无 pytest；
   `status --json` 旗标顺序与车道新 CLI 不符（子命令级 `--json`）；
   引用 4 个全仓不存在的 unittest 文件。三条都让 verify 结构性失败。
4. **spec 路径陈旧**：write_surfaces 指向不存在的非版本名，实际文件是 v1.1.0。
5. **三次 blocked run 关不掉**：closeout 前置 verify 过不了, 维持 blocked（准确态）。

## 3 changed — 改变了什么

- DCP-20 重注册为 **BET-Y2Q4-T10-240**（#4703, 内容不变, id 让位）
- verify 命令修正（#4704）：补 `--with pyyaml`、`status --json` 回退、删除幽灵 unittest
- spec v1.1.0 + waiver 补入 main 并补 frontmatter
- 车道暂存代码原样落 main（#4705, 36 tests pass）

## 4 lessons — 固化什么

- **暂存区不是交付**：staged 但未 commit 的工作对 main 不存在, 对 `complete`
  不存在, 对下一个接手的 agent 也不存在。判据：验收任何"已完成"声明前,
  `git ls-tree origin/main:<path>` 与符号存在性检查, 不看工作树状态。
- **wip-guard 快照会把未登记条目带进分支**：ccecdd571 把 T10-236 条目快照进特性分支,
  制造了"条目已存在"的假象, 而 main 上从来没有任何 DCP-20 条目。
- **id 撞车的根因是登记动作被取消**：#4686 被关后无人重挂, 空 id 被下一个 BET 占用。
  登记类 PR 关闭必须同步作废依赖它的 run/objective。
- **verify 命令是契约不是文案**：旗标顺序、依赖包、文件存在性, 每条都要对着
  实际代码实测（本轮 3 条全错）。

## 5 遗留（实测后登记，不是遗漏）

- **部署保持 BLOCKED_G0_M0**：LaunchAgent 身份链未修, G0/M0 晋升需独立 release BET
  （拟 **T10-241**, draft 已备, depends_on T10-240）+ 人类授权。
- **三次 blocked run**（bet_id=T10-236）：车道失联, verify 过不了无法 closeout,
  维持 blocked; 其持有的 bet/root-gate/path 锁随 run 终止自然失效。
- **A6/A9 挂门**：或ca 证据与 cockpit 源健康依赖 Zhixing 运行时, 属 T10-236 部署面。
