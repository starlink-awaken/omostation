## 4. 教训（lessons）

1. **台账派生计数器的冲突不能靠「重建整份文件」解**。`meta.total_bets` 是派生值，两侧同时改同一行时
   行级三方合并看不见「我的内容是 main 的超集」，整份重建恰好制造这个重叠。
   正解已由 `.omo/_knowledge/retros/BET-Y2Q4-T10-210.md` 第 7 条点名（"我第一次的修法制造了第二种模式"），
   本轮第二次踩同一坑才走回它：`git merge origin/main` + 解成超集，配
   `docs/SOPs/ledger-closeout-sop.md` §3.6 三条断言（实测 `524==524` / dupes `0` / main 侧 523 条
   逐条存活、done 519→519 / diff `+71 −1`）。**纪律**：撞台账先读 T10-210 与 SOP §3.6，不要先重建。
2. **测量脚本自己也要被测量**。我在断言里写出 `len(tb and mb and tb and tb or mb)`，它打印
   `actual=523` 却同时打印 `PASS` —— 一次典型的「假读数配真结论」。判据：断言脚本里每个参与 PASS/FAIL
   计算的量必须**单独命名、单独打印**，且打印值与结论可比对；否则先把脚本改对再谈结论。
3. **`cmd | tail` 吞 exit code 本轮复发两次**：pytest `11 failed` 被后台通知报成 exit 0；
   `make gac-local-gate` 的 uv 环境失败也靠读末行才发现。判据：需要退出码时不让管道当终点。
4. **done_when 的 prose 会因实现追加而变陈旧**：done_when-1 写「变为 9 passed」，
   实测两文件是 **10 passed**（我随后补了第 4 个用例）。本轮**没有**改台账里的这个数 ——
   `done_when` 在 WorkPacket 投影内，claim 之后再改会给后续 claim 造 `WORK_PACKET_SOURCE_DRIFT`；
   修法是在台账已进 `origin/main` 之后改文并用 `agent-workflow.py refresh-packet` 重新编译 packet。
   **纪律**：done_when 里写**判据语义**（"全部转绿"）比写具体条数更耐久。
5. **新 claim 的 worktree 里 `make gac-local-gate` 可能环境性不可用**：uv 试图
   `Creating virtual environment at: .venv` 并 canonicalize 一个已不存在的
   `/opt/homebrew/Cellar/python@3.14/3.14.7/.../python3.14` → `make` Error 2。这不是治理失败。
   verify-4 改用直跑 `python3 bin/gac/gac-local-gate.py --scope run --run-id <run>`，
   并把这条环境差异写进回执，别把它读成"本轮引入的红"。
6. **读数必须绑定「哪棵树 + 是不是独占跑」**。本轮先后得到两个全量读数：`11 failed / 1901 passed` 与
   `10 failed / 1903 passed`。差别**不是**顺序波动，而是两件事：① 前一次跑在 #4643 合并前的树上
   （总用例 1912 → 1913 变了，说明集合本身不同，不能当同一集合的抖动）；② 我发现时该 worktree 里正有
   **两个 `pytest tests/unit` 并发**（一次是压缩前遗留的后台任务没随会话结束而死），同检出并发跑正是本 BET
   修的那一类污染，于是两边读数都不可信 —— 全部杀掉后重跑一次才拿到 10/1903。
   **判据**：写"残余红"时同时记 `git rev-parse --short HEAD`、`failed+passed` 总数、以及跑前独占检查
   `ps -eo pid,command | grep -c "[p]ytest tests/unit"` **== 0**（⚠️ macOS/BSD `pgrep` 无 `-c`，
   实测 `usage:` 退出 2 —— 计数只能走 `grep -c`，且模式要写成 `[p]ytest` 免得自匹配）。总数变了就是换了树，
   先确认 base 再谈消长。
