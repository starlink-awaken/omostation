# BET-Y2Q4-T10-284 retro

## 1. 本意（intended）

ADR-0456 B4b 的逐批验收判据写着「每批切完 `--reality-check` E2 仍为 0」，中止判据是
「任一批后 E2 ≠ 0 即停」。批次 1 之后 E2 = 1（`com.user.omlx-smart-gateway`：本机真实在跑、
注册表未声明），B4b 批次 2 因此被自己的判据按住。本 BET 要在 **agent 权限面内** 把 E2 复零，
使 B4b 批次 2 重新可开工 —— 不碰机器 launchd，不改判据本体。

## 2. 实际发生（happened）

- 取证：`launchctl print` 可读该 job（state = running，pid 49772，从未退出）、18080 LISTEN、
  `GET http://localhost:18080/gateway/status` 200；本机 plist 六个键与登记条目逐一对应，
  **无 `EnvironmentVariables` 键**。
- 三条候选路线的取舍（`gen-service-configs.py` 轴序决定，非偏好）：
  1. `exempt_labels` —— **不可达**：`classify_label()`(:403) 先查 `workspace_prefixes`，
     `com.user` 前缀由 BET-Y2Q4-T10-206 加进（那是 #91 尺的口径来源），前缀判定先于豁免清单，
     加了仍计入 workspace 分区。
  2. 撤 `com.user` 前缀 —— 把 E2 的 1 换成 E4 的 22→23，并推翻一条已署名 BET，代价更大。
  3. **observe-only 登记**（`enabled: true` + `generate: false`）—— 选定：只登记现实，不夺取
     plist 的写权；E2(:731) 与 E5(:790-791) 两个方向都归零，对 E1/E3 零扰动。
- 交付：6 commit / PR #5039，因 base 漂移被受控后继 PR **#5042** 取代（教训 7、8）。首跑 CI 红，
  根因是**我自己**的一条 ERROR：spec frontmatter 缺
  `owner`（`missing_frontmatter:accepted-specifications count=1` 落在未预算的 warning 桶 ⇒
  `unbaselined_warning` [error]），补 `owner`/`schema` 后本地 `doc-governance-check --scope
  workspace --no-new-warnings` 实测 ok=true、0 error。
- 复测：`--reality-check` e2_undeclared 0、owned_installed 51 == owned_declared 51、
  e1 0 / e3 0 / e5 双向 0；`ok` 仍 false，驱动项是 E4 的 22 条未分区 label（#147，本 BET 不碰）。
- 反证（台账 done_when 强制项）：同一 `reality_check()` 跑「剥掉本条的注册表」得 e2 1 + owned 50，
  跑现注册表得 e2 0 + owned 51，其余字段全等 —— 归零由本条造成，不是别处凑上来的。

## 4. 教训（lessons）

1. **「归零」有两种机制，选错的代价是另一条轴的债**：declare（登记现实）与 exempt（清单豁免）
   不等价。判据的分类顺序（前缀 → 豁免）决定哪条路可达 —— 修法要按尺的实现序倒推，不能按语义直觉。
2. **spec 绑定后编辑 spec 会永久 drift-lock 该 run 的 claim**：`validate_work_packet_run`
   (`bin/plan/bet-ledger.py:2348`) 每次 claim 用当前台账+spec 重建 packet，改一个字节即
   `WORK_PACKET_SOURCE_DRIFT`。本轮第三次实证（T10-259 两个 run、T10-258 单 run 声明 8 面）。
   纪律：**start 之前**先把 spec 过一遍 `doc-governance-check`，并把收口腿要写的
   retro/report 路径**一次性**写进 `write_surfaces`。
3. **技能清单会漏键**：`bet-closeout-chain` 的「frontmatter 七件套」没有 `owner`，而
   `accepted-specifications` surface 的 `required_frontmatter` 有 —— 照技能写必被 CI 拦。
   已作为技能缺陷单独登记，不在未 claim 的文件上顺手改。
4. **写进 notes 的计数会腐烂**：同族条目数「35」实测已是 57，「前 50 条」这种相对措辞更是
   定时炸弹。判据是「跑一次能复算吗」，不能复算的就删掉计数。
5. **本机 `python3` 跑不了治理脚本**：Xcode 3.9 既无 pyyaml 也无 `datetime.UTC`(:12)，
   直接跑会把「脚本坏了」误读成「门禁红了」。可用口径是
   `uv run --no-project --python 3.12 --with pyyaml python <script>`。
6. **明文令牌不进仓**：入口脚本 `~/.local/bin/omlx-smart-gateway.py` 内含明文 bearer token；
   本轮只登记「它在哪、它活着」，值不复制进 services.yaml / spec / 台账 / PR / 本 retro。
   已向 principal 报告并建议轮换。
7. **CI 的 workflow 定义与检出树可以来自两棵树**：`governance-verify` 显式
   `ref: pull_request.head.sha` + `fetch-depth: 0`（评分支自己的 head tree），而**步骤集合**取自
   PR 的 merge ref（= 最新 main + head）。base 前进后，main 新增的 step 会跑在我那份**旧**代码上。
   本轮实测：main #5041 同时改了 `tests/unit/test_diff_debt.py`（`git init -q -b main`，去掉对
   `init.defaultBranch` 的依赖）并接线 step `diff debt marker gate`，我的 head tree 只有旧用例 ⇒
   2 fail（`ERROR: 无法解析 ref 'main'`），而**我的 diff 一行代码都没碰**。判据：`git diff <base> HEAD
   -- <失败用例>` 为空 + main 自身 push CI 绿 ⇒ 红属 base 漂移，不是本 PR。
8. **「把 main 合进 PR 分支」在本仓被结构性封死**：`git merge origin/main` 能过 pre-merge-commit
   （前提：未初始化子模块要先 `git submodule update --init <path>`，钩子只给这条路），但 pre-push 的
   lane 尺用 `rev-list --no-merges` 枚举 push 范围 —— merge commit 自己豁免，main 的混 lane 提交
   （`d53f975b1`: code+docs+governance_code）却落进我的范围 ⇒ FAIL 拒推。因此 base 前进时的合规路线
   只有 WP1 typed 指令的 **distinct managed full successor**：在最新 main 上重放同样的提交，旧 PR 标
   superseded 关闭（先例 #4745→#4749，本轮 #5039→#5042）。重放前查文件面交集（`diff --name-only
   HEAD...origin/main`），零交集才敢逐条 cherry-pick；重放后必查 `diff --name-status origin/main..HEAD`
   无 `D` 行（PITFALL-COO-005）。
9. **Grep 输出的高亮转义会吞掉命中片段，制造「幻影引用」**：`grep` 在本机是 rg，命中子串被 ANSI
   高亮包裹后经管道回传常塌成 `n` / `ln` 之类碎片。本轮据此一度判定 `bin/n.py` 是被 sed 损坏的幽灵
   路径 —— 实际实现是 `bin/change-lane-check.py`，`bin/n.py` 根本不存在。定「某引用是幻影」之前必须用
   `--help` / Read 直读实体（第 3 次实证「判据报警先 print 原始行」的姊妹形态：证据通道自身也会失真）。
