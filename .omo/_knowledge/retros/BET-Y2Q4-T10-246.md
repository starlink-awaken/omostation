# BET-Y2Q4-T10-246 retro — 把「E2 归零」拆成两个可证伪的读数

性质：ADR-0456 **B4b 批次 2+ 的前置** —— 本轮不动本机 launchd，只让「已装 label == 注册表」这条中止判据在本仓可证。

## 1 intended — 本来打算做什么

B4b 的 done_when 里挂着一条中止判据：「每批切完 `--reality-check` E2 仍为 0」。
先跑一次就发现它**已经**被违反：本机 E2=3，其中两条占用 `com.omostation.*` 命名空间的服务
从未在 `services.yaml` 声明。用户选的路径是「先修 E2 前置，纯仓库改动走 PR，不碰本机 launchd」。

所以这轮的理想态是三条同时成立：① 我登记的两条从 E2 消失；② 登记这件事对 E1/E3/E4/E5 与 CI
`--validate` 零扰动；③ 本机 plist 的 mtime/size/sha256/`launchctl` 状态逐字节不变。
外加一条被现场逼出来的：② 的「两棵树并集」必须单独证，因为 E2 的读数根本不属于这台机器，
它属于**你站在哪个检出里跑命令**。

## 2 happened — 实际发生了什么

**先撞的是口径，不是代码。** done_when 写「指向 `Workspace` 的 plist 由 43 → 0」，
而 `--reality-check` 的实际尺子是 `workspace_scoped=33`；43 是 `owned_installed`。
两个数都真实存在，是把不同字段的读数当成同一件事写进了判据 —— 已在 spec §1 记录，不动 done_when 本体。

**E2 读数在 20 分钟内自己变了。** 同一台机器、同一条命令，先测 E2=3，后测 E2=2。
没有假设「现实变了」，而是去查注册表来源：`--reality-check` 读的是**当前检出**的
`.omo/_truth/registry/services.yaml`。主工作区 `d06571798` 领先 `origin/main` 11 个未 push 提交，
其中 `ccecdd571` 声明了第三条 label；`origin/main` 没这条。于是范围不能用「E2 列表里有什么」定义，
改用谓词「在两棵树里都零引用」，筛出恰好两条异主 label 属于本轮，第三条归并发线。

**exempt 这条路结构上是关的。** 想绕 E2 的第一反应是把异主 label 塞进 `exempt_labels`。
读码发现 `bin/mof/gen-service-configs.py:478-480` 会主动报
「E4 exempt 项被 workspace 前缀遮蔽 (死数据)」——E2 分桶由 `launchd_namespace.workspace_prefixes`
（11 条前缀）派生，不由路径派生，所以 `com.omostation.*` 下的 exempt 项永远读不到。
把机制写进 spec §3，而不是试一遍撞墙再改回来。

**`generate: false` 不是偷懒，有一条 plist 替它作证。**
`com.omostation.zhixing-brief-watchdog.plist` 带 `ProcessType: Background`，
而生成器从不发射这个键。若把它声明成 `generate: true`，`--check` 会立刻逐字节比对，
E1 漂移当场+1。另外三条实现理由（`:645-652` 跳过比对、`:142-165` 早返回、`:627-629`
对 launchd+generate:false 跳过 `resolve_interpreter`）都在 spec §4 落了行号。

**`enabled` 取 true 还是 false 也被判据钉住。** `:503-505` 的 E5 不变式是「enabled ⇒ 必须已装」，
两条都已装，所以声明 enabled:true 零扰动；声明 disabled 反而造出「disabled 却已装」的新 E5 残留。

**两处 CLI 参数是猜错的。** `agent-workflow.py claim` 收 `--actor` 不是 `--profile`；
`affected-graph.py --changed-projects` 的合法 token 是 `workspace-root`（`bin/gac/affected-graph.py:18`
`WORKSPACE_ROOT_PROJECT`），写 `workspace` 直接 `unknown project(s)`。都靠读码而不是重试解决。

**交接后差点按摘要重做一遍已合并的交付。** 上下文压缩后接手时，摘要说 HEAD 是 `b884e2919`、
分支 `t10-246-e2-backfill`、`services.yaml` 未改。实测：HEAD 已是 `94ef45831`（即 #4729 的 squash），
分支已是 `t10-246-closeout`，注册表里两条已在。若照摘要动手会重复插入并造出重复 id。
先测真实状态（`git log` / `gh pr view` / `yaml` 计数）再动手，这一步省掉了一次自我冲突。

**canary 快照补不进去，是结构而非疏忽。** 收尾时想照 T10-245 的样子另落一份
`docs/reports/…-canary.json`，`claim` 当场 `WORK_PACKET_SCOPE_MISMATCH` ——
本轮 write_surfaces 只有五条路径，而 `bin/plan/bet-ledger.py:2333-2336` 的漂移检查在 scope 检查**之前**，
说明「先改 write_surfaces 再 claim」会直接撞 `WORK_PACKET_SOURCE_DRIFT`（write_surfaces 是投影字段），
`refresh-packet` 又要求台账已等于 `origin/main`（我的 evidence 编辑还没提交）。三条路都堵，
处置是把读数快照内嵌进**已声明**的 receipt，并在 receipt §2b 写明为什么没有独立文件。

**ISC-6 的「移除 44 行逐字节还原」是真测出来的。** 不是「应该相同」：
按 `- id:` 边界删掉本轮两块后，与合并前 `origin/main@b884e2919` 的注册表 `==` 成立，
YAML 仍是 2 docs / 373 services / 373 unique ids。这条判据的价值在于它同时否证了
「顺手改坏了邻居条目」和「插入位置跨了文档边界」。

**所有 ISC 用直接测量复核，不信草稿。** 复跑 `--reality-check` 得 E2 3→1，余项恰为
`com.omostation.panorama-compact-observation`；E1/E4/E5/installed_total 与改前基线逐字段相同；

## 4 lessons — 固化什么

- **测「本机实况」的判据必须先命名产生读数的树。** E2/E1 这类 `--reality-check` 读数不是机器属性，
  是「机器状态 × 你所在检出的注册表」的积。写进 done_when 或 receipt 时若不注明注册表来源，
  同一命令 20 分钟后自证矛盾；多 agent 并发下更会把别人的未 push 声明读成自己的遗漏。
- **范围用谓词定义，不用列表定义。** 「修 E2 列表里的项」会把并发线的活儿吞进来；
  「在两棵树里都零引用的已装 label」才是本轮的边界，且这条谓词本身可复算。
- **想绕门禁前先读它的分派逻辑。** exempt 看起来是最省事的解，实际被 `:478-480` 判成死数据。
  结构性关闭的门禁不是「这次没生效」，是「永远不会生效」——值得写进 spec 而不是留个 TODO。
- **observe-only 的证据是那个生成器不会发射的键。** `ProcessType: Background` 一个键就否证了
  「顺手改成 generate: true 更整洁」的直觉；诚实登记的理由要落行号，不落形容词。
- **数字口径分歧要在动手前落成文字。** 43 与 33 都是真实字段，混淆的代价是 done_when 永不可满足；
  发现即记录，别悄悄按自己顺眼的那个执行。
- **WorkPacket 的写面在 `start` 那一刻冻结。** write_surfaces 是投影字段，中途加路径 = 造漂移，
  `refresh-packet` 又要求台账已在 `origin/main`，新建 BET 的首轮用不上它。
  所以 mint 台账时就要把**所有**收尾产物（receipt、retro、canary/快照落点）写进 write_surfaces；
  漏了就只能内嵌进行为补救，而不是硬开新文件。
- **接手压缩后的会话，第一件事是重测状态而非信任摘要。** 本轮摘要的三个「当前状态」全部过期，
  而它们看起来完全自洽 —— 自洽的过期摘要比明显损坏的更危险。
