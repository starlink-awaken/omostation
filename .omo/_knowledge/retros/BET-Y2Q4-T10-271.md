# BET-Y2Q4-T10-271 retro

台账：`docs/plans/3y-bet-ledger.yaml` `BET-Y2Q4-T10-271`
规格：`docs/superpowers/specs/2026-10-26-bet-271-e4-admission-resign-22.md`

工程腿：PR #4902 → squash `63d389cee`

## 1 本打算发生什么

把 T10-259 署名的准入清单从 19 行重签到 22 行，并把这三条落进机读豁免面
`launchd_namespace.exempt_labels`；我在立项文案里向 principal 承诺的结果是「E4 归零」。

## 2 实际发生了什么

授权执行完就是全部现实：`exempt_labels` 11 → 14，准入表 19 → 22，双向集合相等
（`missing=[] extra=[]`）。但 E4 的读数是 **19 而不是 0**，`e4_prefix_ok` 仍为 False。
原因不在执行，在立项：门禁 pass 条件是 `bin/mof/gen-service-configs.py:773`
`not any(f.startswith("E4") for f in findings)`，而 `:684` 只要
`buckets["unmanaged_unknown"]` 非空就报 E4 —— 它要求**每一条本机已装 label 都被分区**。
T10-259 的 19 行只是文档面（该 spec §6 自己拒绝「为凑 `ok=true` 把 label 塞进 `services.yaml`」），
所以「19 签 + 3 新 = 全签完 ⇒ E4 归零」这句话从一开始就不可满足。

四条改动全部按 lane 切开交付（`docs`+`docs_data` 一 commit、`governance_state` 单文件一 commit），
两个 `gac-local-gate --scope staged` 均 `ok=True`，CI 22 success / 3 skipped，`mergeStateStatus=CLEAN`。

## 3 因此改变了什么

- **spec 与台账里所有「归零」措辞**在同批改成如实终态，并新增 §2.1 把 pass 条件本体写进契约
  （读自源码，含 `:773` / `:684` 两个行号）。
- **验收判据 1 从「退出码 0」换成 JSON 逐字段断言** —— `--reality-check` 在 `ok=false` 时 rc=1，
  按 rc 写验收会把正确的红灯读成命令失败。
- **一条判据换装置读数不同的新面**：注册表面的四条回归用例在 `HOME=<空>` +
  `env -u OMOSTATION_ROOT` 下 2 failed，红的是 `canonical_root()` 定位不到规范检出。
  处置是给被测检出显式钉 `OMOSTATION_ROOT`，并把这条装置要求写进 spec §4 复算命令 D。
- **digest 耦合跨到另一条已闭合 BET**：改 T10-259 spec 的字节 → 台账里它的 `content_digest`
  与一处裸十六进制 `verify expect:` 都要同步（两处文本形态不同，第一次按 `"sha256:"+hex`
  匹配只命中 1 处）。

## 4 教训（进感知面的那一句）

**给 principal 的选项里凡是「门禁会变成什么读数」的承诺，必须先从门禁的 pass 条件源码导出，
不能从「待办清单少了几项」倒推。** 二者只在「清单 == 门禁的全集」时等价，而准入清单天生是
门禁全集的一个子集 —— 这次是 19/22。同族形状：把「我已登记的都处理完了」读成「门禁会绿」。

第二条，比第一条更贵：**自己写下的不可满足验收，只有回头读判据本体才会暴露**。所以「先跑一次
再写进契约」（T10-264 起反复用）在这里的加强版是：**先读 pass 条件再写进契约** —— 跑一次只能
告诉你当前读数，读源码才能告诉你这个读数能不能变绿。
