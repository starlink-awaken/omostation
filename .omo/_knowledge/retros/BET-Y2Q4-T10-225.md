## 1. 本意要发生什么

ADR-0456 双根改造走到 B5/T10-224 之后，这一路踩到的形状有个共同点：**不是报错，是「报错的机制」本身不响了**。
本 BET 不解决任何工程问题，只把六条达标的形状（含其**指认方式**）固化进 agent 感知面，并把台账并发追加的
恢复配方写进 SOP —— 因为人类说「完成之后记得更新运维和基建以及 agent 的感知，否则其他 agent 不知道」。

## 2. 实际发生了什么

交付本身按 spec 完成（4 文件、211/2、零 `.py`、合并树复跑 5/5 绿）。但**过程里踩到的东西比结果更值得记**，
而且有几条正是本 BET 自己要固化的形状：

- **差点写出一条否证自己内容的判据**。台账 `verify` 第二条我最初写成「陈旧行号指针在 `AGENTS.md` 中必须不存在」，
  实测 `stale_pointers=['…:42', '…:146']`、rc=1。原因不是内容错，而是 ⑥ **必须点名陈旧形式**才能作为证据。
  判据与被固化内容正面冲突。若我按原样「修内容去迁就判据」（把那两条引用删掉），就正好销毁了这一条的教学价值；
  若我把判据改成恒真，就正好犯了本 BET 要固化的 ③。**正确解只有把判据的射程收窄到它真正要保护的对象**：
  「`「已提交的 legacy 兜底」` 那一条内不得出现裸行号指针，且必须出现两个符号名」。
  ⇒ 教训：**判据要在内容写完之后再实测并逐条解释失败原因，绝不许先写判据再期望内容符合。**
- **两道 schema 校验不一致**：`bin/gac/ledger-safe-insert.py` 放行了我的条目，`bet-ledger.py lint` 随后报
  `ERROR … 缺字段 verify`。插入器校验的是它自己那份字段集，`lint` 校验的是 9 个必填字段。
  ⇒ 「插入成功」不等于「台账合法」，插入后必跑 lint。这是 E1 家族的近亲（两个同根因判据一起假绿）。
- **`claim` 超时但 worktree 已建成**，而我的管道 `| tail` 把 exit code 读成 0（AGENTS.md 已记录该陷阱，本轮复发）：
  PASW 因 `全部子模块 init 超时 (300s/次, 305s)` 拒了 claim，`kairon.git` clone 失败，但 worktree 与分支都已存在。
  ⇒ 我没有重复 claim（重复会撞已有分支），只按需 init 了 `projects/omo` + `projects/ecos` 两个真正被代码需要的子模块。
- **`start --bet` 的前置是两个子模块在盘**：先是 `ModuleNotFoundError: No module named 'omo'`，
  补 init 后又 `WORK_PACKET_COMPILER_UNAVAILABLE`（缺 `projects/ecos/src`）。而 `projects/ecos` 处于
  2181 行 porcelain、**全部 `D `**、非 `D` 为零的半初始化态 ⇒ 按 AGENTS.md 第⑤类脏项自清：
  在**子模块内** `git reset --hard -q`（不是主仓），随后 `start` 一次成功。
- **`uv run --with pyyaml` 因 host 补丁版漂移失败**（`python@3.14.7` 路径已不存在，实机 3.14.8），
  且失败时留下一个半截 `.venv` ⇒ 我用 `shutil.rmtree` 清掉自己的产物，改用 `python3` 直跑。
  这台机器上 `uv run` 不是可靠前缀，而它失败会**污染检出**。

## 3. 由此改变了什么

- `AGENTS.md` §7 多了一条覆盖 ①–⑥ 的形状清单，并把 ⑥ 顺手用在自己身上（就地修正两条陈旧指针）。
- `docs/SOPs/ledger-closeout-sop.md` 多了 §3.6 台账重建配方，Step 4.2 那句「优先保留 main 版」被显式标注
  **不适用于台账**。
- `meta.total_bets` 519 → 520，且用三条断言证明这次追加没说谎。
- 新增 BET 的合法形状里 **`verify` 是必填**：本轮之后，`ledger-safe-insert.py` 放行 ≠ 合法，插入后必跑 lint。

## 4. lessons（可迁移的部分）

1. **固化一条判据时，判据的射程必须与它要保护的对象同宽** —— 比对象宽会误伤自己写的证据（本轮 rc=1），
   比对象窄会恒真（本轮 ③）。收窄靠「限定到那一条 bullet」，不靠删内容或放宽断言。
2. **同一份数据被两道校验看，就要把两道都跑一遍**（插入器 + lint）。任何一道绿都不是另一道的替身。
3. **管道会吞 exit code**（`| tail` 使 claim 失败被读成成功）—— 本 BET 把这条列为 E3/⑤ 同族，自己差点又栽一次。
4. **并发交付时优先看内容而非文件身份**：#4625/#4627 同期改 `AGENTS.md`，我先跑内容等价检查再决定是否放弃本轮；
   结果是不同小节、可并存，于是按 blob 与 base-delta 两路各验一次（+8/−1、8 个标记、main 侧三条存活）。
5. **指认方式必须是不依赖本机状态的**：本 BET 六条的判据全部能在一个 `git worktree add --detach` 出来的干净检出里跑，
   这也是 operational 轴 `PROVEN` 的依据 —— 不是「我复述了一遍自己的文字」，是「换一棵树重跑还是那个读数」。
