# Retro — BET-Y2Q4-T10-350

## 1. 意图（intended）

journey-runner 对 5 张场景卡报 spec FileNotFoundError，而治理体系自带的
scene-journey-autogen 的 scan/generate/report 全报 0 missing——修复工具对真实
缺口全盲。本 BET 消除数据源分裂并根治 5 张 404 卡。

## 2. 实况（happened）

**根因两层（实测）**：
- 工具数据源分裂：autogen 的 SCENES_DIR/JOURNEYS_DIR 指向
  `.omo/_truth/{scenarios,journeys}/v3`（另一套注册表），与 runner 实际读的
  `docs/scene-cards + docs/journey-specs` 脱节；covered 判定读
  `runtime.journey_ref` 子字段——70/70 卡零使用（真实字段是顶层 journey_id，
  65 命中/5 404），fallback 命名从不匹配。
- 5 张 404：engineering-delivery→intent-to-evidence、family-asset-governance→
  family-financial-audit-workflow、knowledge-curation→capture-to-retrieval、
  research-deep-synthesis→research-deep-synthesis-workflow、health-gov-doc-cycle
  →自指。

**验证数字**：修复后 scan 对 docs 体系报 3 missing（与改挂 2 张后的实况精确
一致）→ generate 3/3 → scan 归零；runner 实测 5 张 404 全消（4 completed +
meeting-to-delivery 异步 paused 属设计）；新测试 5 passed；
journey-validate 全过；verify ok=True（3 checks + claim_coverage）。

**发现链方法论**：jsonl 落盘机制 → 异步/同步分型 → 404 名单 → 字段使用率
扫描（70/70 零使用）→ 目录常量比对——每步实测，未猜测。

## 3. 变更（changed）

- `bin/ssot/scene-journey-autogen.py`：目录常量对齐 docs/ 体系（旧
  .omo/_truth/v3 目录保留不删）；`_journey_ref()` 顶层 journey_id 优先
  （runtime.journey_ref 向后兼容）；generate_spec 同步。
- 2 张卡改挂：engineering-delivery-dogfood→meeting-to-delivery（spec 铁证
  引用）、knowledge-curation→knowledge-capture-pipeline。
- 3 张欠账 spec 程序化生成（research-deep-synthesis-workflow /
  family-financial-audit-workflow / health-gov-doc-cycle）——工具本职。
- `tests/test_scene_journey_autogen.py` 新增 5 用例。

## 4. 教训（lessons）

- 同域两套目录体系（.omo/_truth/v3 vs docs/）是工具失明的结构性根源——
  "工具修的数据源 ≠ 运行时读的数据源"这类分裂比单点 bug 更隐蔽，scan 的
  0 missing 会给出虚假的安全感。修工具先对齐数据源，再修判定。
- 主仓/worktree 的运行时文件（trial jsonl、system.yaml）差异会造成场景卡
  总检的环境性失真（worktree 0/70 vs 主仓 7/63）——跨环境比对 gate 结果
  必须先核对运行时数据面。
- trial 判定与卡字段解耦（jsonl 按 scene_id 匹配）意味着"跑对 journey"
  即可回填 trial——但异步型 journey 需真实消费者闭环，dry-run 推状态机
  不等于 completed，这是诚实边界而非缺陷。
