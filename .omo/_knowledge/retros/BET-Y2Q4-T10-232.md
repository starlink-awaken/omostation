# BET-Y2Q4-T10-232 retro — B1 残留收口：14 处 import 时冻结的写面常量改调用时刻解析

台账：`docs/plans/3y-bet-ledger.yaml` `BET-Y2Q4-T10-232`

交付：PR #4651 → squash `317bc0315`（root 仓，21 文件）；本 retro + evidence 回填走第二个 docs PR

## 1 intended — 本来打算做什么

把方案 `nimble-bay-asp.md:138` 那行字面判据真正做成真：

```
grep -rE "DEFAULT_(EVENT_)?LEDGER\s*=" bin/   →   0 命中
```

并把「为什么它 9 天没被发现有假」变成一条**能红**的门禁（AGENTS.md §7「扫源码的门禁必须自证」），
而不是再抄一次 0。范围由**度量**决定，不由变量名枚举决定：对 `bin/**/*.py` 做 AST 不动点扫描，
把模块级赋值中「值直接调用根 resolver」者及其传递依赖全部纳入 —— 读数 34，其中 14 处依赖 profile 根
（`event_ledger_path()` / `state_root()`），17 处依赖 code 根，3 处经传递归入 code 面。

## 2 happened — 实际发生了什么

14 处全部改为调用时刻解析（12 个文件），I1–I7 全部落为可执行断言（`tests/unit/test_b1_ledger_call_time.py`，
44 用例）。五件事与计划不同，且每件都改变了交付物：

1. **判据的第二段与被检对象不同源，是它自己的失效原因**。T10-203 的 verify-3 写的是
   `grep -rEn "^(DEFAULT_(EVENT_)?LEDGER|LEDGER|DEFAULT_DB) *=" bin/ | grep -c "event-ledger" || true`。
   第一段产出的行含 `event_ledger_path`（**下划线**），第二段过滤 `event-ledger`（**连字符**）⇒ 计数恒 0，
   `|| true` 再吃掉退出码。这条判据在**它自己交付的那一刻**起就失效，之后无论攒出多少冻结常量都是绿的，
   而 retro 把那个 0 当真值抄了一遍。本轮的反基线读数：**同一命令在 `origin/main` 上 6 命中、在本分支 0 命中**。
2. **改常量名会打断测试侧的 `setattr` 缝**。既有用例靠 `monkeypatch.setattr(module, "SYSTEM_YAML", tmp)` 换路径，
   常量改成 `_system_yaml()` 后当场 `AttributeError`。方案估「适配 1 个文件」，实测 **4** 个。
   同时我自己引入了一处 `NameError`：`omo-state-write-guard.py` 里残留一句 `SYSTEM_YAML.read_text(...)`，
   **且没有任何用例走到那一行**（命中它需要真正触发 ghost-declaration 分支）。系统性找法 = AST 比较
   「模块级被赋过值的大写名」与「函数体内 Load 的大写名」的差集，再逐项对 `origin/main` 复核去噪
   （`UTC` / `POC_SERVICES` 是 try 块与函数内 import，属预存）。
3. **落点判据差点被我写成文案断言**。第一次预测 `_check_ledger()` 返回 `(False, "ledger check failed")`，
   实跑是 `(True, "ledger ok")` —— **0 字节文件是合法的空 SQLite 库**。如果我当时改窄断言，就是把判据改到能过。
   正确形状是 monkeypatch `LedgerBroker.connect` 记录**实际被打开的路径**，断言它等于 import 之后才声明的
   `<tmp db>`。这条也顺手否证了「消息文案可以代表落点」这个默认假设。
4. **门禁「写完」不等于「有人跑」**。`tests/unit/**` 既不在 `governance-check.yml` 的显式 pytest 文件白名单，
   也不在 `verify-omo.sh`（只跑 `projects/omo` 与 `.omo/tests`）里 ⇒ 本地 42 passed 对 CI 是零证据。
   接线时又踩到 `on.pull_request.paths` 不含 `bin/**`：只改脚本的后续 PR 根本不会触发这个 workflow ——
   读到 `on.schedule: 0 */6 * * *` 才确认周期跑能兜住，这不是我推理出来的，是打开 workflow 看的结果。
5. **接线那一步当场抓到了门禁自己的 host 依赖**。PR #4651 首跑 `governance-verify` = **5 failed / 37 passed**，
   而本地和那个最小 venv 都 42 全绿。根因不是随机顺序也不是缺包：探测对 `repo_root.__all__` 里每个零参
   可调用对象都试调，`canonical_root()` 未声明 `OMOSTATION_ROOT` 时兜底 `~/Workspace`，runner 上没这个目录
   ⇒ `bin/lib/repo_root.py:80` 抛 `RuntimeError`。本地绿只是因为**这台机器恰好有规范检出**。
   用 `HOME=<空目录>` + `env -u OMOSTATION_ROOT` 在本地逐字重现了同 5 条红。
   处置没有选「给 CI 步骤加特例」也没有选「把 `canonical_root` 从探测里摘掉」（那两条都是把判据改到能过），
   而是探测两侧都钉 `OMOSTATION_ROOT=<被测检出>`（它按构造含 `MARKER`）⇒ 同值不入集合、profile 位移仍由
   sentinel 观测；并补两条用例：一条把「不依赖 host」钉成断言（变异对照：装回旧探测体 ⇒ 当场红，实测
   1 failed / 1 passed），一条把「钉住之后仍能认出 `canonical_root` 翻成写根」钉成断言（否则那条反向
   断言就是按构造就绿）。用例数 42 → 44。

## 4 lessons — 固化什么

1. **两段管道 = 两个契约，必须各自在真文本上命中一次**。合成违规样本要跑**全管道**，不是只跑第一段；
   否则「检测器命中了」与「判据报警了」是两件事，后者才是验收对象。
2. **`|| true` 在验收判据里等于删掉这条判据**。它把「装置坏了」和「没有违规」压成同一个读数。
3. **反基线读数（同一命令在未修复树上非 0）是每个源码门禁的必要组成**。只有 0 的绿无法区分「修好了」与「没在看」。
4. **改名/改形状会破坏别处的隐式依赖**：`setattr` 缝、`from x import a as b` 别名、跨模块属性读者。
   判据不是「有没有报错」，而是「差集里每一项我都能解释」。
5. **落点断言要断被打开的路径/被写的文件本身，不断文案**。文案断言会在下一个合法空态（0 字节库）上反转。
6. **门禁要问三件事：谁能红、谁在跑、跑的环境有多窄**。第三件是**两个**面：依赖面用最小 venv 复刻，
   **host 面用 `HOME=<空目录>` + `env -u OMOSTATION_ROOT` 复刻** —— 本轮 §2-5 正是后者，只复刻前者会漏。
7. **「本地绿 / CI 红」的第一处置是问「判据依赖了这台机器的什么」**，而不是问「CI 哪里特殊」。
   一旦答成「给 CI 加特例」或「把那一项从探测里摘掉」，判据就从测性质变成了测我的机器；
   正确形状是让装置在被测检出自洽（`OMOSTATION_ROOT=<被测检出>`，它按构造含 `MARKER`），
   再补一条变异对照证明自洽没有把探测变哑。
8. **判据的尺也要写明**：我用 `git grep -E "DEFAULT_(EVENT_)?LEDGER\s*=" origin/main -- bin` 反查基线时读数是 **0**，
   差点据此写下「反基线不成立」。实际用 `/usr/bin/grep -rE` 扫 `git archive` 出来的同一棵树是 **6** ——
   git 的 ERE 引擎不认 `\s`。⇒ 同一条判据在两个装置下一个是恒绿的。本轮把它写进 §7-⑦：
   反基线读数必须在判据指定的那把尺上复算，判据一律用 `[[:space:]]` 而不是 `\s`。
9. **BET 号是共享命名空间里的抢占锁，不是"我起个名字"**。空号在我建条目与 squash 之间会被并发 agent 占用，
   而**对方可能已经把同号跑到 `done`**。⇒ 台账类交付在 merge 前的最后一步必须重查一次
   `git show origin/main:<ledger>` 的 id 唯一性；撞了就走 §3.6 改号配方，**改自己的、不改别人的**。
   改号会连带动 `content_digest`（spec 里也有 bet_id）与 retro 文件名 —— 这三样是一组，漏一样就是
   `SPEC_BINDING_REQUIRED` 或 `COMPLETION_FILE_DIGEST_MISMATCH`。
10. **merge-ref 只认 synchronize 事件**。`mergeable=MERGEABLE` 但 `gh pr checks` 为 0，不等于 CI 放过；
    解冲突之后仍需一次真实 push（空提交即可）才让 GitHub 重算并排队。判据顺序照 §7-④，只是多一档：
    `CONFLICTING/DIRTY` → `MERGEABLE + 0 checks` → synchronize → checks 排队。
11. **后台任务的 "exit code 0" 是包装器的，不是被包装命令的**。`make gac-local-gate &> log` 之后
    通知报 exit 0，而 `make` 自己 `Error 1`（通知来自最后一条 `tail`）。⇒ 凡在后台跑门禁，
    必须把真实码落进日志（`echo "EXIT=$?" >> log`）再读日志判定。
