# Retro — BET-Y2Q4-T10-288 第四类根准入

读数 base：工程腿 `origin/main = c3a93e9cc1c583f0083b5da302f9f9922645d4b2`（PR #5070 squash，
2026-11-06T03:57:56Z）；spec § 装置 base = `3a1c0770290a5d2a1ddbd896fb3f9de358ecbc90`。
两把尺 `tests/unit/test_resident_write_plane_split.py`（A）与 `tests/unit/test_writeplane_root_pin.py`（B）。

## 1. 本意（intended）

ADR-0456 把根收敛成 code / state / install 三把，隐含前提是「路径字面量总要挂在一个已解析根上」。
本条 BET 处理**第四类落点**：`Path(".omo")` 这类不挂任何根的相对锚 —— 落点随进程 CWD，且它连 profile
都不读，声明与否不影响它。两把根尺按构造看不见它：A 靠 `parents[` / `__file__` 认检出、靠 anchor 变量归类，
相对锚**没有 anchor**；B 只统计已登记 resolver 的站点，于是「不在登记里」被读成「合规」。
所以要做的是**类目补齐**（不是补登记），并处置两处确证站点：`projects/omo/src/omo/workflow/lock_graph.py`
（死写面 + 活读者）与 `bin/notification.py`（env 默认值即默认生效）。

  `call`（单 `Path()` / `os.path.join()` 带仓内相对默认，含 `Path(os.environ.get(NAME, "<相对默认>"))`）。
  A **31 passed** / B **12 passed**（合计 43 件）。
- 跨尺**同源对拍**：`b_keys ⊆ a_keys` 且差额恰等于显式集合 `RULER_B_MARKER_BLIND`

  从散文变成断言 —— 两把尺再也不是两份互不相干的名单。
- 基线登记由 8 项收敛为 **6 项**（`notification` 两处被处置后从 `scan_cwd_relative_sites` 消失）；
  变异对照按 `shapes` 开关分别记：摘 `chain` ⇒ 该形读数归零，摘 `call` ⇒ `_REL_B_CALL` 用例当场红。

  `code_root()` 解析，并加了正向落点断言（`CWD=/tmp` 下解析到检出那份配置且 `load_config()` 读到 5 个键）。
  `lock_graph` 显式降级并登记，**不删代码**（删代码需另行授权）。

## 4. 教训（lessons）

1. **变异装置本身会假绿，且失败形态是「全绿」**。第一次给 B 造变异对照时，脚本「在 `def` 后第一行插桩」
   实际插进了 docstring 内部 —— 12 passed 全绿，看起来像「断言不承重」，其实是桩根本没进函数体。
   改用 `ast` 取 docstring 的 `end_lineno`、在其后插桩 ⇒ **3 failed / 9 passed**（真实读数）。
   这是 AGENTS.md §7「扫源码的门禁必须自证」③「按构造就绿」的**新面**：先前只教人怀疑被测对象，
   本轮证明**变异对照的插入点也要自证**（判据：变异跑出全绿时，先回读改动后的那几行字节）。
2. **台账 `verify[].cmd` 也是一种尺，它自己会失效**。`verify[0]` 原样照抄的 hermetic 命令缺
   `--with pytest-timeout`，而本仓 `pyproject.toml:47` 的 `addopts` 写死 `--timeout=300 --timeout-method=signal`
   ⇒ pytest 当场 rc=4 `unrecognized arguments`。验收判据**不可执行**时，「跑通了 verify」这个说法是空的。
   已订正为含 `pytest-timeout` 的装置，并把完整可跑命令写进收据。
3. **「先写结论后测量」在两份文档里各复发一次**：PR body 说生产者 `bin/hitl-proposal.py`「仍在 `LOCAL_ROOT`
   上取默认」（实际是 `:30` 的模块常量，且名字不是 `LOCAL_ROOT`）、ADR addendum 引用 `:32`（陈旧行号）。
   两处都由复测否证后订正（`efc62e4b7` + `gh pr edit`）。纪律仍是 §7⑥：**优先写符号名，行号只作辅助**，
   落笔前用 `git show origin/main:<path>` 取该行内容核一遍。
4. **A2A 碰撞谓词只看 `status`，不看锁 TTL**：`claim` 被他人 run
   `20261104T115230Z-project-code-change-d825f60f`（BET-Y2Q4-T10-285，`claude-lead`）挡在
   `docs/plans/3y-bet-ledger.yaml` 上；实测该台账仍 `in_progress`、零 open PR、心跳停在 2026-11-04T11:54:48Z。
   按既有纪律**不 `prune-locks`、不替并发 agent 清活锁**，选择未 claim 直接交付并把原因写进 closeout evidence。
   这是本 BET 之外的一条待立案缺陷（谓词应看锁的 `expires_at`），已在「未闭合」点名。

## 5. 未闭合（具名三条）

- `bin/hitl-proposal.py:30` 的 `PROPOSALS_DIR`（HITL 提案面**生产者**）仍随 CWD 且 import 时冻结。
  消费者已 fail-closed，所以现状是「未声明即拒写」而不是读写分叉；但一旦只给消费侧声明 env，两半会落到
  不同目录 ⇒ **两半必须同一次交付改**，生产者不在本轮单独动。
- 尺 B 的 `pinned` 谓词结构性不认 `code_root()`（tip 实测未被 `__file__` 归类而字面量命中 marker 的
  `/`-链 **188 处**）。本轮**不扩这把尺**：扩它会让 spec §4 记下的基线读数不可复算，与 done_when[2] 直接冲突。
  扩展必须连带重算 spec §4 全部读数并另立 BET。
- A2A surface-lock 的碰撞谓词不看锁 TTL（见 §4.4），本轮实测两次（另一次在 28h 前心跳、`expires_at`
  已过期 13h 的 run 上）。待另立 BET，判据应为「`status` 活跃**且**锁未过期」。

价值轴 NOT_PROVEN：本条消除的是 ADR-0456 根契约的第四类盲区（落点随进程 CWD 且两把尺按构造看不见），
收益面在门禁可见性而不是业务指标；`value_indicator_policy` 显式 false，与同族 281/282/284 同判。
