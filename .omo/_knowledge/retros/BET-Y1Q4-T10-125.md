# Retro: BET-Y1Q4-T10-125 — Resident BOS 双向任务网关与异步队列调度中枢

常驻 agent 体系 (`omo-resident`, ADR-0396) 已有 4 个只读 BOS URI (status/roles/daemon/decision)。
本 BET 在 BOS 端、router 端、daemon 端三处贯通，新增 4 个 task_gateway 端点 + 持久化任务队列 + daemon tick 派发循环。

## What was learned

- **`isolation_level=None` + `BEGIN IMMEDIATE`** 是 SQLite Python 写锁的标准范式 — 多 daemon worker 并发派发同一任务问题靠它根治
- **状态转换合法性表 `_ALLOWED`** 把"严格单向状态机"从注释升级为代码可执行约束
- **`status_override` + `attempts_override`** 参数解决"事务内 UPDATE 后返回旧 row"问题
- **commit `git checkout -- file`** 会丢未提交改动 — 教训: 在重置 submodule 前先备份已编辑文件

## What to improve

- daemon hook 只注册了 2 个 URI (sediment/decision trigger), 未来 sediment/decision 真实落盘逻辑需扩展
- task_queue 暂不支持优先级队列 (FIFO only) — 高优任务可能饥饿
- retry delay: 当前是立即重试, 真实场景应加 exponential backoff
- 单 daemon 进程派发, 多 daemon 协作场景未测 (假设并行多 daemon 各自 poll 不同 projector)
