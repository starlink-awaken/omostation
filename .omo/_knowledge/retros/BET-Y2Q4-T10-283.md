# Retro — BET-Y2Q4-T10-283 43195 注册进端口表 + resident-web 记录订正

## 本意

ADR-0456 分期表 B2 行的验收原文里有一条「未注册端口 0」。这条判据在台账上被写成已完成状态已有
若干轮，但**从未在同一把尺下复算过** —— 本轮做的是它的第一次真实测量，并把测出来的缺口各自归位：

1. 复算口径：本仓自有服务里，实际在听但 `protocols/port-registry.yaml` 未声明的端口有几个；
2. 把测出的反例注册进端口表，并钉成一个**结构口径**的可复算用例（不是「文件里有这串字」）；
3. 顺带处理扫描时发现的那条注册记录自身的错。

范围限定：注册 + 记录订正 + 钉子。不动 `resident-web` 的代码默认端口、不改任何 plist、
不替 principal 挂上 E6/E7 两个准入开关。

## 实际发生

复算读数（同一份监听扫描，收口腿在 `039e58836` 复跑）：`lsof -nP -iTCP -sTCP:LISTEN` 共 42 个
监听站点，其中 argv 引用本仓检出根或安装位的自有站点 5 个 —— `[4000, 8766, 9290, 43195, 43910]`；
端口表数字键合并两侧（`protocols/` + `projects/ecos/`）改前 57、改后 58。于是
`自有 ∧ 未注册` 从 `[43195]` 变 `[]`，非自有站点在同一次扫描里两侧都是 37、未因本次改动变化。
所以 ADR-0456 那句「未注册端口 0」在改前是**假**的，改后才成立 —— 这条从「声明」变成「实测」。

但这个「0」在**接线到 CI 的那把尺**上是读不出来的：`bin/ssot/check-hardcoded-ports.py` 的
`unregistered` 改前改后都读 0，`43195` 作为 hardcoded 站点读数是 0 次。逐条看它的
`PORT_PATTERNS`（`:59-67`）才定性 —— 五条正则里没有一条能匹配 `def cmd_web(port: int = 43195, …)`
（类型注解把 `port:` 与数字隔开）或 `default=43195`。也就是说 plan:139 那句判据在这把尺上一直是
**空真**；本轮的 1→0 靠的是监听面扫描，不是它。尺的缺陷另案立案（任务 #179），不在本 BET 里
顺手扩范围修 —— 修一把尺等于换一批历史读数，那是另一条 BET 的责任。

反例的成因是双面的：`projects/omo/src/omo/resident/interact.py:1060`/`:1550` 把 43195 写成
字面默认值（无 env 覆盖面），而端口表从未登记它。注册动作只解决后一半；前一半留在代码里，
spec §5 显式写明这是**已登记的存量**，不是本轮交付。

扫描同时暴露了另一处更安静的错：`.omo/_truth/registry/services.yaml` 的 `omostation.resident-web`
条目仍记着检出根与一份陈旧 `content_digest`，而它的实盘 plist 早在 2026-10-28 已切到安装位。
逐字读到 `bin/mof/gen-service-configs.py:211` 才定性：**没有任何代码读这个 digest**（该脚本对
`generate: false` 的条目跳过生成校验）。也就是说这条记录错了不会有任何东西变红 —— 本轮把它
改回真（`runtime_root: install`、载荷根订正、digest 由实盘文件重算），并把「无读者」这条边界
同时写进条目 `provenance:` 和 spec §6，不让它被读成「门禁被修复了」。

钉子用例按 YAML **数字 mapping 键**计数，配两条反证：合成 YAML 里注释形态的 `# 43195` 和字符串
键 `'43195 '` 都不进声明集。第三条断言（声明 `install` 的条目载荷里不得残留检出根字面量）在
worktree 里遇到测量装置问题：`canonical_root()` 对本检出会 raise（无 MARKER）。判据是**显式
skip 而不是退回 `code_root()`** —— 退回去会让断言在错误的对象上变绿。为证明它不是空转，另测
76 条 launchd 条目中确有 14 条携带检出根字面量，而声明 `install` 的 28 条与之交集为空。

首轮 CI 两处红，都是本 PR 引入：① `tests/unit/test_gen_service_runtime_root.py:130` 把「声明
运行根的条目数」写成字面量 27，与它自己的封闭集是同一事实的两份副本，加一条必红；② spec 缺
surface 要求的 `owner` 键，而 `missing_frontmatter:accepted-specifications` 这一桶**没有例外预算**，
于是 warning 直接判 error。②的本地首轮之所以没看见，是我把检查输出 `head -10` 截断了 ——
测量被自己掐掉了前半段。

收口腿自己也被同一把尺量了一次，这次是**我自己的写法错**。初稿按前几轮 retro 的样式写了

## 教训（可复用判据）

1. **封闭集 + 字面量条数是同一事实的两份副本**，任何新增成员必红。条数断言应写成
   `len(实测) == len(封闭集)`，但要说清它仍在抓什么（同 label 重复行会被 set 合并而溜过集合相等）——
   否则下次有人把它当冗余删掉。
2. **registry 声明的 required_frontmatter 要逐键对照，不要抄邻近文件的键序**。缺一个不在你注意
   范围内的键（`owner`），落在**无例外预算的桶**里就是 error 而非 warning。判据：先读
   `document-governance.yaml` 里该 surface 的 `required_frontmatter`，再写 frontmatter。
3. **截断自己检查命令的输出 = 亲手关掉一半测量**。`... | head -10` 让首轮本地跑得「绿」。
   门禁类输出要么全读，要么落盘再 `rg` 关键字。本轮 `lsof -F` 的 `tail -18` 又复发一次：
   43195 就在被截掉的前段里。
4. **「没有读者」不等于「不会漂」**：记录与自己声明的根不同侧、且没有任何测试会红，是本轮真实
   发现的形状。判据是把记录的 `program` 与安装位/检出根做**同侧比较**，而不是相信它带了一个
   digest 字段就受摘要保护。
5. **正证要配反证同批写**：数字键口径若不配一条「注释/字符串键不算声明」的反证，断言就退化成
   「文件里有这串字」，而后者对任何后续改动都永远为真。
6. **测量装置不可判定时显式 skip，不降级**：`canonical_root()` 在 worktree 里 raise 是环境事实，
   退回 `code_root()` 会让断言在错误对象上取得假绿；skip 配上「本机无从判定」的措辞，
   再用一次独立实测（14 条携带者、交集为空）证明它不是永久空转。
7. **判据成立 ≠ 尺看得见**：同一句「未注册端口 0」，监听扫描读出 1→0，接线 CI 的源码尺两侧都读
   0。交付前必须问「这条判据由哪把尺担保」，并把它读不到的形状立案 —— 否则「已达标」只是换了
   一个观测面重述愿望。
8. **packet 是契约绑定，不是缓存**：`start` 之后对 spec/ledger 投影的合法演进会冻结该 run 的
   `claim` 能力，且 `refresh-packet` 只允许 ledger/spec 与 `origin/main` 逐字一致且绑定未变时重绑。
   由此得一条执行纪律：`write_surfaces`（含 retro/receipt）必须在 `start` 前写全，spec 字节变更
   要与 `content_digest` 重绑同批落，收口腿用补全后的投影另起 run。
9. **被 warning baseline 吸收的仍然是错**：`completed/journal` 这对值不挡 CI，于是我从上一轮 retro
   一路抄了四轮，把同一份债乘成 4 份。判据不是「这次跑绿了吗」，而是两条：读 surface 的
   **允许值集合**（不只 required 键），以及用 `--strict --files <自己的文件>` 单点复算 ——
   全量口径把 45 条 warning 平均成「PASS」，单点口径才会把自己的写法暴露成 outlier。
