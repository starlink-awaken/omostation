# BET-Y1Q3-T10-19 复盘

## 北极星

decision 角色每 2min 写提案（evolution-proposals 已积累 3945 个 JSON）但只写不消化——无采纳→执行→验证状态机，proposal-to-adr 手动不在 cron，north_star 纯 value 投影不读知识消费。本 BET 把决策提案从「只写不消化」变为「可采纳→可执行→可验证」闭环，并在北极星中可见知识消费水位。

## 做了什么

- **主仓 PR #2286 MERGED (39a6db62)**: `bin/ssot/proposal-to-adr.py` 提案状态机——status 字段（new/drafted/adopted/executed/verified）+ `--mark-status`（枚举+迁移校验）+ `--dry-run --json` 报告 status_counts；`convert()` 处理最新 new proposal → ADR 草稿标记 drafted（不自动采纳）
- **north_star 知识消费轴**: `north_star_meter_v2.py` 输出增 `knowledge_consumption`（proposal_total/adoption_rate/retro_referenced），纯投影不改 value 轴判定
- **cron 自动化**: install-resident-cron.sh 增 CRON_PROPOSAL_ADR（每天 01:00）
- **测试**: tests/unit/test_proposal_to_adr_status.py 7 用例覆盖状态机迁移 + 知识轴输出，ci-local-fast 57 ALL GREEN（B 预检无 pre-existing 残留）

## 没做什么

- 不自动采纳/执行提案（人工/运营 agent 兜底，ADR 采纳是 human gate）
- 不改 decision.py 提案写入 schema（仅增 status 字段兼容读取）
- 不改 north_star 现有 value 轴判定 / 不重算历史快照
- 不引入 LLM 自动撰写 ADR 决策内容

## 教训

- **连字符文件名模块无法 import**: proposal-to-adr.py 含连字符不能直接 import，测试须 `importlib.util.spec_from_file_location` 按路径加载
- **测试 mock 文件名须匹配 proposal-*.json pattern**: 否则 convert() 找不到提案静默通过，断言失效
- **closeout verify 与主仓 PR 合流解耦**: closeout ok（run 20260826T132250Z-project-code-change-6cbb5114）先于 PR 合并可执行，合并后 evidence 落位即闭环
