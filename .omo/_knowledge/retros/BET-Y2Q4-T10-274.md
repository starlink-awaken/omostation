## 4. lessons（可迁移的）

1. **「两次读数不同，先疑基线」有一条更强的同族**：动的可以不是数据、也不是检查脚本的 base，而是
   **检查脚本所加载的 kernel 来自哪棵树**。问 `omo.workflow.core.__file__` 比问 `git rev-parse HEAD` 更根本。
2. **同名常量的第二次绑定是把语义交给导入路径**：`parents[N]` 类反推根在「脚本自己」上尚可读，
   一旦值来自别的包，它就不再表示执行检出。判据要写成「读哪棵树」而不是「读哪个根」。
3. **否证的候选项不得登记**：「AGENTS.md 幽灵路径 `bin/gac/doc-governance-check.py`」是我自己的笔误
   （本文件引裸文件名，真实脚本在 `bin/ssot/`）——把自身笔误写成仓库缺陷即伪造溯源，本轮显式拒绝并留否证读数。
4. **「装置跑过」不等于「交付发生过」，这条本轮咬到我自己的记录上**：run
   `20261027T055325Z-…-a20aa965` 于 `06:05:25Z` 闭合 `status: ok`，而本腿 PR 到 `08:43:29Z` 才创建，
   闭合时 `evidence:` 里那条串属于**上一条 BET（#4919 / T10-272）**。
   判据：`close` 的 `evidence` 是 `extend`（`lifecycle.py:1550-1551`）而非覆写，
   一条错串会长期留在记录里且没有任何读者会红 —— 所以**闭合动作必须发生在交付动作之后**，
   而不是「先关掉再说，反正链判据绿」。这与本 BET 的主命题（尺读错了树却报得理直气壮）同形。
5. **单 PR 交付下 `merged_reachable_commit` 写不出真值**：该字段记录的是「本条交付落在 main 的哪个 commit」，
   而单 PR 路径写字段时那个 commit 还不存在。实测 origin/main 上 T10-270/271/273 三条该字段**全部**是
   main 上的真实 commit（ancestor 判定均 YES），所以正解不是接受 WARN 了事，而是**合并后补一次
   只改该单字段的订正**，并按 AGENTS.md §7（T10-267）的字段路径枚举去同步其余摘要位 ——
   排除法替换会连带改掉 `content_digest`，那一位绝不能动。
6. **`tail -N` 之后的读数只能当样本，不能当总数**（本轮第二腿自伤，已检出并改写）：
   我把 `bet-ledger lint` 的 `… not ancestor of origin/main` WARN 写成「其他 7 条」，
   依据是同一次管道末尾的 `tail -8` 里正好数出 7 行 —— 全量 `grep -c` 复算真实读数是 **27**。
   这不是笔误级错误，而是**判据级**：那一句是用来支撑「零命中是逐条结果、不是尺失效」的对照量，
   写错就变成用一个被截断的读数去论证另一个读数的意义。
   **纪律**：任何以「数量」为断言的读数，取值命令必须本身只产数量（`grep -c` / `wc -l`），
   不得经过 `head`/`tail` 这类**可视截断**再人肉计数；需要看样例时把「计数」和「看样例」分成两条命令。
   与本 BET 主命题同源：**输出的形状不构成输出的完整性**。
7. **自指摘要不可落在正文里 —— 它按构造就为假**：台账有 6 个证据位指向本 receipt 文件，
   而这 6 位的值由该文件字节决定。我在 receipt §7 写下「本次实测 `a21df239…`」的那一刻它是真的，
   下一次编辑该文件时它就**必然**为假 —— 不是写错，是这个句式不可满足（比 lesson 6 更硬：
   那条只是读数口径错，这条是**任何一次修订都注定让它失效**）。
   **判据**：`grep -cE '[0-9a-f]{64}' <跟踪文档>` 应为 **0**。
   **纪律**：自指对象的摘要只由**外部**按磁盘字节重算（写回脚本即是），正文只写定位方式与断言；
   固化「重算纪律」的句子本身不得携带重算结果。
8. **重跑时「恰好 N 行」类断言会自己变假 —— 修断言形状，不修数字**：写回脚本第二次运行时
   `POST-WRITE ASSERTION FAILED: lines changed inside block = 7, expected 8`。
   语义断言（6 receipt 位 == 磁盘、1 retro 位 == 磁盘、无第三种值、`content_digest` == spec 字节、
   `ref` == squash）**全部通过**，失败的那条只是把「首次运行时 ref 位也需要改」写成了常量 8；
   幂等重跑时 ref 位已到位 ⇒ 真实变更行就是 7。
   **纪律**：改动量的断言必须写成**集合包含**（变更行 ⊆ 意图槽位集合）而不是**基数相等**；
   基数相等只在「首次且唯一一次」成立，而重跑是这个流程的常态。
   这与本 BET 主命题同族：**把一次运行的读数当契约内容**，换一次运行就为假。
9. **「目录空」不是判据，「index 全量 `D ` 且 HEAD==pin」才是 —— 后者决定了复原命令不是 `submodule update`**：
   本 worktree 五个子模块被并发守卫清空后，`git submodule update --init <path>` **静默 no-op**
   （它见 HEAD 已等于 gitlink 就认为无事可做），把「我修过了」和「什么都没发生」做成同一份输出。
   真判据：`git -C <sub> status --porcelain` 全量为 `D `、无其他条目、`HEAD == 父仓 pin`
   ⇒ 内容只在 index 里被抹掉，`git checkout HEAD -- .` 才复原。
   **反向纪律**：`HEAD != pin` 的两个（`l4-kernel` / `omlxc`）**不能**用同一条命令 —— 那会还原成父仓
   未记录的 commit，等于伪造子模块图；这一类要走 `submodule update` 切 pin，与本条是两种病。
10. **门禁的 shell rc 与它的承重面不是同一个量**：`make gac-local-gate` rc=2 而
    `gac-local-gate.py --json` 在同一状态下 `ok=true / hard_fails=0 / rc=0`，差的那条是
    `test-mcp-kos` exit **78**（脚本自己写明「skipped, **not passed**」）。
    只读 rc 会把「一条本机产物缺失的跳过」读成「门禁失败」，只读 ok 又会把「跳过」读成「通过」。
    **纪律**：判门禁必读 `--json` 的 `hard_fails` 列表 + 每条的 `skipped`，rc 只当导航。
