# BET-Y2Q4-T10-217 retro

四问结构。receipt：`docs/reports/2026-10-01-bet-217-root-side-writers-state-root-closeout.md`。

## 1 intended — 本来打算做什么

把 ADR-0456 双根契约在 `bin/` 侧收尾：四个仍在用 `__file__` 反推根或读私有仓根 env 的模块
（`evidence-smoke.py`、`task-inventory.py`、`generate-brief.py`、`generate-docs-index.py`）
接进 `code_root()` / `runtime_state_root()`，让**自己的产物**在声明 profile 时落到 state root，
并消灭 `OMOSTATION_WORKSPACE_ROOT` / `OMO_WORKSPACE_ROOT` / `WORKSPACE_ROOT` 三个脚本侧私有别名。
Appetite 0.5 day，交付形态 = 4 模块 + 2 测试 + 台账 + accepted spec。

## 2 happened — 实际发生了什么

交付本身按 shape 走完（PR #4591 squash `ff6e45a74`，CI 22 pass，6 条 verify 全 exit 0，
L3 review 0 findings）。真正改变判断的是三件事：

**(a) 一条规则压住了整轮的形状。** 原计划"顺手把读者也改挂 state root"。起草判据时发现
`task-inventory.py:36 REGISTRY` 与 `evidence-smoke.py:111-112` 两个 jsonl 若跟着写者一起走，
读者会指向另一棵树，而**没有任何测试会红** —— 这类回归在双根下是静默的。于是把
"写者可独走、读者须随写者"写成 spec §0.5，并让每条 MOVED 断言配一条 KEPT 断言。
复跑读数：MOVED 恰 4、KEPT 恰 7；四项 KEPT 各有实测理由（两个 jsonl 仍被 git 跟踪；
`REGISTRY` 全仓零写者；`BRIEF_MD` 是跟踪的人类读物；三处 `WORKSPACE` 是读面归 code root）。
最终形态因此不是"四个模块改根"，而是"四个模块里**属于它们自己的产物**改根"。

**(b) `task-inventory` 的整条数据面是空的。** 我给它两个产物（`SNAP_DIR`、`DRIFTS`）改了根，
然后顺手量了一条"这条链在跑吗"：`crontab.new:90` 声明每天 09:35，`crontab -l | grep -c task-inventory`
= **0**（未安装）；`runtime/task-inventory/` 无 `snapshots/` 也无 `drifts.jsonl`；它读的
`.omo/state/task-registry.yaml` untracked、全仓无写者、且在 `~/Workspace` 与两个 state root 下
都不存在；`load_registry()`（`:61-69`）用 `except Exception` 把缺文件压成 `[]` 后继续。
⇒ 改根在结构上对，但今天零运行流量；G8（morning-brief 注册在案从未安装）那类缺陷第二次复发，
而且这次连输入文件都不存在。

**(c) 回填撞在自家协调面上。** 首轮 run 的 `claim` 报 `WORK_PACKET_SCOPE_MISMATCH`：packet 的
`write_surfaces` **由台账条目派生**，而 T10-217 当初只登记代码面，report 与 retro 从未在内。
补两行进台账后另起 run；紧接着 `claim` 台账又被交付 run 的在活锁挡住
（`A2A Path Lock Collision … in run 20260930T131106Z-…`）—— 锁跨 worktree 可见，
这是"协调面全机共享"的第三次独立实证。去 `closeout` 交付 run 释放锁，它又报 `missing_retro`。
三件事咬成一个环：**retro 必须先落盘 → 才能 closeout 交付 run 放锁 → 才能 claim 台账改 status**。

## 3 changed — 交付形态因此变了什么

1. 台账 `write_surfaces` 追加 report 与 retro 两行（照 T10-216 先例），代价是这一轮的 packet
   与首轮 run 作废、另起 `20261001T005127Z-project-doc-change-6a707287`；`verify` 参与 packet
   哈希，所以"改旧 run"不可行。
2. `verify` 从缺字段（`lint` 直接 `ERROR … 缺字段 verify`）补成 6 条真判据，其中第 3 条
   （HEAD vs `origin/main` 常量字节等式）取代了"应该没影响"这类叙述，同时充当回滚判据；
   第 5 条把生成态污染（hook 重写 `system.yaml` 的 `health_score_evidence_generated_at`）永久挡住。
3. 一次 `gac-local-gate` 的 `mixed lanes` FAIL 把交付切成 3 个 commit —— `bin/change-lane-check.py`
   里 `code` 与任何 lane 不同乘，拆法由这张表决定，不是凭印象。
4. §4 三件未闭合项（task-inventory 空数据面、`agent-presence` 准入清单互斥、
   jsonl/生成态 cohort）从"本轮顺手做完"改成**带读数的另立**。

## 4 lessons — 下次直接可用的判据

- **双根下改任何读面前，先问"它的写者已经改挂了吗"。** 没改就跟着走 = 静默读旧数据，测试不会红。
  落法：每条 moved 断言旁边写一条 kept 断言，让"只翻一半"这件事自己报错。
- **开 BET 时就把 report + retro 写进 `write_surfaces`。** packet scope 由台账派生、packet 哈希含
  `verify`，事后补登记会让首轮 run 作废并多开一次 run。
- **closeout 与 retro 的真实顺序是 retro 在前**，即使 retro 记的是交付轮；交付 run 的路径锁
  跨 worktree 挡住回填 run，先 `closeout` 放锁才能 claim 台账。
- **给一个写面改根之前，先测它有没有在跑**：`crontab -l | /usr/bin/grep -c <name>`、
  产物目录是否存在且有非空 mtime、输入文件是否真的存在。"结构上该搬"与"这条链是活的"是两次测量。
- **判据文本本身也有实现陷阱**：`P` 只能装纯 python 程序（再包一层 `python3 -c` 就是
  `SyntaxError`）；`- id:` 起始块 `yaml.safe_load` 返回 list（要 `[0]`）；最后一个 bet 的条目边界
  是第一个 column-0 行（`campaigns:`），按"下一个 `- id:`"切片会把顶层键吃进来；
  zsh 下命令替换要引号包住。
- **grep 类判据要区分 env 读方与字面量方**：`bin/gac/meta-doctor.py:50` 是把别名当**正则字面量**、
  `bin/gac/documents-*.py` 是配置键**写方**，裸串 grep 会把它们算成幸存者而假红。
