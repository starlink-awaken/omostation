## 4. 教训（lessons）

1. **「台账声明的交付面 ≠ 已发生的交付」，而且过期前提会一直当真值活着。**
   证据：规格 `last-reviewed: 2026-11-02` 比 discovery 晚三天，仍写着 Windows 11 Pro；台账阻断段与
   `reports/` 零交付物同时存在。判据：接一个"被标记 blocked"的 BET 前，先实测它 blocked 的那句话，
   不要复用文字结论——本轮一次实测就推翻了一个维持 8 天的阻断理由。
2. **改 Markdown frontmatter 不能用 `split("---")`。**
   正文里的表格分隔行 `|---|---|` 含 `---`，`t.split("---")[2]` 会把文件在**第一张表格处截断**；
   实测两个文件分别从 186 / 117 行掉到 35 / 20 行，而脚本自己的"替换成功"断言照常打印，
   `git status` 也毫无异常。纪律：按**第一个 `\n---\n` 边界**取 frontmatter（`index` 而非 `split`），
   并在写完立刻做**行数或字节数对拍**（本轮靠 `wc -l` 才发现，代价是重做两份）。
   与 AGENTS.md §7「不许写半份镜像」「目录缺席 ≡ 目录为空」同族：能改变判定面的都是**兜底/切分**的写法。
3. **public 仓入库前要有脱敏这一道。**
   本仓 `visibility: public`（`gh api repos/starlink-awaken/omostation --jq .visibility` 实测）。
   机器事实里天然带主机标识：全局 IPv6、machine-id、私钥文件名、未登记过的 peer 主机名。
   判据不是"有没有泄密"而是"是否新增了仓内从未出现过的可定位标识"——本轮按此逐个核对，
   私有网段 IP 因**仓内已有同类先例**（`192.168.31.210` 等 16 处、`100.99.210.78` 等）予以保留。
4. **引用行号前逐行回读，否则文档自己会变陈旧。**
   §5 的 20 余处 `file:line` 全部做了逐行内容校验，抓到两处错：`orchestration_contract.py` 漏了
   `projects/omo/src/omo/` 前缀，且 `:44`/`:94` 不是契约位点（真位点是 `:84` `OrchestratorAdapter`）；
   `bin/harness` 的"8 阶段 DAG"在 `:3` 不是 `:2`。这与 AGENTS.md §7⑥「行号指针会随上一轮交付漂移」同源。
5. **浅 init 的子模块 index 会被清空成"整份 staged `D`"，`git submodule foreach` 在 worktree 里探不到它们。**
   实测 12/16 子模块命中，`git -C <sub> rev-parse --show-toplevel` 仍返回子模块路径（已 init），
   所以这是 §7 ⑤ 的父仓盲区形状而不是未初始化。修复要**先比 head 与 pin**：head==pin 的 9 个用
   `restore --source=HEAD --staged --worktree` 就够，head≠pin 的 3 个（agora / cockpit / aetherforge）
   必须 `git checkout <pin>`（浅仓缺 pin 对象时先 `fetch --unshallow origin main`）——只 restore 会把
   工作树恢复到一个不是 pin 的 commit 上，根仓继续报 ` M`。
