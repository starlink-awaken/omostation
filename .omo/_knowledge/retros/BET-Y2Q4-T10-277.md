## 3. 改变了什么认知（教训）

1. **「修完 N 站表」不等于「修完 N 类形状」。** 一张按行号写的站点表天然按位置分类，而缺陷按**表达式形状**分类。同一根因在 omo 侧还剩两种表外形状，其中一种（`relative_to`）连尺都打不到。判据：收尾时问「这把尺的匹配规则覆盖几种形状」，而不是「表上还有几行没改」。
2. **反基线必须与改后由同一次扫描产出**（AGENTS.md §7⑤ 再证一次）：`git archive a8709b9 src/omo` 造对照树跑同一把尺得 pre=5，同一脚本得 post=0。只报 post=0 时，「少认一种形状」和「多认一处合法」都能凑出绿。
3. **浅历史 clone 让 `git show --stat <squash>` 变成陷阱**：omo 侧 `is-shallow-repository=true`，那条命令把整棵树报成 1253 files / 239109 insertions，看着像「PR 里混进了巨量文件」——包括一份 `.claude/skills/**`。在深 worktree 里复核真实内容是 3 个文件。**判据**：核对 PR 内容用深检出（或 `gh pr view --json files`），不用浅 clone 的 `--stat`；浅树里 `HEAD~1` 直接 `unknown revision`。
4. **写回台账摘要/路径时，「排除法」是危险形状**：本轮订正的是三处陈旧**路径**指针，靠按字段路径定位（`write_surfaces`/`done_when[3]`/`verify[0]`），并回读对拍 `content_digest == sha256(spec 字节)` 确认规范绑定那位一字未动。与 AGENTS.md §7 那条「刷新摘要按值反选会把规范绑定一起改掉」是同一事故的正面版本。
5. **`git commit <pathspec>` 不隔离已 staged 的别人改动 —— 而 `git diff --cached` 不是「commit 里多了什么」的尺**：收口 worktree 的 index 里预先躺着一处非我所为的 `projects/agora` gitlink（与 `origin/main` 树、与子模块工作树 HEAD 三者各不相同）。我用 `git commit -- projects/omo`，提交前 `git diff --cached --stat` 只有一行，看着完全合规；提交后 `git diff --name-status origin/main..HEAD` 却多出一条 `M projects/agora` —— 该形式是在当前 index 之上构造提交、只把工作树里点名的路径盖上去，其余已 staged 内容照旧进去。**判据**：交付隔离度只看 commit 后的 `origin/main..HEAD`，不看 `--cached`。**处置**：`git reset --mixed origin/main`（本地未推的三个 commit 退回、工作树逐字保留）→ 显式 `git add <路径>` → **不带 pathspec** 的 `git commit`。同轮因此**没走** `submodule-pointer-transaction.sh`（它按 base 差集 `git add` 全部漂移并 push 别人子仓）；这条工具行为值得单独一次治理，不在本轮顺手改。
6. **CI 的两套口径决定测试该落哪**：omo `ci.yml` 跑整份 `pytest tests/`，根 `governance-check.yml` 用显式文件白名单且不含 `tests/**`。所以尺放 omo 侧才有外部证据；台账却点了根仓库一个不存在的路径 —— 这是**登记腿写判据时按想象中的通道**，不是执行腿的缺口（AGENTS.md「验收条款先实证通道行为」第四次命中）。
