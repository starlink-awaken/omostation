## Q3 过程中发现的与 plan 不符的事实（打假）

1. **spec §4-8 的 plist 基线"51"是错的，实测 43**（全量 58）。spec 已被 `content_digest` 绑定，
   改它必然触发摘要不一致，所以留痕而不回改。
2. **plan 说"状态迁移"，本轮实际只做到"放置副本"**。`event_ledger/surface.py` 从不读
   `OMOSTATION_STATE_ROOT`，只认 `OMO_EVENT_LEDGER_DB`，否则回落 `WORKSPACE_ROOT`。
   所以任何"状态根已迁移"的表述都为假；台账 `goal` 已把这点写进去，避免后继批次误接。
3. **`owned_installed == owned_declared` 是派生等式，不是门禁**（`gen-service-configs.py:477`
   用 `owned_installed - len(e2_gap)` 算 declared）。拿"49==49"当不变量会在批次 2 自欺。
4. **PASW worktree 自带一个平行写平面**：`repo_root.py --json` 在 `ws-b4b1-evidence` 里报
   `code_root == state_root == 该 worktree`，`event_ledger_path` 指向一个**不存在**的
   `<worktree>/runtime/omo/event-ledger.sqlite3`（`canonical_root` 仍正确）。这符合 ADR-0456
   "未声明 profile 时二者相等"的不变量，但 plan 的风险表只防了"误写 prod"，没防反向的
   "**每个 worktree 各写一份、`release` 时静默蒸发**"。这是本轮 canary 撞出 `source_missing` 时才看见的。
5. **`source_ahead` 本轮测不到非零**。done_when #3 把它当"源仍是活权威"的证据，但两次快照都是 0
   （权威写入节奏低于窗口分辨率）。证据改由**跨两次运行**的 seq 增长间接给出：真实副本 63 → 1.5h 后
   canary 67。契约的这条取证方式在低频写入下不成立，值得后继批次改用显式双读。

## Q4 下次可复用的做法（固化）

1. **判断在途 PR 能否靠重跑转绿之前，先读 workflow 的 `ref:`**。`github.event.pull_request.head.sha`
   意味着"修主干 + 等重跑"整条思路失效，唯一出路是托管后继。AGENTS.md §6 现在那句是错的，待订正。
2. **碰 gitlink 前先 `git -C projects/<sub> rev-parse --is-shallow-repository`**。`true` 时
   `merge-base --is-ancestor` 双向 false、`branch -r --contains` 空 —— 本地祖先判断整体不可信，
   会让 pre-push 报出与我改动无关的子模块"不可达"。`fetch --unshallow origin` 后即可证。
   锁被占时先 `lsof` + `pgrep` 确认无人持有，再把 0 字节 `.lock` **移走**（不是删）。
3. **单行生成态时间戳会挡 `gac-worktree.sh merge`**。用 `git show HEAD:<path> > <path>` 还原，
   比 `git restore` 稳：后者会派生 `post-checkout`，而本机已有一个挂了 4.5 小时的该钩子实例。
4. **receipt 必须在合并后重测**，不复述交付期数字。本轮因此才发现 63→67 的增长与 `exit 0` 不再成立。
5. **派生指标不当等式门禁**（Q3 第 3 条）；低频写入场景**取证要靠两次采样的差**，不靠单次窗口内计数。
