## 1. 本意（intended）

SIRI-51 报「agora-gateway 只有 UDP 42024、无 HTTP /health」。台账把这条外部诉求改写为四个可验的面：

1. `com.agora.daemon` 提供 `GET /health`，返回 `{status, uptime_s, udp_port}`，`udp_port` 只回报
   `AGORA_SWARM_UDP_PORT` 配置（7455），daemon 自身不开 UDP socket；
2. HTTP 默认端口自 7432 迁至 7433 并注册进 `protocols/port-registry.yaml`（7432 属 ecos-event-listener）；
3. `~/runtime/matrix.yaml` 新增 agora-daemon 条目并声明 `health_url`，让既有健康扫描走真 HTTP 探活；
4. 安装根 `~/.local/opt/omostation/projects/agora` 同步到含 `7c8269f`（types.py → agent_types.py）
   与本变更的提交，使 daemon 退出 crash-loop。

非目标四条：不复活独立 gateway（P2-5）、不动 UDP 逻辑、不 bump 主仓 submodule 指针、不改
cron-service/MatrixScheduler 代码。

## 3. 变了什么（changed）

- **机器态跑在仓库态前面**。合并前 `bf9a70f` 与 `17028fa` 的 tree 逐字节相同（`07a8fb6b5cd1a9c5…`），
  所以运行内容没有变；变的是「这份内容属于哪个 ref」。合并前安装根挂在一个**远端已删分支上的游离 commit**
  上，下一次 `git fetch --prune` + gc 之后它就不再可寻址 —— 回滚命令、复现命令都会指向一个不存在的对象。
  收口时把安装根前移到 `17028fa`（daemon 不重启，uptime 连续 92760s → 93155s 可证内容未变）。
- **判据随 base 变，第三次咬到自己**：`matrix-consistency-lint` 的 `PORT_REGISTRY_PATH` 由脚本自己的检出
  决定（`bin/ssot/matrix-consistency-lint.py:28-30`）。在落后的主检出上跑，它报 `R2 WARN: 'agora-daemon'
  port 7433 not found in port-registry.yaml` —— 而 `origin/main` 上 7433 早就注册了。这条 WARN 是装置没跟上
  基线，不是登记缺失；按 §7「门禁的尺本身会随 base 变」用 `git archive` 造了一棵基线树复算才拿到真读数。
- **子仓 PR 无 CI 是结构而不是状态**：`gh pr checks 126` 零输出，`mergeable=MERGEABLE`、
  `mergeStateStatus=CLEAN` —— 因为 omostation-agora 的 `origin/main` 上**一个 workflow 文件都没有**。
  这与 §7「no checks reported 的第一因是 CONFLICTING」是两种不同的零读数，必须先分清再决定是否补跑本地测试。
- **A2A 锁碰撞谓词的第二次复发被按 PITFALL-COO-008 处置**：`claim --path docs/plans/3y-bet-ledger.yaml`
  被 `run 20261104T115230Z-…-d825f60f` 的 `status: active` 阻塞（心跳 40h+ 前、锁过期 20h 前、该 BET 无
  open PR）。三条量都指向僵尸，按登记过的处置走**未 claim 交付**，不跑 `prune-locks`、不碰他人锁，
  原因写进 close evidence。

## 4. 教训（lessons）

1. **「代码在跑」不等于「交付完成」**。daemon 健康了 25 小时，而台账三面全空、PR 还 open ——
   这段时间里没有任何一道门会报警。凡是「机器侧先部署、仓侧后合」的交付，部署动作本身就应带着一次
   closeout，否则中间窗口对治理面完全不可见。
2. **跨仓交付的终态要由收口腿显式对齐 SHA，而不是靠 tree 相同来推**。tree 相同只能证明「此刻内容一致」，
   不能证明「一个月后还能找到这个对象」。收口时把安装根、子仓 main、证据 ref 三者对齐同一 SHA。
3. **子仓零 CI 时，本地复算是唯一证据**，所以收据必须写清「用哪个解释器、`agora.__file__` 指向哪棵树、
   base 侧同尺读数是多少」。缺任何一项，「4 passed」就是不可复核的数字。
4. **非目标要写清承接人**。「不 bump 主仓 submodule 指针」把 `projects/agora` 的 gitlink 留在 `e1cc383`，
   与子仓 main 差 1 个 commit；`bin/ssot/submodule-pointer-transaction.sh` 在「子仓 commit 已在
   origin/main」这一形态下**按构造 no-op**，所以这条 drift 不会自愈，只能由 `submodule-freshness-gatekeeper`
   报警后另起 `chore(submodule)` 交付承接。收据里点名，而不是留给下一位读者推。
