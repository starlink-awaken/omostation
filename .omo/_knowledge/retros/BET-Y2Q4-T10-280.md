# Retro — BET-Y2Q4-T10-280 panorama 账本路径接入 profile 缝

## 本意

ADR-0456 决策 2 列出的 9 处重复根定义里，`bin/panorama/panorama-collect.py` 是唯一没有折进
`repo_root.event_ledger_path()` 的一处。目标是把它的账本读面从检出根移到 profile 声明的
state 根，且未声明 profile 时逐字节保持历史布局。

## 实际发生

- 缺陷不止一层：除 import 时求值的模块常量（`:111-116`）外，还有 **3 处默认参数**
  （`:370`/`:381`/`:672`）把常量二次冻结，以及 `:3921` 调用点直接传常量。只把常量换成函数
  调用会让默认值仍在定义时刻抓住旧值 —— 这一层若不一起改，改动的实际效果是零。
- 交付：`bin/panorama/panorama-collect.py` + `tests/unit/test_panorama_event_ledger_seam.py`
  两个 commit（governance-state / code 分 lane），PR #5009。
- 取证：反基线读数在 `origin/main` 上 `^EVENT_LEDGER[[:space:]]*=` = 1、冻结默认值 = 3，
  在 HEAD 上均为 0；变异对照（把 3 处解析换回 import 时常量）读数 `2 failed / 6 passed`，
  红的正是两条 profile 用例；还原按 sha256 逐字节核对。相关既有用例同批 49 passed。

## 教训

1. **「把常量改成函数」的一半工作是默认参数**：`def f(x: Path = CONST)` 在函数定义时刻求值，
   与模块级常量同一种冻结。判据不能只看定义点读数为 0，还要看默认值是否仍是对象而非 `None` ——
   本轮把这一条直接写成用例（`test_default_argument_is_not_frozen_at_definition`），
   于是变异对照不再需要手工执行。
2. **`cp` 别名会静默拒绝覆盖**（本机 `cp → cp -iv`）：一次「备份→变异→还原」的收尾 `cp`
   打印 `not overwritten` 且 rc=1，若只看末行会以为还原成功。还原类操作一律用
   Python 写回 + sha256 对拍，别经过 shell 别名。
3. **同一 `&&` 链里混入非法变量名会截断整条链**：`sha1-before=$(...)` 在 zsh 里因连字符
   不是合法标识符而 `command not found`，后面的变异写入根本没执行，而 pytest 照样 8 passed ——
   这是「变异对照读数全绿」的假象来源。多步装置改用单个 Python 进程串起来。
4. **`tests/unit/**` 不在 `governance-check.yml` 的显式 pytest 白名单里**，本 BET 的新用例
   在 CI 上不可见；因此 receipt 明确标注「本地取证」，不把 CI 绿当这些用例的证据。
5. **未跑的检查如实写**：`make gac-local-gate` 全量本轮未执行，记在 Test plan 的未勾项，
   不写成「通过」。
