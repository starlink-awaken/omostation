# BET-Y2Q1-T10-03 retrospective

## Q1. What was intended?

台账瘦身：306 个 done BET 归档出主文件，消灭 20000+ 行主台账的并发编辑冲突热区；消费方合并读保证历史统计不失明；submit 增加裸冒号前置拦截。

## Q2. What happened?

全部按 spec 交付，PR #3307 CI 23/23 CLEAN 合并（3001f509）：
- 主台账 20000+ → **2898 行**（56 BET：39 candidate + 2 blocked + 13 留守锚点）
- archive 306 BET / 23416 行（含 meta 头）
- 4 个加载器合并读：lint 显示 **362 bets**（零重叠零丢失）、show 归档 BET 命中、value-proof **162 entries 全量可见**、arch-health 不缩水
- submit 双预检：冒号坏文件实测拦截、并发写警告落地

## Q3. What changed during implementation?

- **归档引发 gate 假 findings 的根因战**：lint 当前侧经 load() 合并 archive 可见归档 done，而 base 侧 `git show` 只读主台账 → 306 BET 被误判"新转入 done"→ bet-done-gate 硬失败。本地复现（BET_LEDGER_BASE_REF 环境）后补 base 侧合并——过程中发现并行 agent 的 #3309 已带入同款修复，主动放弃重复 commit（patch 等价性判定，PITFALL-GAT-006 实战）。
- **消费工具逐一核对兴趣面**：chain-bind-audit 只取 active/candidate（零影响跳过）；portfolio_projection 有 digest 快照锁定（改它破坏 PROJECTION_DRIFT 语义，明确不改）——按语义分流而非盲目全合并。
- **worktree git 状态烂透后止损重建**：cherry-pick/rebase/checkout-B 三重序列残留 + unmerged 路径，修复成本 > 重建成本，force remove 后从 origin/main 重建分支（本 commit 即产物）。

## Q4. Lessons (P73 truth-driven)

- **归档类改造先画消费面矩阵**（谁读什么状态字段），不画就漏。
- **双侧对称原则**：给"当前侧"加载加合并时，所有"base 侧/git show"路径必须同步——否则 diff 语义撕裂，这是本次 gate 假阳性的机制根源。
- git 状态烂透时**重建优于修复**（worktree remove --force + branch -D + 重建，2 分钟 vs 30 分钟考古）。
