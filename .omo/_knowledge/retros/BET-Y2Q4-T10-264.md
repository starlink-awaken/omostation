台账：`docs/plans/3y-bet-ledger.yaml` `BET-Y2Q4-T10-264`
规格：`docs/superpowers/specs/2026-10-22-tasks-index-rebuild-fail-closed.md`（digest `sha256:685f5519c35bf4e6…`）

## 1 intended — 原本要发生什么

这条 BET 不在 plan 的 B1–B5 任何一批里。它是在为 B4b 批次 2 做准备时**顺手量出来**的一个 B5 缺陷面：
`sync-tasks` 会把 `.omo/tasks/registry/INDEX.md` 的派生段重写成空面。
原计划只是「看一眼能不能自决修掉，再回去做批次 2」；按 §7 的准入习惯，它需要 spec + 台账 + 测试才能改生产者。

## 2 happened — 实际发生了什麼

1. **事故形状在真机上已经发生了**：一次 sync 把 tracked 的 Planned 7 行（含 `TASK-019B7FD6`）写成 0 个。
   根因不是逻辑错，是 `if dir.exists() else []` 这个兜底把「面缺席」折叠成「面为空」。
2. 修法只有四行（要求四张面全存在，否则 `return False`），但**判据成本远大于修复成本**：
   要区分「目录缺席」与「目录存在为空」两种输入，就得给 fixture 造一个能表达「键缺席」的构造器
   （`materialize_sync_tasks_index`：键不存在 → 不建目录；键存在且为 `[]` → 建空目录），
   否则用例只会测到其中一种。
3. 浅历史 worktree 让我在 re-pin 时拿到**假「非祖先」读数**（`merge-base` 空输出），
   差点据此认为 bump 会回退子仓内容；换到 canonical 深检出才量出线性史。
4. 中途两次 `WORK_PACKET_SCOPE_MISMATCH`：我给收口报告**编了**一个文件名，而 packet 里
   声明的是另一个。回执把权威 scope 列表原样打了出来 —— 照它取名即可，不是随机拦截。

## 3 changed — 实际改变了什么

- 生产者侧：`_rebuild_tasks_registry_index()` fail-closed；「未重建」成为可见输出而不是静默。
- 契约侧：AGENTS.md §7 新增一条（证据→判据→纪律），三条命名用例进 CI 可见的 omo 测试面。
- 刻意**没有**顺手收紧 `system.yaml` 的计数语义（spec C3 + T236 边界）：那属于 B5 的另一面，
  混进本 PR 会让一个 fail-closed 修复变成写面重设计。

## 4 lessons — 可复用的判据

1. **「缺席」与「为空」必须在类型上可区分**，否则任何 `exists() else []` 兜底都会把
   「这台机器上这棵树没有这个面」读成「这个面有 0 项」，进而让派生器覆盖真源。
   判别式不是「值对不对」而是**输入形状**：兜底返回的空集合与真实的空集合是否共用同一个构造点。
2. **改派生器的守卫，测试 fixture 必须能表达「缺席」**。本轮如果只用 `planes = {…, "planned": []}`
   就测不出新守卫 —— 它测的是「存在且为空」，守卫会被误判成无效。
3. **绿必须配变异反证**（§7③）：摘掉守卫 → 缺席面两条用例当场红。没有这一步，
   「67 passed」不能证明守卫起作用。
4. **可达性判据前先测浅史**（§7 第四次实证）：`rev-parse --is-shallow-repository` 是前置动作，
   不是事后解释。
5. **packet 报错里含着权威名单**：`WORK_PACKET_SCOPE_MISMATCH` 的回执文本就是正确路径来源，
   比自己的命名习惯可靠。

## 5 遗留

- INDEX 的 `Completed` 里程碑段与 `Archived` 段仍是手维护（`_rebuild_tasks_registry_index` 只刷派生段），
  与「摘库后各检出各一份」的长期形态有张力，属 B5 后续。
- 本 BET 不构成 B4b 批次 2 的任何进展；批次 2 的前置实测显示 `gen-service-configs.py` 的
  `workspace()` 仍锁 `canonical_root()`，改道需要生成器侧改动，不是运行面动作。
