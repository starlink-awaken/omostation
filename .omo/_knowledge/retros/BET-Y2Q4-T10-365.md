# Retro — BET-Y2Q4-T10-365

## 1. 意图（intended）

`BET-Y2Q4-T10-364` 的收口回执 §5 记实了一次**发布自伤**: 发布器返回 `ok: true`,
宿主刷新作业随即抛 `projection_collector_not_at_bound_commit`, 投影停更,
live server `CODE_DRIFT`, 静态资源 503, 驾驶舱整站不可用; 本轮已回滚复原。

回执同时把根因写成了一条**从未被写进契约的前置条件**:
「采集器字节必须等于生产者代码根 HEAD 上的字节」。

本 BET 三件事: ① 把这条前置条件机器化 —— 发布器在切换 `current` 之前必须先验绑定;
② 绑定不可验证时**跳过而不阻断** (无法自证时不反手阻断发布);
③ 让判据有正反用例, 且接线钉在**真实 `publish()` 入口**上。

## 3. 差距与坑（learned）

1. **契约要成对**: 采集器把「我的字节必须等于生产者 HEAD 的字节」当**硬拒绝**,
   发布器只当「我的字节必须等于仓库资产字节」当**通过条件** —— 两个半边都不完整,
   合起来才是完整契约。发布侧缺的那一半**不会自己报错**, 只会让下游以另一种方式
   (503 / 投影停更) 崩, 于是排查成本全落在「为什么服务挂了」而不是「谁违约了」。
   **纪律**: 给任何有身份自校验的组件做发布器时, 先把自校验里的等式抄成发布器的
   前置检查 —— 等式两边一换就是契约缺口。
2. **前置检查的位置必须在「切换指针之前」**: 检查若放在切换之后, 就退化成事后审计
   (出了问题再回滚, 而回滚本身在宿主上要 `restore` + 两次 kickstart)。放在
   `_prepare_version()` 之后、`_switch_current()` 之前, 失败只需丢弃新建目录,
   宿主零扰动 —— 实测回滚路径上「什么都没发生」。
3. **不可验证 ≠ 不通过**: 生产者根缺失 / 非 git 仓 / HEAD 无该路径时, 检查无法给出
   结论。此时**跳过而不阻断** —— 因为在采集器自身同样无法自证的情形下 (例如
   code-main 尚未建立), 阻断发布会把「本来可以慢慢修」变成「发布面彻底不可用」。
   判据要区分三态: 成立 / 不成立 / 不可验证, 不能把第三态塞进第二态。
4. **接线钉子必须走真实入口**: 本 BET 的核心用例是「绑定不成立时 `publish()`
   拒绝且 `current` 未被切换」, 走的是**真实发布入口**而非抽出来的函数 ——
   沿用 T10-364 的教训 (「测试绕过接线就钉不住接线」: `test_gac_guard_submodules.py`
   原本从生产脚本抽函数体直接调, 派发死了它全程绿)。
5. **lane 隔离是 per-commit 的**: 本轮四个写面分属 `governance_code` / `code` /
   `docs` / `docs_data` 四个 lane, 混在一个 commit 会被 pre-commit 的
   `change-lane-check` 拦下 (`ALLOWED_COMBOS` 不含 `code` 与 `governance_code`
   的组合)。按语义拆成 4 个 commit 后通过 —— 拆 commit 的粒度本身就是判据要求。
6. **台账轴状态有取值域**: `engineering` 轴只接受 `NOT_STARTED` / `IN_PROGRESS` /
   `VERIFIED` (没有 `NOT_PROVEN`, 那是 `operational` / `value` 的取值);
   起草态用 `IN_PROGRESS` + `overall_state: evaluating`, 收口时才改 `VERIFIED` +
   `delivery_accepted`。另外 `done_when` 里带 `: ` 的条目要加引号, 否则被解析成 dict。
