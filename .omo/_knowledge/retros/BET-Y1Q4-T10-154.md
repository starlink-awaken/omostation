# Retro: BET-Y1Q4-T10-154 (Diff Lifecycle Closure)

## Summary

扫描 workspace 中的 `.patch/.diff` 文件, 检测其中包含的 commit 是否已被后续 merge 覆盖, 防止孤儿 diff 长期占用仓库空间。

## What went well

- 与 PR #3578 一起批量交付 5 个 repo hygiene 脚本 (diff-lifecycle / diff-debt / diff-growth / orphan-files / stale-branches), 共享同一套脚本注册 + 测试 pattern
- `check-diff-lifecycle.py` 用 git rev-parse 检测 patch 中 commit 是否仍在 HEAD 历史中, 不依赖外部 patch tracker

## What was learned

- 孤儿 diff 大多来自 8 月批量化并发 agent 的 WIP patch 沉淀, 与 bet-execution closeout 流程不完善相关
- 5 个脚本均使用同一 git subprocess shellout pattern, 后续可抽象 `SubprocessGitHelper` 共用

## What to improve

- patch 中的 commit SHA 可能因 force-push 而不再可达, 需要 fallback "patch 文本模糊匹配" 路径
- 当前只检测 .patch/.diff 文件, 未检测 stash 留下的 commit (stash 通常以 reflog 形式存在)

## Metrics

- Files: 1 script (214 LOC) + 1 test (164 LOC)
- 覆盖场景: 4 种孤儿 diff 模式 (orphan-patch / orphan-stash / orphan-commit / orphan-no-origin)
- Appetite used: 0.5d (within 1 sprint)

## 关联

- 同批交付: T10-155 (Diff Debt Tracking) + T10-156 (Diff Growth Detection)
- 后续可挂入 pre-commit hook 强制孤儿 diff 在 commit 前阻断
