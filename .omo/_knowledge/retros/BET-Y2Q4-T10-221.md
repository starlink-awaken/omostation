## 2 happened — 实际发生了什么

**预期外的只有一件，但它 dominates 本轮**：台账 verify 第 1 条我自己写的检查命令，第一跑就 rc=1。

原因不是"指针引了不存在的行"（那条命令的 `expect` 文本预言的失败形状），而是
`re.findall` 在模式含单个捕获组时**只返回组内容** —— 返回的 token 不带 `:NN`，
于是 `p.split(':')[1]` `IndexError`。装置坏了，不是被测物坏了。

两种读法的分岔代价很高：按 `expect` 文本读，我会去改 AGENTS.md 的指针文字（把对的改成错的），
或者去补 `.gitignore:411` 那条忽略（把已摘库的生成态塞回仓）；花一次执行看 traceback 就分清。
修正形状在同仓已有正确实现 —— T10-215 的同名命令用两个捕获组解包（台账 `:38692`）。
我重新造了一遍轮子，于是重新造了一遍它的 bug。

顺带查出一个更阴的静默漏洞：那条命令的扩展名 alternation 里没有 `yml`，而我本轮新写的指针里
就有 `governance-check.yml:118` —— 即便命令能跑，这类指针也**从来没被检查过**。

其余按预期：三条 lane 分片各跑一遍本地门禁全 PASS（`change-lane-check` 把 `.omo/**` 归
governance_state 且禁止与任何 lane 同批，所以 4 文件一个 commit 会红，拆 3 个 commit 就绿）；
7 条 verify 全部跑出声明的读数；CI 20 项全绿；squash 合并后 `gh` 的回读请求 TLS timeout 报 exit 1，
但 `gh pr view` 确认 MERGED —— 按既有"失败发生在效应之后"读数处理，没重跑合并。

## 4 lessons — 固化什么

1. **契约里的每条命令，写进台账之前先跑一遍**（本轮第二次踩，第一次是 T10-220 那句被自己
   receipt 否证的"检出不含这三行"）。区分"被测物坏了"和"测量装置坏了"的唯一手段是执行，
   而 `expect` 文本预言的失败形状会**主动**把装置故障误读成回归。
2. **一个"通过"的检查可能只是没看见东西** —— 白名单型 alternation 少一个扩展名，门禁就对
   该类对象永久沉默。写扫描类命令时，判据不是"它 PASS"而是"它能 FAIL"：拿一个已知会命中的
   对象试一次（`governance-check.yml:118` 就是那枚探针）。
3. **抄同批已绿的邻居，不抄 checklist** —— 本轮把它从文档面（frontmatter）推广到命令面：
   同一仓里已有正确实现的检查，先用 `git grep` 找现成的，别在台账里重写一份。
4. **lane 门禁的形状要先测再拆**：`change-lane-check` 只在本地 `--scope staged` 生效、
   对 `.omo/**` 一律归 governance_state 且拒绝混批 —— 这决定了感知类交付天然是多 commit，
   而 squash 合并让它对 PR 历史无代价。知道这条，就不用把"门禁红"误读成"交付有问题"。
5. **交付的边界是远端，不是 `git commit` 成功**：本轮两个 commit 落库约 11 小时后工作树目录
   `/Users/xiamingxing/ws-t10-221-perception` 从磁盘消失（`git worktree list` 也不再列它）。
   对象与分支 ref 都活在主仓共享 `.git` 里，所以 `git worktree add` 到一个**不匹配 `$HOME/ws-*`
   / `$HOME/workspace-*`** 的新路径就能逐字节恢复；但这条恢复路径只在"已 commit 未 push"时成立 ——
   未 commit 的工作面没有任何地方接着它。commit–push 之间的窗口越长，越要把 push 当作断点而非收尾。
