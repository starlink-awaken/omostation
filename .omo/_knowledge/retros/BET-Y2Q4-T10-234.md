## 4 lessons — 固化什么

1. **bet id 分配是竞态，不能从「本地看到的空号」推断「main 上仍空」**。并发 agent 可能基于更旧的
   base 各自算出同一个「下一个号」。本轮之前的候选流程只查了本地台账 → 撞上 `T10-233`。正确流程：
   `git fetch origin main` 后，从**当前 origin/main** 的 ledger 计算已用号集合，并同时扫
   `.omo/tasks/`、`.omo/_knowledge/retros/`、`docs/superpowers/specs/` frontmatter 里的 `bet_id`
   占用；选定候选后按 (i) ledger (ii) run records (iii) retros filename (iv) spec frontmatter 四项
   复验。已选 `BET-Y2Q4-T10-234`，四项全部通过（见交付报告 Task 1）。
2. **台账工具对「本地文件」求值，对「并发 merge 后的 main」不可见** —— `ledger-safe-insert.py`
   的 duplicate 校验只能防同 base 内的自撞，防不了并发 merge 引入的撞号。这是真实工具缺口：
   **用它之前先 fetch 并核对 origin/main**，把「撞号 lint 会在合并后硬失败」当作默认风险而不是
   工具会替你兜底。
3. **未提交的工作树状态是零持久性**（本轮自伤实证）：`git checkout -f` 一次就冲掉未提交的台账
   条目。能恢复靠的是**已入库的文本留存**（spec 意图 + run 记录绑定），不是任何未提交状态。
   写正式交付物（spec / ledger / retro）时：**先 commit**，再继续；改动完立刻显式 `git add` +
   核对 `--cached --name-status`（勿 `-A`），不要让关键文本只存在于工作树。
4. **代理判据会传染，且路径子串就是它的最弱形式**：`"phase10" in registry_text` 连
   `phase10_retro:` 文档路径都能放行。真正的判据必须指向**执行的证据**（观测缝水印/记录），
   并配「旧判据在什么输入下会假绿」的反例测试。
5. **首发门禁必须 WARN**，不能 ERROR：缝新、无基线记录时 hard error 会在每个干净检出/CI 上假红；
   WARN + docstring 升级路径让门禁立即上线而不制造噪音。

## 5 遗留（实测后登记，不是遗漏）

- **缝的 ERROR 升级**：需要一份「默认环境真实执行」的基线记录（生产观测到一次 `default_env=true`
  后）才能把「无真实执行」分支翻为 hard error 并加新鲜度窗口 —— 属于后续独立 BET。
- **台账条目与 complete 的收尾时序**：台账路径在交付轮被活跃 run `76449fc2`（T4-07，status active）
  持有 path 锁，按协调纪律不偷锁、不 prune；本条目的**真实插入 + `bet-ledger.py complete`** 因此
  安排为独立后续步骤（条目草稿与 dry-run 校验已随交付报告给出）。
- **fixture-only 不写观测**意味着「尚未观测到真实执行」只能靠文件缺席表达 —— 这是有意设计；
  监控端如需「明确无记录」与「从未建过文件」的区分，属于后续增强。
- 吸收自前一轮（#4662/#4665 resident wave）的既有语境：ADR-0456 的
  `BET-Y2Q4-T10-233`（omo 写面 state 根）与本次 `BET-Y2Q4-T10-234`（MOS 观测缝）是两条独立 bet，
  retro 路径各自对应自己的 id，互不覆盖。
