# BET-Y1Q4-T10-132 retro — DBOS 离散状态水合与 WAL 原子调度

## What changed

- **`omo/resident/hydration.py`**（新）：`HydrationStateMachine` 四态
  （DORMANT/HYDRATING/ACTIVE/DEHYDRATING）非法迁移 fail-closed；
  `hydrate`（WAL SQLite 读回认知帧，实测 **0.076ms ≪ 15ms**）、
  `dehydrate`（事务原子写 + 内存引用释放——无 GPU 张量持有，
  显存增量 0 由构造保证）、`probe_read_latency`（mode=ro 探测）。
- **`schema_v3.sql`**（新）：hydration_frames 表（agent_id 主键/state
  CHECK 约束）+ WAL 启用 + 状态索引。
- 测试 7/7：迁移非法性（fail-closed）、水合往返、ACTIVE→DEHYDRATE
  循环、ro 探测 ≤15ms、6 agent 并发水合独立性、50 轮压力循环；
  ruff clean。

## Q3 (打假)

- "显存增量 0" 是**代码结构语义**（帧为纯 JSON dict，无张量持有），
  非物理显存测量——本层不接 CUDA/Metal。
- 状态机首版拒绝 DORMANT→DEHYDRATING，但"初始帧落盘"是该迁移的
  合法语义——放开后单测同步更新。
- binding spec 的 last-reviewed 写了 CI 时区的未来日期
  （2026-09-07 vs CI 09-06）→ unbaselined warning 红一次；
  digest 也随之失配重绑——**spec 落库日期一律取 UTC**。

## Q4 (遗留)

- 水合引擎为独立组件，resident daemon 事件循环的接入待后续 bet。
- 多进程（非线程）并发与跨机 WAL 语义未压测。
