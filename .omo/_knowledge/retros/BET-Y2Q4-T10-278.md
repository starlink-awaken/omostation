## 教训

1. **「待办 BET」不一定等于「待办工作」。** 台账 `status: pending` 只说明簿记未闭合。领 BET 前应先按
   `done_when` 逐条在 `origin/main` 上实测（本例三条全部命中，且其中一条的引入 commit 比 BET 登记日还早一个月）。
   跳过这一步会重做已合入的内容——在并发多 agent 仓里，重做的 PR 合并会回退 main 的正确值。
2. **按编号引用决策是这份仓库特有的坑。** 两文件同时声明 `id: ADR-0456` 且均为 `ACCEPTED`，
   只有文件名不同。任何 `ADR-0456` 形式的引用都可能指向另一件决定；引用一律写完整路径。
   （这条已由 `ec2f14252` 写进 `AGENTS.md` §1，本轮是第二次撞上去。）
3. **draft 报告长期挂 `status: draft` 会成为反向证据。** 它的「未闭环项」文字在事实变化后不自动更新，
   下一位接手者会按文字重做。定稿比新建一份更便宜，且必须逐行复核旧文字。
4. **准入豁免的作用域要在交付前重读。** 豁免只允许登记、明确禁止提交推送；把它读成「本 BET 全流程已获授权」
   会越权。真正需要的是正常 run + claim 之后的独立交付。
