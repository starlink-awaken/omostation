## Q3 与 plan（或与我自己的预判）不符的事实 —— 逐条打假

**a. 台账 done_when-2 把两个函数的判据糊成一句。** 「空串、None、相对路径一律抛」在 `assert_import_root` 面上成立；
而 `import_root_report(None)` 按 spec C2 的显式措辞是**自探 `repo_root.__file__` 并返回布尔**，不抛。
第一版用例把两者当同一件事写，`[None]` 参数当场红。
**这不是实现错，是判据文字没点名。** 处置：不缩判据，而是拆成两条用例把这条不对称**显式钉住**
（`test_g1_none_module_file_is_the_self_probe_not_an_unreadable_input`，`assert_import_root(None)` 抛 / `import_root_report(None)` 自探）。
教训：**同一条 done_when 覆盖两个 callable 时必须点名函数**，否则下一轮有人会把它「修」成其中一种读法。

**b. 我自己写的 `verify[0].cmd` 按字面跑不起来。** 它少了 `--with pytest-timeout`，而根 `pyproject.toml` 的 addopts 注入
`--timeout=300 --timeout-method=signal` ⇒ 最小 venv 下 pytest 当场 `unrecognized arguments`。
更糟的是我第一次想修它时用了**单行 `str.replace`**，而 YAML 里那条 cmd 是折叠多行标量 ⇒ 命中 0 次、断言失败、文件没被写。
「写进台账的验收命令」和「实际跑过的命令」之间没有自动等价 —— AGENTS.md §7「验收条款先实证通道行为」这条**在我自己身上复发了一次**。
判据：cmd 落盘前逐字执行一次；改 cmd 时按 YAML 折叠后的真实文本匹配（先 `yaml.safe_load` 取出字符串再比对）。

**c. 变异对照差点是空判据。** 输入面有**两层守卫**（`assert_import_root` 自己的守卫 + `import_root_report` 里的绝对路径判断），
所以「只撤一层」的 mutant 照样抛 —— 撤一层不是有效对照，绿是因为另一层兜住了，不是因为判据在工作。
真正能判别的 mutant 要把守卫**折成静默通过**（`return base`）。同理，`under` 判定的恒真 mutant 必须绕过 `relative_to`
而不是把 `try` 包成别的形状。三条对照各带一条「装置没命中就不算证据」的前置断言（`mutated != source` / `count == 1`）。

**d. 装置类自伤两次。** ① 本机 `cp` 是 `cp -iv` 别名：对已存在文件打印 `not overwritten` 后 **rc=1**，
于是我的「换基线对照」链条在 `cp` 处断掉、pytest 根本没跑，而输出看着像跑过了（改用 Python `shutil.copyfile`）。
② `affected-graph.py --changed-projects` 要的是 layer-contract 里的**项目名**不是目录名，`docs`/`bin` 报 unknown project，
本腿这种只碰根仓文件的改动正确值是 `workspace-root`；receipt 还必须经 `--affected-hash` 显式传给 `claim`，且不能落 symlink 目录。

**e. 我算错了一次总数。** 596 —— 实际 `git show --numstat` 累加是 **696 insertions / 1 deletion**。
落盘前用实测数字对拍才没让它进 receipt。凡是「几个文件加起来多少行」这类叙述，用命令算，不用脑子加。

**f. 与 ADR 的关系要如实说：这条缓解仍然没有接线。** `assert_import_root()` 交付即绿，但没有任何常驻入口调用它，
所以 ADR-0456 `:246` 记的风险面**只是变得可观测，不是被拦截**。接线轮的前置顺序（B4b 批次 2 的逐批改道授权）写进 spec §1，
不被本 retro 的「完成」措辞覆盖。

## Q5 下一个认领这条线的人需要知道什么

1. **缝在这里，但它是观测面不是保险丝**：`bin/lib/repo_root.py:140`（`import_root_report`）/ `:177`（`assert_import_root`）。
   接线到常驻入口 = B4b 批次 2 的授权面，动之前先读 spec §1 与 task #91，别在改道之前把硬断言塞进 driver。
2. **「判不了」的读数形状不可折叠。** `under=None` 是设计，不是 bug；把它改成 `False` 会让「探针名不可解析」与「确实不在根下」同形
   （用例 `:163` 的对照专门钉这一点）。`roots_report()` 未设探针时 `probed=false` 且 `ok` **不是** true。
3. **边界用 `relative_to` 不用父段交集。** `/tmp/x` 与 `/private/tmp/x` 两条 resolve 链的父段集合有交集，
   用父段判交会把「不在根下」读成「在根下」。
4. **跑这些用例的装置**：`env -u OMOSTATION_ROOT -u OMOSTATION_STATE_ROOT HOME=<空> uv run --no-project
   --with pytest --with pytest-timeout --with pyyaml python -m pytest … -q -p no:randomly`。
   宿主解释器在 `HOME=<空>` 下连 pytest 都没有；`pytest-timeout` 不能省（根 addopts 注入 `--timeout`）。
   `tests/unit/**` **不在** CI pytest 白名单，所以这里的绿只有本地证据。
5. **39 条 `.pth` 仍原样**。它们是 14 个 venv 的 editable 产物；本轮只让「跑的是哪份码」可读，重建属运维，
   且目标拓扑取决于 B4b。别把这 39 条当成本轮该清的债。
6. **邻居那 6 条红与本契约无关，且可复现**：换基线 `repo_root.py` 同装置单跑，失败函数名逐字相同。
   其中 5 条属 resident write-plane 判据清单，1 条属 ledger 调用时刻探针 —— 想动它们请另开 BET，别顺手改窄。
