## 教训

- **spec 的 "processed=2208" 是快照口径，实际以真实事件文件为准**：真实 `events.jsonl` 累计到 2214 条，sediment 路由消费 2090（其余属 decision/execute 角色事件）。done_when 的精确数字不可脱离数据源复现，验收时应以"无 placeholder 落盘 + 按 run 幂等 + 计数符合事件分布"为准。
- **worktree 子模块 half-init 是真坑**：`gac-worktree.sh claim` 超时中断后，子模块 git-dir 存在但 worktree 文件缺失（aetherforge/bus-foundation），需要逐个 `git reset --hard` 物化。根因是 claim 时 submodule init 未完成。
- **重放必须在隔离 worktree 跑**：sediment 草稿写到 `WORKSPACE/.omo/_knowledge/sediment/`，在共享主仓跑会污染并发 agent 状态。用 `--events-jsonl` 指向真实事件文件 + worktree 隔离写入，产物 gitignored 不入库。
- **ledger 数据债**：T10-MATURITY track 定义缺失（12 个 T10 bet 全部 claim-check KeyError），T10-01~09 缺 done_when/verify（空列表），T10-06 depends_on 是逗号字符串（lint 逐字符拆分报 60+ 假错误），T10-12 done_when[4] 未加引号冒号。本次修了 track + T10-06 deps + T10-12 冒号；T10-01~09 的 done_when/verify 重构 + completion_evidence sha256 漂移（74 lint 问题）留作独立收敛。
