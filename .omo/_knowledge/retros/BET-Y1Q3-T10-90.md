# BET-Y1Q3-T10-90 retrospective

## Q1. What was intended?

Align the derived Workspace task-state projection with the tracked task
directories after a planned task reappeared on main.

## Q2. What happened?

The OMO `sync-tasks` broker refreshed `system.yaml` counters and rebuilt the
planned-task registry index. The coherence gate then returned `ok=true` with no
divergence flags.

## Q3. What was discovered?

The failure was a mainline concurrency regression: a task file landed without
the corresponding derived state refresh. The full `omo state sync` wrapper also
has an environment-sensitive editable dependency path, so the narrow
`sync-tasks` broker was the correct bounded repair.

## Q4. Surface accounting

Only broker-owned task projection surfaces changed in the repository. No task
source, Documents content, client state, runtime payload, or submodule pointer
changed. The runtime receipt was emitted under the registered ingress delivery
root.

## Q5. What should the next agent know?

Keep `event-loop-dead-loop` as a separate candidate; this BET only repairs the
projection that describes it. T10-71 remains a separate spec/evidence repair
until its pull request is rechecked against the repaired main baseline.
