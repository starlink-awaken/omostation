## 4. 教训（lessons）

1. **「归零类」验收必须问这个 0 是谁给的**。规则给的、树里本来就没有的、检测器没命中的，三种 0
   在输出里逐字相同。判据：写"改后为 0"时同时写一条"改前为 N"，且 N 与 0 由**同一次装置**产出，
   装置里被检对象要真实存在（本轮靠按路径物化空文件造出来）。
2. **契约取派生集，不取实测集**。本机只长出 4 个目录，源码导出 14 个；按实测写契约等于把这台机器的
   历史当规格，下一台机器或下一个 commit 就会红。
3. **变异装置自己会消失**。收口腿想引用工程腿记的"M1 2 failed"时发现 `/tmp` 驱动已被清掉、定义无从
   核对 ⇒ 只能整批重跑一遍，并把**改法 + 红的用例名**一起写进 receipt。这是"读数必须标注产出它的装置"
   的加强版：装置是会过期的，不落定义就等于没做。
4. **链式命令里别把"审查用的可选探测"和"必须发生的写动作"串在一起**。`git status --short --cached`
   不是合法选项，rc=129 把 `&& git commit` 一起打断 —— 什么都没提交，而 `git add` 已经成功。这类
   "半程失败"比整程失败更费时间，因为它留下一个看着像已完成的状态。
5. 又一次实证 AGENTS.md §7⑤：zsh 里 `cp` 是 `cp -iv` 别名，对已存在文件打印 `not overwritten` 后
   **rc=1 且目标逐字节未变**；还原文件一律走 Python。
