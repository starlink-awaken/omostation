# Retro — BET-Y2Q4-T10-281 B4b 验收尺的 repo_root 缝可达性修复

## 本意

`scripts/tools/launchd-workspace-reality-check.py` 是 BET-Y2Q4-T10-272 为 ADR-0456 B4b 造的
E7 写根轴量具。本轮不是要改 B4b 的目标态，而是要让**这把尺本身**能观察 profile：它的
`repo_root` 缝算成 `parents[1] / "lib"` = `scripts/lib`，检出根与运行时安装位两侧都不存在，
所以每次运行都走 `except ImportError` 的字面量兜底。

范围严格限定在尺自身与它的用例。不动 `spine-daily-ingress.py`（同一个死缝，但它是 B4b 唯一
还在真写检出根的活面），不扩 `test_writeplane_root_pin.py` 的枚举面。

## 实际发生

- 缺陷确认方式不是读代码，是**在尺里打印解析结果**：三个 resolver 的 `__module__` 不是
  `repo_root`，而是尺自己定义的兜底函数。兜底 `install_root()` 永不返回 `None`，直接违反
  BET-Y2Q4-T10-265 定下的「`install_root()` 返回 `None` 时抛错，绝不静默退回检出根」。
- 修缝后重跑，读数**逐字节等于**修缝前：9 个顶层字段、19 个叶子字段，0 处差异，两份 JSON
  的 `sha256` 一致。这把尺过去的读数没错，错的是它**没有能力**在某些情形下出错。
- 交付链在 `agent-workflow start` 上断了一次：worktree 以 `SKIP_SUBMODULE_INIT=1` claim，
  `projects/omo` 缺（`ModuleNotFoundError: No module named 'omo'`），浅 init 补上后
  `start` 又报 `WORK_PACKET_COMPILER_UNAVAILABLE`——`bin/plan/bet-ledger.py:2121` 要求
  `projects/ecos/src`，而 `--depth 1` 的浅克隆缺 gitlink pin 指向的对象
  （`fatal: Unable to find current revision in submodule path 'projects/ecos'`）。
  去掉 `--depth 1` 走完整 init 才通。当时**在任何 commit/push 之前**停下，主仓台账未留下
  悬空 `in_progress` 条目。
- 本轮自己也复现了同一个深度 bug 一次：新用例里 `REPO = Path(__file__).resolve().parents[1]`
  对 `tests/unit/x.py` 应为 `parents[2]`，4 条用例全部 `FileNotFoundError`，指向
  `<worktree>/tests/scripts/tools/…`。修完 4 passed。这是被修的那个错误的同形复现。
- 一次流程违规：动笔前没问「我在哪棵树」，Edit/Write 落到了共享主区
  `/Users/xiamingxing/Workspace`（违反 AGENTS.md §0）。同轮内按文件 sha256 对拍搬回 worktree、
  `git checkout --` 已跟踪那份、`rm -f` 自己那份未跟踪的，主区恢复干净。

## 改变

- 尺：缝深度 → `parents[2] / "bin" / "lib"`；目录缺席 → `SystemExit`；`install_root()` 返回
  `None` → `SystemExit`。静默兜底整段删除。
- 新增 `tests/unit/test_b4b_ruler_seam_reachability.py` 四条，其中一条是**合成违规自证**
  （把缝改回 `parents[1]` 复制进临时树，断言守卫当场 `SystemExit`），一条是 fail-closed 面。
- 第一次以「可达的缝」产出 B4b 读数：84 plists / workspace 2 / install 40 / other 42 /
  state_root profile 35 / undeclared 49。这组数与兜底版同值，但从此可移植。

## 教训

1. **「读数对」与「尺能用」是两件事，前者不提供后者的任何证据。** 这把尺连续几轮产出看起来
   合理的数字，只因为兜底字面量在这台机器上恰好等于真实根。判据：任何验收尺都要能回答
   「换一台机器 / 声明 profile / 目标缺失时，我的读数会不会变」，三问全不会变 ⇒ 尺没接上。
2. **兜底码的可见性测试要写成 `__module__` 断言，不是数值断言。** 数值断言在兜底路径下同样绿。
   本轮第一条用例就是这个形状。
3. **量具类交付的默认验收里必须有一条反基线读数**（合成违规注入）。AGENTS.md §7③「按构造就绿」
   在尺上尤其致命，因为尺的产物被别人当权威引用——历史 receipt
   `docs/reports/2026-10-27-b4b-managed-cutover-pilot-batch1-closeout.md:23-27` 的
   「40 → 39 / install 0 → 1」就是这么被抄下去的。
4. **`SKIP_SUBMODULE_INIT=1` 的 worktree 与 governed run 不兼容，且失败点滞后。** 浅 init 只补
   omo 不够，`agent-workflow start` 还要 `projects/ecos/src` 的 WorkPacket 编译器，而浅克隆缺
   pin 对象。判据：要跑 `start`/`claim` 的 worktree 用 `claim --full`（或
   `GAC_FULL_SUBMODULE_INIT=1`），别用 `SKIP_SUBMODULE_INIT=1` 快速路径。
5. **动笔前一条命令问根**：`pwd` + `git rev-parse --show-toplevel`。§0 的隔离不是靠记得
   「我要在 worktree 里改」，而是靠落笔前实测当前树——本轮的违规发生在「心里知道规则、
   手上直接 Edit」的缝里。
6. **台账里的 `#` 是注释起始，不是字符**（AGENTS.md §7 已记过一次，本轮再犯一次，且犯在
   我自己上一轮写的条目里）：`note: …… 由 PR #5017 squash ……` 被 YAML plain scalar 规则
   截断成 `'……由 PR'`，磁盘上文件完好、`git diff` 看不出问题、`safe_load` 不报错。
   本轮在写 ledger 后做**解析回读**才发现自己的 note 断了，并顺手取证邻居
   BET-Y2Q4-T10-280 的 note 在 `origin/main` 上已是截断值（同形、同日、同一作者）。
   **判据**：凡是往台账写含 `#`、`:` + 空格、或引用 PR 编号的文字，写完必须
   `yaml.safe_load` 后**打印该字段的解析值**，而不是只断言「能 parse」。
7. **heredoc 脚本是整体编译的，一句语法错 ⇒ 前面的写盘也没跑。** 本轮一条 `IndentationError`
   让已经写在脚本前半段的 `write_text` 替换整段作废，而我一度以为替换生效了。
   **判据**：这类「改 + 断言」合体的脚本，改完再独立跑一次 `count(新串) == 1` 的复核，
   不要信同一个脚本自己的成功输出。
