# BET-Y2Q4-T10-238 retro — 把「首跑必绿」放大成「每次必绿」的那半边修掉

台账：`docs/plans/3y-bet-ledger.yaml` `BET-Y2Q4-T10-238`
契约：`docs/superpowers/specs/2026-10-09-evidence-freshness-reader-plane.md`（1.0.0 → 1.1.0）
Receipt：`docs/reports/2026-10-09-evidence-freshness-reader-plane-closeout.md`

## 1 intended — 本来打算做什么

ADR-0456 两根收敛（B1→B5）的收尾审计里，`check-evidence-freshness` 是唯一一条**读者**还按
`__file__` 反推检出根的门禁。写侧 `evidence-smoke.py:111 _output_dir()` 在调用时刻按
`state_root()` 落盘，读者在 import 时刻按检出树算目录 —— 声明 profile 后两者永远不在一棵树上，
于是读者**每次**都看不见写者的产物，每次都掉进生成支路，而生成支路只赋分不比分。
本 BET 的 ISC 形状（spec §2）：读侧改同形、生成不豁免分数、分裂要显形成一条 violation、
未声明 profile 逐字节等于历史、检测器自证、CI 必须点名这个平面。

## 2 happened — 实际发生了什么

- 读侧根改走 `repo_root.state_root()`（调用时刻）；脚本路径与 cwd 留 `code_root()`；
  子进程**不传 `env=`**，profile 靠继承传下去 —— 这条与 `bin/compass_radar.py:482` 是同族沉默契约。
- 新增 `evidence_unreadable`：生成 rc=0 且返回合法 JSON、但读路径上没有那份产物 ⇒ `ok=false`。
  原来这里静默 PASS，正是本 BET 要修的洞。
- 用例 10 条落 `tests/unit/`，其中两条是装置自证：注入违规形状当场点名、冻结的改造前副本仍带缺陷。
- 把 `tests/unit/**` 接进 CI：`.github/workflows/governance-check.yml` `interface-check` 的 pytest argv。
  这不是可选项 —— 该 job 是显式文件白名单，`tests/unit` 不在任何白名单里，未点名即不算交付。
- 合并后重测暴露 **ISC-6**：`age_days=-1`。`main()` 在运行开始拍 `now`，生成支路落盘晚于它，
  `(now - mtime).days` 对负 `timedelta` 向下取整。修法把时钟移到读取时刻。
  **这条不可能由变异对照发现**：改造前副本在该支路硬写 0，所以「绿」和「对」在这里第一次分开。
- 两处自己的装置误差，都在下结论前被抓出并修正：
  ① 判据-8 首次 `identical=false` —— 我把带 `grep -n` 行号前缀的一侧和裸 `grep` 的一侧相比；
  ② 只读 `jobs` 键时把 `KeyError: 'governance'` 当成结构问题，实际 job 名是 `interface-check`。

## 3 changed — 改变了什么

| 维度 | before | after |
|---|---|---|
| 读者解析根的时机 | import 时刻 `__file__` 反推 | 调用时刻 `state_root()` |
| 生成支路 | 只赋分，不比 `MIN_SCORE`；`age_days` 硬写 0 | 与读支路同一套两把尺；龄在读取时刻测 |
| 写者读者不同树 | 静默 PASS | `evidence_unreadable` 一条判据 |
| `tests/unit` 平面 | CI 永远看不见 | `interface-check` argv 点名，差分 +9 证其非空转 |
| 未声明 profile | 历史行为 | 逐字节相同（`equals_checkout_path=true`） |

副作用面：本地门禁里 `check-evidence-freshness` 从「结构上永不红」变成真能红 ——
它此前一直在给自己发绿牌，只是没人需要它红过。

## 4 lessons — 固化什么

1. **同形才是同树**：读者与写者的目录表达式必须逐表达式相同**且在调用时刻求值**。
   字符串相等不算 —— 两侧写法（`parents[2]` vs `state_root()`）在默认根下能巧合相等，
   声明 profile 那一刻就分家，且没有任何测试会红。
2. **去掉假绿之后必须重测真实读数**，不能只信「用例全绿」。本轮的 `-1` 只存在于真实
   profile 树的第一次运行里；用例覆盖的是我预先想到的形状，装置误差和新增形状都在想之外。
3. **「CI 跑了我的用例」要有正面证据**：`-q` 不打印用例名，所以用 `--collect-only` 做
   含/不含该文件的**差分**（217 vs 208 = +9）。200 与「job 绿」都不证明文件不是空转。
4. **两侧对拍必须同装置**：`grep -n` 的行号前缀足以把「完全相同」测成「不同」。
   凡「两次读数不一样」，先疑装置，再疑被测对象。
5. **门禁的并集读法不是交付执行面**：`--scope files` 会把多 lane 文件并成一次
   `change-lane-check`，那必然 mixed lanes；真实执行面是 pre-commit 的 `--staged` 逐 commit。
   要用并集读数当结论，先在**已合并**的历史 commit 上跑同一并集，看它是否也红。
6. **squash-merge 后的二次交付走新分支**：GitHub 删了 head 分支，往同名分支再 push 会把整条
   旧 stack 复活成 PR 内容。本轮从 `origin/main` 起 `agent/governance-agent/t10-238-closeout`。
7. **spec 演进时，约束力靠 digest 重绑，不靠改台账措辞**：`done_when` / `verify` 是 WorkPacket
   投影字段，claim 后改动会让后续 claim 报 `WORK_PACKET_SOURCE_DRIFT`，而 `refresh-packet`
   又要求新 ledger+spec 已在 `origin/main` —— 新建/演进一轮内没有合法改法。
   把新判据写进 spec 并升 `spec_version` + 重算 `content_digest` 才是本轮能落地的承载方式。
