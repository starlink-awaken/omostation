# BET-Y1Q3-T10-23 retro

## Outcome

Implemented a read-only consumer audit with stable `documents.consumer-audit.v1`
output. It detects active cron, LaunchAgent, Scheduled skill, and domain gateway
references without executing them or writing to Documents. The implementation is
in `lib/documents_consumer_audit.py` and reuses the existing
`documents-domain-owner-job.py consumer-audit` entrypoint so the bin surface does
not grow.

## Evidence

- RED: the focused test initially failed because the audit entrypoint did not
  exist.
- GREEN: `uv run --with pyyaml --with pytest python -m pytest
  tests/test_documents_consumer_audit.py -q` — 3 passed.
- Ruff passed for the implementation and tests.
- Live scan found 191 active consumers and 12 unmatched references; evidence was
  written under the Workspace run evidence directory.
- `python3 bin/ssot/script-registry.py validate` passed with 499 registered
  scripts after the latest-main `auto-sync-submodules.sh` orphan was registered.

## Corrections made during implementation

- Added a direct crontab snapshot path so live reads do not require a temporary
  generated source file.
- Excluded disabled/archived LaunchAgents and non-command plist fields to avoid
  treating log paths as consumers.
- Restricted domain-gateway parsing to executable-looking fragments and ignored
  ordinary Markdown/npm references.
- Superseded one workflow run after its WorkPacket changed, then started a clean
  run with the final registry surface.

## Follow-up

The audit correctly prevents a premature cutover. Resolve the 12 unmatched
references and establish parity for the 9 active cron consumers before changing
crontab, LaunchAgent, or Documents files. Physical migration requires a separate
danger-gated, reversible operation with before/after fingerprints.
