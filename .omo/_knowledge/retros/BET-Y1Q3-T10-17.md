# BET-Y1Q3-T10-17 复盘

## 北极星

把 sediment 草稿与聚合 retro 的五问从「全空」升级为「确定性骨架已填 + 语义项待完善」的混合路径，不引入 LLM。此前 502 篇 sediment 草稿的五问字段全部留空——草稿只沉淀了事件原文，未做任何结构化的「计划 vs 实际 / 结果与证据 / 失败根因 / 指标」提炼，聚合 retro 也无法回答「这次运行到底发生了什么、成败如何」。

## 做了什么

- **`omo/resident/ledger_trace.py`（新增）**：`iter_run_sequences` 逐行读统一事件流 `.omo/_knowledge/workflow-mesh/events.jsonl`，按 `workflow_run_id`/`trace_id` 聚合为有序事件序列（缺归属跳过）；`extract_deterministic_five_q` 确定性提取可确定骨架——objective（首个 WorkflowRequested 的 payload）/ steps（step 事件去重序列）/ outcome（终态 ok/status/evidence_count）/ failure（StepFailed/WorkflowFailed 的 step_name+error）/ metrics（event_count+duration_s）
- **`promote.py`**：`--fill-five-q`（默认 true）对主题 retro 填入确定性骨架，关键发现/交接建议保持空 checkbox 人工兜底，`--json` 报告含 `five_q_filled` 计数
- **`sediment.py`**：`_payload_summary_lines` 把当前事件自带 payload 的可确定字段（objective/error/status/evidence_count）渲染为草稿 body 内嵌摘要段，不读事件流、不覆盖存量（幂等）
- **`cli.py`**：`resident promote` 子命令入口 + `--json` 骨架输出供运营 agent 完善
- **测试**：新增 test_ledger_trace.py / test_resident_promote_five_q.py，12 单测全绿
- **真实链路验证**：813 个 run 序列全量索引成功；对真实 `governance-state-mutation` run 提取出完整五问骨架（objective/steps=[execute]/outcome blocked/error=workflow failed/metrics 1043s）；`promote --fill-five-q --dry-run` 扫描 502 草稿 → 14 主题全填骨架（five_q_filled=14），并输出 failure_breakdown（387 runs / 115 failures / failure_rate 22.9% / StepFailed 主导）

## 没做什么

- 不引入 LLM / 不自动撰写语义项（关键发现/交接建议/净增减的语义判断留运营 agent/人工）
- 不重写存量 508 篇草稿（幂等不覆盖，存量经 promote 追溯在 retro 层面获得骨架）
- 不新增事件类型 / 不改 events.jsonl schema / 不改 daemon 路由
- 不扩展五问定义（沿用现有 5 项）

## 教训

- **两套事件流易混**：`.omo/_delivery/agent-workflows/events.jsonl`（字段 `run_id`，agent-workflow 自身事件）与 `.omo/_knowledge/workflow-mesh/events.jsonl`（字段 `workflow_run_id`/`trace_id`，workflow-mesh 统一事件流）字段与事件类型完全不同。ledger_trace 消费的是后者；喂错文件会静默返回空 dict（0 序列），须先核对事件格式再断言验证结果。
- **确定性提取的价值在于可证伪**：outcome/failure/metrics 全部来自事件流真实字段，不编造——这保证了 retro 骨架可审计，语义项留空不假装填了。
- **evidence 引用须主仓化**：升 done 的 completion_evidence 引用必须落在 git ls-files 已跟踪文件（代码/测试/attestation/retro），不可指向子模块文件或 gitignored 运行时产物（CI 无 submodules checkout，receipt://projects/omo/* 会 MISSING → derived=blocked → gate 硬失败）。

## 交接给下一个 agent

- 五问语义项（关键发现/交接建议/净增减）仍全空，运营 agent/人工可基于 `resident promote --fill-five-q --json` 输出的确定性骨架补填语义判断
- failure_breakdown 显示 failure_rate 22.9%（115/387），StepFailed 主导——可作为后续「失败根因自动归类」或「高频失败 run 优先人工复盘」的输入信号
- 真实链路验证产物（events.jsonl 提取结果、promote dry-run 报告）以统一事件流 `.omo/_knowledge/workflow-mesh/events.jsonl` 为准
