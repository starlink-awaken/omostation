# BET-Y2Q2-T10-153 retrospective

## Q1 Actual time versus appetite

Implementation and focused verification consumed roughly half of the one-day
appetite; managed-clone and publication overhead were outside the engineering
appetite.

## Q2 Done-when evidence

- The external-root registry uses schema v1 and fails closed for bad IDs,
  symlinks, non-directories, non-git roots, Workspace-contained roots, and
  duplicate IDs.
- OMO normalizes admitted external files to `external/<id>/<relative-path>`;
  `bin/plan/bet-ledger.py` projects WorkPacket surfaces through the same map.
- The Zhixing dashboard root is admitted only for JS and Python implementation
  surfaces; the registry grants no root-level or arbitrary-home access.
- Focused OMO result: `tests/test_external_write_root_claims.py` and
  `tests/test_workflow_attribution.py` = 16 passed. Ledger lint and default
  governance gates must remain green before merge.

## Q3 Plan-versus-facts

The first implementation run was superseded because `bin/plan/bet-ledger.py`
needed to be explicit in the write surfaces. The mapper also exposed that a
root-level `*.js` pattern is required because `**/*.js` does not match a
root-level file.

## Q4 Net change

Added one explicit OMO workflow test file and one registry root; extended OMO
workflow core and Ledger WorkPacket mapping. No rules, ADRs, or scripts were
removed. The change is justified because it closes an unsafe incentive to edit
external surfaces without claims.

## Q5 Next agent

Use `external/<root-id>/<relative-path>` in claims. Do not add a root without a
local `.git`, explicit patterns, and a real directory; Claims Authority v2
activation and arbitrary-home access remain out of scope.
