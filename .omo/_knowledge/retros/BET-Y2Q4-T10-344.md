# BET-Y2Q4-T10-344 复盘 — mini Cron 作用域识别现场主机别名

## 1. 意图（intended）

按 spec `docs/superpowers/specs/2026-11-10-cron-mini-host-alias-task-eef1cedc.md`：同一台 mini 在现场有
`mini` 与 `Mac-mini` 两个名字，编译器与安装预览必须用同一个主机作用域，在两个别名下各选中一次既有看护
条目 `work-agent-respire-mbp-watchdog`；只改三路径（`.omo/cron/registry.yaml` + 两个测试模块），
离线验收 7 组主机组合，保持 launchd 段、命令、频率、解释器不变。

## 2. 实况（happened）

**代码早已在 main，台账却停在 `pending`。** `git log --oneline -S … -- .omo/cron/registry.yaml` 直接命中
`d284efcaa fix(cron): 识别 Mac-mini 看护主机别名（BET-Y2Q4-T10-344） (#5226)`，其 diff 只动两行
（`hosts: [mini]` ⇒ `hosts: [mini, Mac-mini]` + 一行注释）与两个测试模块。也就是说 PR 合并这一步在
2026-11-10 就做完了，缺的只是「独立验证 + 台账收口」。若不做这步溯源，本次极可能把 #5226 重做一遍
—— 这正是 PITFALL-GAT-006 的反向形态（不是 main 缺，是台账落后于 main）。

**spec 枚举 7 组，落地矩阵只有 6 组。** spec 的离线验收写「原生 `Mac-mini`、`mini`、`mbp`、未知主机，
以及 `Mac-mini` 被显式覆盖成 `mbp` 或 `mini`、未知主机被显式覆盖成 `mini`」= 4 + 3 = 7 组；
`test_host_scope_excludes_other_hosts_jobs` 的 `cases` 只有 6 条，缺 `("Mac-mini", "mini", 1)`。
没有任何守卫能发现「少一组」，所以缩水是静默的。独立七组回放（不经 pytest，直调
`bin/scheduler-compile.py:compile_crontab` 与 `bin/ops/install-cron-plane.py:_compiled_lines`）7/7 通过，
证明缺的是**用例枚举**而不是**行为**。

**阶段边界与工作流链互相咬住。** 本 BET 的 `non_goals` 明写「不执行…提交、打标签、合并、复盘写入或
BET 完成」，而 `agent-workflow.py closeout` 的 vision→retro 链硬性要求
`.omo/_knowledge/retros/BET-Y2Q4-T10-344.md` 存在才允许 `--status ok`。两者同时成立时，该 run 只能以
`blocked` 收口（20261122T132900Z-bet-execution-c68d0894 就是这么留的，verify_ok=false 如实入账）。
owner 2026-11-23 明确授权「提交/合并/复盘/收口」后才解除。

**`write_surfaces` 不含台账与 retro ⇒ BET 无法自收口。** claim 的作用域直接取自台账条目的
`write_surfaces`（`bin/plan/bet-ledger.py:2410-2416`），本条只有三路径，所以
`claim … --path docs/plans/3y-bet-ledger.yaml` 与 `--path .omo/_knowledge/retros/…` 都报
`WORK_PACKET_SCOPE_MISMATCH`；`--surface` 更是明写「not modeled by scope.write_surfaces」。
对照 T10-345 / T10-346 两条的 `write_surfaces` 都把「台账自身 + retro + closeout 收据」列进去了 ——
本条是唯一没有把收口面纳入作用域的，于是收口必然越界。这是**立案口径缺陷**，不是执行侧偷懒。

## 4. 教训（lessons）

1. **「PR 合并」不等于「BET 收口」，台账落后于 main 会让下一个 agent 重做已完成的工作。** 判据固化为动手前一条命令：
   `git log --oneline -S '<目标行为的关键行>' -- <path>`，命中即先读那个 commit，再决定是做增量还是做收口。
2. **spec 里枚举的用例数必须有同源的组数守卫。** 「七组」写在 spec、矩阵只有 6 条且无断言，就是静默缩水；
   固化形态 = `assert len(cases) == N` + 一次「删一条用例必须转红」的变异自证。与 docs/pitfalls.md
   「检查的扫描面要等于被管面」「判据口径要与契约名同源」同族，不新增条目。
3. **立案时必须把收口面写进 `write_surfaces`。** 凡 `retro: required` 的 BET，作用域至少要含
   台账自身与 retro 路径，否则 claim 与作用域校验互相死锁，只能靠越界或 `blocked` 收场。
   反向教训：`non_goals` 若禁「复盘写入」，就不要同时要求该 run 能 `--status ok`。
4. **run 的活性靠 heartbeat 维持，长门禁期间会被并发方收走**（同 BET-Y2Q4-T10-347 §3 记录，此处只登记复现，
   不重复条目）。
