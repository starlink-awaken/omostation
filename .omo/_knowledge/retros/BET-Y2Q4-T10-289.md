# Retro — BET-Y2Q4-T10-289 `.omo/_knowledge` 根归类裁决

## 1. 本意（intended）

`.omo/_knowledge` 同时被四个来源归类，而它们互不知情：尺 A 把若干族登记成 **state 根**写面、尺 B 按
marker 前缀把它整串**排除**在 pin-gate 之外、`.gitignore` 对其中三个面既**跟踪**又**忽略**、`bin/` 侧
62 个站点把同一目录钉在**检出根**上读。spec §3 给了判别量（以面自己的字节来源定权威根），要求逐面裁决、
写进 ADR-0456 addendum，并把 pin-gate 的排除面由「按 marker」改成「按族」。

## 2. 实际发生（happened）

## 3. 偏离（changed）

**一条实质偏离，且在台账里可复核**：`goal` 与 spec AC-03 第三列要求「收敛 13 个具体族读者中的 10 处模块级常量
（`bin/**`）改调用时刻解析」，但本 BET 的 `write_surfaces` **不含任何 `bin/` 路径**，`done_when` 四条也
**没有一条**是这次迁移。所以本轮按 packet 声明的写面交付 = addendum 给出 18 处读者的分流与修法（含 3 处写者
这一最尖形状：写者往 ignored 面的检出副本里写，而尺 A 早已把同族登记到 state 根 ⇒ 声明 profile 的机器上同族
产物分池，且没有任何测试会红），**`bin/` 侧一行未改**。

这不是偷懒而是准入：WorkPacket 的 `scope.write_surfaces` 是授权边界（AGENTS.md §1.4），擅自扩面等于把
principal 的 gate 变成事后通知。需要一条**新的 BET** 承接这次迁移，且它的 spec 必须把 addendum §4 的三分类
（纯读 6 / 遍历读 1 / 写 3 + 函数内 3 + 容器 5）逐类写成 done_when，否则下一次仍然会裁而不改。

另一条同类：AC-04 的三个冲突面处置全部改跟踪面，spec 自己就要求**另行授权**，本轮一条没动（`signals` 的裁决
方向已定，执行仍等授权）。

## 4. 教训（lessons）

1. **判别量的行数就是它的适用边界**：三行「穷尽」的判别量被一个实测面否证（`tracked==0` 且未 ignore）。
   凡是写成表格的分类规则，收尾要问「有没有一格是空的、而现实中存在落在那格的对象」。
2. **「族表 vs 跟踪性分叉」不能就地裁**：`dispatches` 那处如果顺手按 trackedness 改，就把「扫单测残留」这个
   读者的语义改成扫一棵不写它的树 —— 两棵树在此不等价。登记为 `_truth` 面自己的后续项比当场拍板便宜。
3. **反「按构造就绿」要钉在桶成员上**：闭合性判据的负例如果压根不进待判桶，那条 not-in 断言是空的。
   本轮修法是先断言「被排除的站点确实出现在 `scan_writers(...)` 的 `bare_inline` 里」，排除才归功于锚点判据。
   同轮第一次探针就是这样假过一回：`state_root.__wrapped__()` 的 AST dump 仍含子串 `state_root`，
   于是 `_STATE_MARKERS` 子串匹配把负例判成正例 —— **负例必须绑到语义上真的另一种根**（这里换成 `code_root()`）。
4. **`grep -rEn ... | grep -c` 的两段过滤词必须都能在对象实际文本上命中一次**：本轮 `scan_checkout_pinned_sites`
   的探测又一次栽在传参上（它内部自己拼 `bin`，外部再传 `<root>/bin` ⇒ 扫到空目录、读数 0，与「没有违规」
   逐字同形）。判据跑出的 0 一律要问「装置命中过吗」，用一次正例先证明尺会响。
5. **混 lane 的 commit 会被 `change-lane-check` 拦**：`code` / `governance_state` / `docs_data` 三面同 commit
   当场 FAIL。正解是按 lane 拆 commit（squash 合并不受影响），而不是拿 `AGENT_WORKFLOW_ALLOWED_LANES` 绕过 ——
   该 env 是给 workflow 声明 `allowed_lanes` 用的，本 workflow 声明的是 `[code, governance_code, config]`，
   用它放行等于改判据。
6. **打印证据时截断，会自己造出一个错误的结论**：真实树探针里我把命中列表截成 `v[:2]` 打印，于是
   「`journey-states` 只出现在 `.subtrees` 一侧」看起来有实测支撑；实际是该面有 4 条命中（两棵树各 2 条），
   截断把另一侧的两条抹掉了。分树复扫（`OMO_SRC` 与 `.subtrees/omo/src/omo` 各跑一次）证明两侧读数
   **逐字节相同**，差异根本不存在。这是 AGENTS.md §7「判据报警先 print 原始行」的**镜像面** ——
   那次错在没打原始行，这次错在把原始行截了。纪律：要据此下结论的打印，要么打全量，要么
   `len()` 与全量至少各打一次；addendum §6 末段因此把「面计数」与「站点计数」分开写，并注明站点数按单棵树口径。
7. **squash 合并出来的 main commit 是单亲的，回滚命令不能照抄 merge commit 的 `-m 1`**（收口腿实测）：
   `git log -1 --format='%p' e2357d7e7` 只给出 `8f04e272d`，所以回滚是 `git revert e2357d7e7`；
   而分支上那 4 个 commit（`10ec4410b`/`1fbd5d1a7`/`9029d7f95`/`465116640`）在 squash 后**不在** `origin/main`
   的祖先图里 —— 收据里引用它们必须写成「分支上的按 lane 拆分」，不能写成 main 上的可达项。
