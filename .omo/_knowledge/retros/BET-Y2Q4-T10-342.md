# Retro — BET-Y2Q4-T10-342

## 1. 意图（intended）

T10-341 retro §4 第三条登记的第三种形状：对方 run 记录仍 `status: active`，但它 advertise 的那条路径
**锁对象已不在盘上**。`lock_scopes_past_expiry()` 只枚举存在的文件，于是这类 scope 既拿不到过期豁免，
`--force` 接管也被拒 —— 一条没有活持有者的历史 claim 永久封锁该路径，且三条自愈通道
（release 只 unlink 自己 run_id 的锁 / prune 只遍历存在的文件 / 对方 closeout 需要那个早已消失的会话）
全部够不着。本轮意图：补上这一判据面，并让逃生口**可达**，同时不许把 T10-292 已交付的
fail-closed 宽度（契约 2）改窄一毫米。

## 2. 实际发生（happened）

判据面补 `lock_scope_object_present(lock_dir, scope)`：只问「这个 scope 现在有没有对象挂着」，
不问 TTL 不问可读性。谓词在 `expired_lock_scopes` 之后再问一次缺席，且**只对 `force_lock=True` 放行**；
普通 claim 仍拒，但报错文本点名「缺席 + 无活持有者 + --force 是退出路径」，不再是与「未过期」
一字不差的同一句话。

放行判据的依据是一条顺序 invariant，而不是直觉：`claim_run()` 里 `acquire_locks()` 先于 `write_run()`，
且记录写入失败会回滚刚建的锁。所以「记录里 advertise 这条路径」蕴含「claim 当时锁存在」，
今天的缺席只能是事后消失（release / prune / 手工 unlink），即没有活持有者。

改动 5 处新增用例 + 1 处 `_claim_as_mine` 转发 `force_lock`，`tests/test_workflow_locks.py` 58 → **65 passed**；
变异对照按改法分别记读数：摘掉缺席分支 → 2 红；豁免不附 `force_lock` 条件 → 2 红；
探测退回 `Path.is_file()` → 1 红。第三组是本轮最要紧的一组 —— `is_file()` 把 `OSError` 吞成 `False`，
于是「不可探测」会冒充「无持有者」，而那条 `except OSError: return True` 变成永不执行的死分支：
写第一版时正是这个形状，红 1 条才证明 fail-closed 宽度面是承重的。

## 3. 改变的东西（changed）

**认知面**：「不可证明过期」在谓词里不是一个原子结论，它有两种成因 —— 有对象但读不出，
和根本没有对象。把它们折成一个结论，就是把自己交付的那条路径永久锁死；这是「两种缺席原因在输出里
同形」在协调平面的实例，与 AGENTS.md §7「解析失败退回空」同族。

**判据面**：逃生口的可达性本身需要一条用例（改动前后 `--force` 读数从「相同」变「不同」）。
本轮把它写成 live canary 而不是只在单测里断言布尔值，因为缺陷的真实形态是「两条命令给出同一句话」。

**流程面**：`change-lane-check` 的 `ALLOWED_COMBOS` 含 `{docs, docs_data}` 但不含与
`submodule_pointer` 的任何组合，所以「铸 BET + bump omo」必须拆两个 commit（squash 后历史看起来仍是一个
commit，容易被误读成「一次就能交」）。本轮第一次 commit 被当场挡住，按 lane 拆开即过。

## 4. 教训（lessons）

- **引用编号前先读注册表。** 本轮把 `PITFALL-COO-009` 写进了用例 docstring 并推了上去，
  而 `coordination` 目录实测只有 COO-002…COO-008 —— 幽灵编号比不引用更糟，它伪造溯源。
  判据：落笔前 `ls` 一次那个目录或 `rg -c` 那个 id；修法是按 COO-008 的 `solution`
  把它认成「同一条谓词缺口的第三形」（commit `ac20a93`），而不是去新建一条登记 ——
  注册表不在本 BET 的 `write_surfaces` 里，扩面需要另一次授权。

- **改一行判据面时，先问「这一分支是不是可达的」。** `Path.is_file()` 与 `stat()` 的差别只在
  「探测本身失败」这一条分支上，而那条分支按 `is_file()` 写法**永不执行**。这类形状的特征就是
  「没有任何测试会红」，本轮靠变异对照（c）才把它变成一条会红的断言。判据：新增 fail-closed 分支后，
  专门变异「让失败原因消失」的那一行，而不是只变异放行条件。

- **豁免的粒度要写成 per-scope，且要有用例钉住它。** 同一次实机复现里，被点名的 run 有 3 条 claim 路径、
  盘上只剩 2 把且均已过期：如果豁免按 run 生效，一条缺席就会把整个 run 的多条路径一起放行。
  用例 `test_takeover_exemption_is_per_scope_not_per_run` 同时请求两条（一条锁在且 live）时必须整体仍拒。

- **standalone clone 的根深度会造成与代码无关的红。** `tests/test_workflow_claims_authority_bridge.py::
  test_hard_run_digest_unchanged_by_binding_record` 在本 omo 克隆里红，根因是
  `omo.workflow.core` 用 `parents[5]` 反推 workspace 根 —— omo 作为独立仓检出时不在 `projects/omo` 下，
  该值落到 `/Users`，于是 `.omo/_delivery/agent-workflows/locks` 解析成 `/Users/.omo/…`。
  基线复算（把三个文件退回后同装置重跑）读数一字不差，才敢定它为预存装置缺陷而不是回归；
  它需要单独处置（把根交给 env 而不是 `__file__` 反推），不在本轮范围。

- **台账块尾要认两类顶格边界，`bets:` 后面跟的不是 `- `。** T10-341 retro 里那条「块边界 = 下一个顶格
  `- `」只解决了一半：`bets:` 是 `campaigns:` 之前最后一个列表，所以本轮的收口脚本按那一条例定边界
  会把 `campaigns:` 与其首个条目 `- id: CMP-W0-PORTFOLIO-TRUST` 一起吞进块内，再按「下一个 2 空格键」
  定位子块尾时正好停在 `  max_parallel_writers:` —— 结果是**删掉两行别人的顶层内容**而摘要断言全绿
  （它不覆盖被删的段）。正解是边界取 `min(下一个顶格 "- ", 下一个顶格 "key:")`，并且写回后除摘要之外
  还要断言顶层键序列相等、**其余 589 条 bet 逐字节未变**。判据：动台账前先问「目标块之后第一个顶格行
  长什么样」（`rg -n "^[a-zA-Z_][a-zA-Z0-9_]*:" docs/plans/3y-bet-ledger.yaml`），不要假设列表尾巴是 `- `。

- **抄邻居 frontmatter 的判据是「那条路径没有告警」，不是「它是同批交付」。** 本轮照 T10-341 抄
  `status: completed` + `lifecycle: record`，同一份内容在 T10-341 的路径上 `warnings: 0`（已被基线吸收），
  在**新文件**上是 2 条未基线告警 —— 而 `--no-new-warnings` 把未基线告警计入 error。仓内惯例实测
  637 份 retro 里 `lifecycle: history` 占 623、`status: active/archived` 占 613，`completed`/`record`
  是 3 份离群。改成 `active`/`history` 后同一命令读到 `warnings: 0`。判据：新跟踪文档落盘后先按
  `doc-governance-check.py --scope workspace --files <新文件> --json` 读到 `warnings: 0` 再提交，
  并且要顺手对**邻居同值**跑一次 —— 邻居 0、自己 N，差的就是基线而不是规则。
