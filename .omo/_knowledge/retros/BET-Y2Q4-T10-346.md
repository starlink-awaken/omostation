# Retro — BET-Y2Q4-T10-346

## 1. 意图（intended）

`AGENTS.md` §7 把「条首短语」当寻址键用（明文写着「跨处引用一律按条首短语定位，不要按序号」），
但索引写的常常不是正文条目的条首原文 —— 键指向不存在的位置，且**零检测器**：没有任何治理脚本读这个
文件对。本 BET 要在不改 `docs/pitfalls.md` 正文的前提下，把索引改到字面可命中，并装一道门禁把命中率钉住，
advisory 到 2026-12-12 转阻断（沿用 ADR-0457 三段式）。

刻意的边界：只查「索引→正文」单方向（反向会把索引当全量目录，几百条红）；提取式只认 `「…」`；
解析范围限 §7 速查表单元格；不为让 gate 绿引入模糊匹配。

## 2. 实况（happened）

**量出来的失配**：`b97281171` 上 `total=45 / dead=16`（36%），三条最典型的分别是反引号被吃掉、
中文引导语被塞进短语、以及索引写了改写后的近义句。收口时在合并后的 main 上重跑 ⇒ `dead=0`，
`docs/pitfalls.md` 字节数两侧都是 191252 —— 「只动索引」这条边界守住了，可证伪。

**交付被上游打断一次**：第一次交付（#5285）与并发落地的 #5284 在 `AGENTS.md` 上 `CONFLICTING`。
本仓禁止用 rebase/merge/pull 吸收上游，也没有可复用的 successor 机制，于是整条重做到新 base ——
一次 claim、九次 commit、一个 PR 的成本，全花在「同一文件两个会话都改了 §7」。

**我自己踩的两处，都是「声明≠执行」**：
① 第一版把新 gate 写进 `gac-local-gate.py` 的 `DEFAULT_POLICY`。该文件 `POLICY = load_sgf_policy() or
DEFAULT_POLICY`，真实策略来自 ecos 子模块，回退副本永不生效 —— 写进去等于没接线。判据不是读文本位置猜的
（我先用「行号 251 > DEFAULT_POLICY 起点」这种启发式自洽了一次，是错的），而是 `importlib` 加载执行器后
直接问 `GATES_LIST`：`RUNTIME_GATES 90`、我的 gate 在、`gate-detail` 不在。
② 一个新脚本要在**两处**登记才不红：`script_baseline`（741→742）与 `bin/_registry/scripts/**`。
只补前者时 `script-registry-validate` 把本地门禁整体拦停。两处同值（validate 报 742）反而是最省事的互证。

**编排面的三次拦停都是对的**：`WORK_PACKET_SCOPE_MISMATCH` 拦住我想顺手改 `docs/pitfalls.md`；
`WORK_PACKET_SOURCE_DRIFT` 两次拦住「先起 run 再改台账/ spec」的次序；`A2A Path Lock Collision` 拦住
台账路径 —— 持有者是我自己当天上午的工程 run，正确处置是先跑工程腿 closeout 释放锁，不是 `--force-lock`。
另有一条「加 ledger `write_surfaces`」的改动必须在 `start` 之前定稿，否则 claim 全数 drift（本窗口
先起 run 再改台账，只能把那个 run 以 `blocked` 关掉重来）。

**`ledger-safe-insert.py` 的 `total_bets` 重写被我自己造的幻影键劫持**：脚本按正则找顶层 `total_bets:`
定位重写点，而 `meta:` 块物理上排在 `bets:` 列表**之后**（L47905）；我从旧 commit diff 的 `+` 行里
提条目时把 meta 的重写行一起塞进了 bet 条目 ⇒ 「meta.total_bets=593 != len(bets)=594」。
根因是提取方式，不是插入器；用 `yaml.safe_load` 取列表元素重建条目后一次插入干净。

**closeout 才发现的自家判据偏宽**：脚本判 `phrase not in body_text`（正文任意位置的字面子串），
而契约名叫「条首短语」。实测 45 条里 **20 条不是任何条目头的前缀** —— 人按索引 `rg` 会落在正文中段。
这与本仓 2026-11-10 刚固化的「判据描述的是『代码属性』，实现却打在文件全文上」同形，门禁自己复发了。
门禁此刻 advisory、限期前不阻断，所以不构成本 BET 的红灯，但**不能**当「问题已收敛」入账。

## 3. 变更（changed）

- 台账 `write_surfaces` 把收口腿会写的文件先列全（retro、receipt），否则 claim 结构性不可达；
  且该编辑属于「定稿动作」，必须在 `agent-workflow start` 之前完成。
- 判「某 gate 是否真被执行」的唯一可信装置是加载执行器问它的数据结构，不是 grep 它的源码文本；
  同理判「某 source_ref 是否指向真实脚本」要按 basename 全库找第二遍（`check-god-module.py` 在 `bin/ssot/`，
  不在声明的 `bin/gac/`），否则会把「路径写错」误报成「幻影规则」。
- 变异/回放一律在 `git show` blob 造的沙箱里做，不进交付树：本轮 `--strict` 的 rc 翻转与字节还原都在沙箱完成，
  交付树全程未被写过一次。

## 4. 教训（lessons，待 §9.6 另案固化）

1. 「`DEFAULT_POLICY` 不是执行面，本地门禁接线要放 root-owned append 段」——本 BET 实测；
   并案登记 `CR-X2-GATE-DETAIL-CONTRACT` / `CR-X2-CRON-INTERP-EXECUTABILITY` 两条注册未执行。
2. 「新增 `bin/` 脚本有两处登记面（`script_baseline` + `bin/_registry/scripts/**`），两处同值即互证」——本 BET 实测。
3. 「claim 是 ledger/spec 定稿后的最后一步，否则 `WORK_PACKET_SOURCE_DRIFT` 全数拦停」——本窗口两次实测。
4. 「`git submodule update --init` 对『gitdir/HEAD/对象都在但 index 空』的检出静默 no-op，要 `--force`」——本窗口两次实测。
5. 「门禁判据的『命中』口径必须与契约名同源；advisory 期内发现的判据偏宽要如实入账，不并进 `dead=0` 的绿灯里」——closeout 实测。

五条都需要 `docs/pitfalls.md` 与 `AGENTS.md` §7 的写面，不在本 BET 的 9 条 surfaces 内 ⇒ 另案。
