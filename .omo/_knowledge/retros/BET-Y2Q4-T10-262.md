## 1 intended — 原本要发生什么

`bin/mof/gen-service-configs.py --reality-check` 只报「读数」，不报「读的是哪一棵树」。
2026-10-20 同一小时内两次读数差出 5 条幽灵 E2，事后定位是测量根与注册表树不同步 —— 但
输出面本身没有任何字段能自证这件事。B4b 批次 2+ 唯一依赖的「集合相等」检测因此无法在
事后被复核：读到 `e2_undeclared = 5` 时，无法区分「注册表落后」与「检出落后」。

本轮要的是一层**纯观测**的自报基座：`measured_base` 六字段（`registry_file` /
`registry_sha256` / `head` / `origin_main` / `base_state` / `behind_count`），零判定效应
（不进 `findings`、不影响 `ok`），并让「注册表落后」与「检出落后」在 `--json` 输出上可分。

**done_when 全部命中，且第 7 条变异对照是实跑不是推理**：把 C3 用例
`test_stale_base_and_full_base_are_distinguishable_from_output_alone`（
`tests/test_service_registry_reality.py:491`，断言在 `:509`）两侧注册表内容改成一致 →
`1 failed`，失败行正是 `assert (0 == 1)`；`git checkout --` 还原后 32 passed。

**三件计划外的事**：

1. **`measured_base` 的 git 事实必须跟着注册表所在的检出走，而不是跟着传入的 `root` 走。**
   在 worktree 里跑 CLI 时 `workspace()` 解析到 canonical 检出，拿 canonical 的 HEAD 去标注
   worktree 里的注册表 = 一份假证词（它声称"注册表落后 N 个 commit"，而落后的是调用者的树）。
   实现改成从 `registry_path.parent` 做 `git rev-parse --show-toplevel`；证不出一棵树就
   `unknown`，不做兜底猜测。钉住它的两条用例：
   `test_git_facts_follow_the_registry_tree_not_the_passed_root`（`:640`）与
   `test_unprovable_registry_tree_is_unknown_not_the_callers_root`（`:663`）。
   这不是"更严谨"，是本轮唯一让 `measured_base` 有意义的性质 —— 否则它报的是调用者的位置。

2. **台账声明的 pytest 命令在本机跑不起来**，报 `unrecognized arguments: --timeout=300
   --timeout-method=signal (inifile pyproject.toml)`。补 `--with pytest-timeout
   --with pytest-randomly` 后可跑。这是**装置补全**，不是把断言改窄：判据本身一字未动。

3. **`bet-ledger.py complete` 的前置与本 BET 的 non_goal 1 直接相撞。** 它要求
   `merged_reachable_commit` 在本地对象库可达（`bin/plan/bet-ledger.py:1682`），而 squash
   合并后的新 commit 只在远端；不 `fetch` 就 complete 不了，complete 不了就闭不了环。
   处置：**执行了 `git fetch origin main`，并在 receipt §4 逐字披露**，同时给出边界分析
   —— 动的是对象库与 remote-tracking ref，`~/Workspace` 的 main 工作树与 HEAD 一行未动
   （仍在 `fdb106c9f`）。**没有**改 non_goal 的措辞来自证清白；提议后续把 non_goal 1
   重写为「不动任何检出的工作树/HEAD」，由 Principal 裁定。

## 4 lessons — 下一轮该记住什么

1. **自报基座的语义要写"跟着被测量对象"，不是"跟着调用者"。** 任何 provenance 字段，
   一旦它的值来自"当前进程的位置"，它就在测量装置与被测对象之间引入了第二个变量。判据：
   同一份数据在两个不同检出里被读出，provenance 是否跟着**数据**变。这轮差点交付一份
   看起来正确、实际上每次都在描述调用者的字段。

2. **`done_when` 里"变异对照"这一类条款，绿不算交付，实跑的红才算。** 推理"改窄断言当然会红"
   与跑一遍得到 `1 failed` 是两种证据强度，后者才排除"检测器压根没命中"那一类空绿
   （AGENTS.md §7⑧ 同族）。

3. **一个 BET 的 non_goals 可能与交付机制本身矛盾；矛盾要披露，不要改写。** 这条比技术上
   的收获更要紧：改 non_goal 让"合规"变成本机自证，是伪造溯源的轻量形态。正确顺序是
   做必须做的最小动作 → 逐字记下做了什么、没动什么 → 提议措辞修订交给有裁决权的一方。

4. **受控后继（successor branch）是冻结 merge ref 的唯一出口。** `gh run rerun --failed`
   重新检出的是存储的合成 merge commit，base 侧的修复永远救不活一个 stale PR；#4843 的
   教训固化进这里：从当前 `origin/main` 起新分支 + `cherry-pick -x`，前驱关闭并标
   superseded，两份历史都留痕。
