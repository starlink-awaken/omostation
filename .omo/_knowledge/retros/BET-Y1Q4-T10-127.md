# BET-Y1Q4-T10-127 retrospective

## Q1. What was intended?

仓库维护任务 Cron 化：僵尸 worktree 清理、分支 TTL 强制、README 硬编码检测三脚本 + repository-health 周报 + 3 个 cron job。

## Q2. What happened?

PR #3332 合并（0e6d649d），CI 23/23 CLEAN。三脚本各吸收一个近亲旧脚本归档 bin/_archive/（bin/ 配额平衡）：
- prune-zombie-worktrees.py（←gac-worktree-cleanup.sh）：三规则判定 + dirty 保护 + D2 claim 联动——**实测抓到真僵尸 ws-t1069 [no-gitfile]**
- branch-ttl-gate.py（←gac-worktree-prune.sh）：work/+agent/ 双段 TTL（policy 驱动），dry-run 默认
- check-readme-hardcoded.py：**实测抓到 README L171 "12 个 SSOT" 计数漂移**——doc-ssot-contract 的自动哨兵落地；--update-health 生成周报

cron 三行：周一 zombie enforce / 周日 TTL dry-run（观察期后切 enforce）/ 每日 README+周报。

## Q3. What changed during implementation?

- **script-registry 也是派生 SSOT**：加/归档 bin/ 脚本必须 register/注销（626 scripts），漏了会 gac-gate 挡——与 capability-registry drift 同族，Candidate PITFALL。
- **bin-scripts-convergence-manifest 是第三个派生清单**：audit 只看 bin/ 文件存在性不看 action 字段——归档后必须从 manifest 移除条目。
- **T10-128 的命名空间当场吃狗粮**：claim 自动生成 agent/governance-agent/t10-127-cron，第一次 push 用旧 work/ 前缀报 "refspec does not match"。
- **worktree 被并行清理工具回收**：工作面中途消失（分支在共享 .git 无损），worktree add 重建即恢复——worktree 是可再生的，分支才是资产。

## Q4. Lessons (P73 truth-driven)

- **bin/ 配额的隐性成本在派生注册表**：脚本增删的 cascade = script-registry + convergence-manifest + capability-registry（若含 skill）三处同步——"add 1 = delete 1" 的真实工作量是 1+3。
- dry-run 先行 + 观察期切 enforce 是删除类自动化唯一安全姿势（本 BET cron 全按此设计）。
