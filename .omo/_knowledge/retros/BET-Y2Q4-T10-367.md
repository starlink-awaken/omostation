# Retro — BET-Y2Q4-T10-367

## 1. 意图（intended）

`BET-Y2Q4-T10-366` 把「切换 `current` 之后必须让运行中 live server 重新绑定并验收收敛」
补进了 `publish()` / `restore()`, 复盘 §4 留了一条同族残留:

> **同族残留**: `migrate()` 同样切 `current` 但不收敛运行期（一次性迁移路径）。

本轮把这条残留连同它下面的第二层空洞一起收掉 —— **迁移激活的基线 release,
运行期根本绑不了**:

- 基线清单的形态 (`identity_kind=deployment_baseline`, `commit_oid=null`) 被运行期
  身份 helper fail-closed 拒绝 (`release_manifest_source_invalid`);
- 基线 release 里**根本没有身份 helper** —— 部署根
  `~/.local/share/zhixing-dashboard/` 实测无 `release_identity.py`;
- 发布器 `_base_manifest_valid()` 接受的恰恰是运行期必然拒绝的那种清单 ⇒
  两套判定同源不同义。

本轮三件事: ① 让**内容寻址**的部署基线进入身份契约 (可从 release 字节独立重算);
② 迁移基线自带身份 helper, 发布器与运行期判定同源; ③ `migrate()` 接入 T10-366
的运行期契约 (切换前证明可绑定 / 切换后验收收敛 / 收敛不了就回滚)。

## 3. 差距与坑（learned）

1. **「收敛」的目标态本身可能不可达**。T10-366 补的是「切完之后怎么收敛」; 本轮
   补的是更靠前的一层: **切过去的东西运行期绑不了** ⇒ 收敛无从验收。
   **纪律**: 补事务边界时必须同时问「目标态本身合法吗」—— 否则只是把失败推后。
2. **内容寻址身份比 git 身份更可验证, 不是更弱**。git 提交 oid 无法从字节反推
   (只能说「这个提交产生了这些字节」, 需要外部 git 才能验); 内容摘要**可以**从
   字节独立重算 ⇒ 把基线写进身份契约不是放松判据, 是换一种更强的判据。
   **纪律**: 遇到「这不是 git 提交」不要发明新身份种类去糊弄, 要找**可从字节
   重算**的那一种。
3. **发布器与运行期必须同一判定, 否则各自为政**。`_base_manifest_valid()` 曾经
   明确接受运行期必然拒绝的清单 ⇒ 两套判定同源不同义。
   **纪律**: 任何跨进程共享的契约 (清单 / 身份 / 版本号) 只有**一处**定义,
   两侧都引用它; 判据同源不同义是比「没有判据」更坏的形态 —— 它给出虚假的绿。
4. **降级判据必须证明「动作真的发生了」**。初版降级只看「还活着 (200)」⇒
   「重启没生效、旧进程仍在服务」会被当成收敛 (假绿)。加上 pid 变化后,
   「进程确实随迁移重启过」才成立。**纪律**: 降级判据 = 「弱化后的断言」,
   不是「把断言删掉」; 弱化后仍要有一条可观测证据支撑动作已发生。
5. **既有测试文件会在新契约下变成真实机器动作**。`tests/test_zhixing_host_sync_publish.py`
   直接调用真实 `migrate()`, 新增收敛步骤后它会对**本机 live server** 发
   `launchctl kickstart -k` —— 一条「测试写得好」的历史用例, 在新契约下变成机器级
   副作用。**纪律**: 任何会走 launchd / 端口的用例, 装置必须**显式**替换掉机器级
   动作 (launchd / 探针 / 收敛超时), 而不是「碰巧当前不会触发」。
6. **接线钉子必须走真实入口**。核心用例走真实 `migrate()`, 沿用 T10-364 / T10-365 /
   T10-366 的教训 (「测试绕过接线就钉不住接线」)。
