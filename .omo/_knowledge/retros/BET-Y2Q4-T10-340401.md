# BET-Y2Q4-T10-340401 Retro

## Summary

Implemented the canonical shared SceneCard YAML parser and migrated three callers
(review, lifecycle, lineage) to use it. Added comprehensive unit tests covering
single-document, FrontMatter+Body, duplicate keys, state conflicts, and write-back
mirror synchronization. Added caller-level regression tests for the three entry
points. All 42 tests pass.

## Key Decisions

1. **Shared parser location**: `lib/scene_card_document.py`, avoiding duplicate
   parsing logic in `bin/ssot/` scripts.
2. **Mirror write-back semantics**: Only sync frontmatter mirrors that already
   existed with identical values; never create new mirrors. The initial
   implementation compared against the already-updated body value, causing
   shadow→assisted roundtrip failures. Fixed by capturing `original_body_value`
   before mutation and using it for the mirror-detection comparison.
3. **Python 3.9 compatibility**: The Make aggregate gate uses the system Python
   (3.9), not the venv Python (3.14). Replaced `datetime.UTC` with
   `datetime.timezone.utc` in lifecycle script to preserve Make target usability.
4. **Caller-level regression**: The ledger `verify` command requires
   `tests/test_scene_card_parser_callers.py`, which did not exist. Added three
   caller tests covering review promote, lifecycle transition, and lineage
   scan/error propagation, all using synthetic temporary fixtures.

## What Went Well

- Clean separation of parser (pure read) from write-back helpers (mutate-in-place
  with explicit re-parse contract).
- Three callers migrated with minimal code changes; no lifecycle admission rules
  or readiness semantics altered.
- All changes stay within the ledger `write_surfaces` boundary.

## What Needs Attention

- Makefile targets use system Python (3.9); any new code touching
  `bin/ssot/` scripts called from Make must remain 3.9-compatible unless the
  Makefile PYTHON variable is also updated.
- The mirror write-back comparison must use pre-mutation values. A future
  refactoring that inlines `document.body[key] = value` before comparison will
  reintroduce the bug silently.

## Verification Evidence

- 42 tests passed (unit + caller + lifecycle + connector) via ledger verify command.
- Shared parser module loaded from current checkout, not cached or foreign path.
- No production SceneCard, broker, lease, or authority operations performed.
