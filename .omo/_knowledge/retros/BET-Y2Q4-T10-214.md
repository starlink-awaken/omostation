## Q3 教训（按可复用性排序）

1. **"没有 X" 类断言要先搜索全库再写**。我凭"lint 不查摘要"的印象写成"无工具比对"，
   而工具早就在 `bin/ssot/` 且带测试。判据：写"没有 X"之前跑
   `/usr/bin/grep -rl "<X 的语义关键词>" bin/ projects/*/src/`，并读 registry 条目的
   `triggers:` —— **"未接线"和"不存在"是两条不同的债**，前者半小时，后者半个月。
2. **写进持久产物的命令，先逐字跑一遍**（C7）。"看起来对"的 `uv run` 串在三个地方错过：
   缺 `--with pytest`、缺 `--directory`、缺 submodule init。注意 `uv run --with pyyaml python -m pytest`
   在这台机器上**必然**失败 —— pytest 不是默认注入的包。
3. **证据里的数字会在交付过程中过期**。任何 `wc`/`len`/计数一旦写进报告或台账，
   最后一次编辑之后必须重算并重跑；我的报告因此在一次交付链里被反复编辑，每次都要重算台账中指向它的 6 条 receipt 摘要。
4. **台账文本手术必须断言边界形态并回读解析**。对 T10-212 条目段做 `replace` 时我漏掉换行，
   产出 `evidence: {}- id: BET-Y2Q4-T10-212` 与 `campaigns: null- id: BET-Y2Q4-T4-05`，
   `yaml.scanner.ScannerError` line 37918。固化判据：写完后
   `assert out.count("\n- id: <SIBLING>\n")==1` + 全文件 `yaml.safe_load` +
   扫 `[^\n]- id: `（应 0 命中）。台账禁整文件 `yaml.dump`（脚本 docstring 记着它曾损坏过台账）。
5. **生成态会被自己的门禁动作改写**。跑 `gac-local-gate` 把 `.omo/state/system.yaml` 的
   `health_score_evidence_generated_at` 从 09-27 推到 09-29（1 行）。交付前
   `git checkout --` 剔除，判据仍是 `git diff --name-status origin/main..HEAD` 里不该出现
   你没碰过的 `.omo/state/**`（#4346/#4359 同条）。
6. **改 `write_surfaces` 会让已绑定的 work packet 漂移，且只能靠新 run 解**。
   在持有 docs 锁的 active run 上扩面 → 后续 claim 一律
   `WORK_PACKET_SOURCE_DRIFT`（packet 在 start 时从 ledger+spec 编译）。
   合法路径只有：`closeout --status blocked`（释放 docs 锁 + 留痕）→ 对**已扩面**的 ledger
   `start` 后继 run → claim 成功。**不要**用 `--force-lock`/`prune-locks` 绕过：
   前者在 authority 激活后直接 `CLAIM_VERSION_STALE`，后者是清理僵尸锁的，不是清活锁的。
7. **worktree 里的 `.omo/_delivery/agent-workflows` 是指向主工作区的 symlink**（实测
   `.omo/_delivery/agent-workflows -> /Users/…/Workspace/.omo/_delivery/agent-workflows`）。
   两个后果：run 记录无法随 PR 提交（git 报 "beyond a symbolic link"），
   且 `affected-graph.py --output` 拒绝写进含 symlink 的目录
   （`receipt output parent must not contain symlinks`）。可用落点是
   `.omo/_delivery/receipts/`（`_delivery` 本身是真实目录）。
   `--affected-receipt` 必须是 **workspace-relative 且解析后不变 symlink** 的路径，
   `/tmp` 下的收据直接被拒。root 面的 `--changed-projects` 取值是 **`workspace-root`**
   （claim 路径不在 `projects/` 下时映射到它），写 `omo` 会让
   `claimed projects missing from affected graph receipt`。
8. **门禁读数要连同"用什么解释器调的"一起记**。同一棵干净的 worktree，
   `uv run python bin/mof/gen-service-configs.py --validate` 报 1 条 blocking 红
   （`omostation.morning-brief` 的 `interpreter: python3` 经 `shutil.which` 命中 uv 的
   ephemeral build dir，被 `:188` 的 uv 临时路径守卫拒绝），裸 `python3` 同命令报
   `ok: true / 0 violations`，而且 `.tmpXXXX` 每次调用都换一个。**结论：这类红不是仓内事实**，
   判据是"换个调用方式，红还在不在"；只写"gate FAIL"而不写读数方式，就是本 BET 要修的那种证据。
9. **change-lane 的边界由 `ALLOWED_COMBOS` 决定，不是由"是不是一个任务"决定**。
   retro 落在 `governance_state`，而 `governance_state` 参与混合即拒
   （`bin/change-lane-check.py:207`）；`{docs, docs_data}` 则是允许的组合同一条
   （`:19`）。所以台账+报告一个 commit、retro 单独一个 commit，两 commit 各自 lane-clean，
   仍走同一个 PR（squash 后合并成一条）。
10. **"diff 工作树"形态的 verify 命令，合并后必然不可验**。我自己的 `verify[3]`
    （`git diff HEAD --numstat -- <台账>`）在 `main` 上逐字重跑返回空输出 —— 期望只在提交前一刻成立。
    这正是本 BET 判定 T10-212 那类"死锚"的同一种病，却长在我自己的条目上。
    修法：把判据钉到**已落地的 commit**（`git show --numstat <sha> -- <path>`）或改为对已落地内容的
    结构断言；分批交付就一条批次一条判据，别指望一条 cmd 覆盖两批。
11. **条目级 verify 里不要写全局判据**。`lint` 的"no errors"和写死的 bet 计数都是**整仓属性**，
    别人铸一个条目就能把你证伪：实测 main 上 #4564 铸造的 `BET-Y2Q4-T4-06` 让
    `bet-ledger.py lint` 报 **10 条 ERROR**（spec 文件从未落地 + 7 条 receipt ref 不解析，再派生
    `OVERALL_STATE_MISMATCH` / `BET_DONE_REQUIRES_DELIVERY_ACCEPTED`），而本 BET 修的 212/214 各
    **0 条**。判据按 **owner** 收窄："没有 ERROR 行点名我的 BET" + `meta.total_bets == len(bets)`。
    同一条纪律也管持久文档里的读数 —— "合并后复跑"的数字必须标批别，否则下一条 mint 就让某句话变假
    （本批 §2 那句"本 BET 与 T10-213 各 0 条"就是这么过期的，已就地否证并改写）。

## Q4 下一个人该知道什么

- **`BET-Y2Q4-T10-213` 的 5 条 receipt 现在是陈旧的**（钉 `sha256:bd2ed573…`，
  而 PR-3 报告编辑后为 `sha256:15ba278f44b1f…`）。本 BET 不动它 —— T10-212 的
  `circuit_breaker` 把"给别人补 lifecycle evidence"列为停止条件。登记为 G2，接手的人
  照着这两个值改即可，别重算一遍再猜。
- **根因不是"忘了重算"，是 receipt 用可变文档的内容摘要当证据锚**。一份报告被 N 个 BET 引用，
  每次编辑要重算 N×（最多 4）个键，且本地与 CI 零信号。要接这根线，先跑
  `python3 bin/ssot/sync-bet-digests.py --report` 量存量（登记批 1,882 条/329 个 BET，closeout 批
  终态 1,887/330 —— 净增的 5 条就是下面 T10-213 那组），
  再选**按 diff 范围核对**，或把 receipt 钉到 `git://<commit>:<path>`（该脚本本来就跳过
  `git://`，不会制造新比对债）。
- **`sync-bet-digests.py --apply` 是安全的**（只替换 `sha256:[0-9a-f]{64}` 字面量、
  拒冲突替换、`assert_structural_invariants` 禁 bet 数量变化与 status 变更，3 个测试钉住）。
  本批没用它，是因为报告在**同一次交付链里被反复编辑**，逐键重算比让一个 `--apply` 扫全库更可控。
- 复现本批的核对命令（逐键、非整仓）：读台账 → 对每个 `receipt://`/`repo://` 键
  比 `sha256` 与 `shasum -a 256 <file>`。
