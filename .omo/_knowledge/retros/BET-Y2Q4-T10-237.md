# BET-Y2Q4-T10-237 Retro — ADR-0456 G8 镜像面与 Principal 署名裁定收官

## 1. 目标与预期产出

- **背景目标**：解决 2026-10-07 BET-Y2Q4-T10-235 门禁触发的 `service-config-drift`（`com.omostation.zhixing-projection-fullrefresh` 盘上手写 plist 偏离 SSOT 声明）。查明其根因并非生成器缺陷，而是现实面将 driver 内部第 3 步的子进程提成了服务本体，并混入了临时日期路径。
- **结项预期（Spec 6 项判据）**：
  1. **I1 归属有署名（主判据）**：由 Principal（夏明星 xiamingxing）直接签署最终形态裁定（采纳 official publisher driver 形态，180s 周期），杜绝「改窄注册表充当解决」。
  2. **I2 绿由对齐取得**：`gen-service-configs.py --check` rc=0 且 `drift_count=0`，生成器装置未被改窄（`git diff origin/main` 为空）。
  3. **I3 driver 步骤保全**：driver 的 0–2 步（flock 锁防重入、origin 远程仓库校验、`reset --hard origin/main` 洁净同步）由官方 driver 承担。
  4. **I4 注册表摘要对齐**：更新注册表内 `content_digest` 为盘上实际运行文件的 SHA256。
  5. **I5 重叠调度可见留痕**：对 `zhixing-projection-fullrefresh` (180s) 与 `panorama-dashboard-refresh` (240s) 的共存保留只读枚举指令与输出记录。
  6. **I6 临时日期路径清零**：杜绝 `…-runtime-clean-20261008` 等临时路径进入机器级配置。

## 3. 关键架构设计与技术取舍

1. **观察模式 (Observe-Only) 的严谨边界**：
   - 对于外部或专用发布器维护的 plist，注册表通过 `generate: false` + `config_source` + `content_digest` 实行「只观察、防篡改」管理。
   - 避免了生成器强行以通用模板覆盖导致专有解释器参数（如 `-B` 前置参数）或专有环境被抹除的问题。
2. **状态根与运行根归零切道联动**：
   - 借由 B4b Batch 5 终局切道战果，该服务不再依赖 Workspace 源码树，直接基于 `~/.local/opt/omostation` 运行，并将写操作收敛至 `~/.local/state/omostation/prod`，消除了环境污染。

## 4. 失败模式与经验教训

- **失败模式**：在早期的调试过程中，为了快速解决发布刷新频率问题，有人绕过 git 仓与配置生成器，直接在盘上修改 `LaunchAgents/*.plist`，把驱动脚本换成了内层 collector，并写死了当天的调试目录。这种「黑屏热修」导致后来门禁 `service-config-drift` 出现 63 行红字。
- **防线固化**：
  1. 门禁 `service-config-drift` 坚持硬拦截，不放宽比对、不降级为警告，成功阻止了破坏性漂移的隐匿；
  2. 确立「归属先于修复」原则：严禁 agent 未经 Principal 授权单方面修改注册表削足适履。
