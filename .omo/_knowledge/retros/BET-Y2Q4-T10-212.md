## Q1 意图 vs 实际发生了什么

意图是"摘掉 legacy 双写并把三份生成态移出 git"。真正花时间的不是摘库（一个 commit 的事），
而是**摘库之后读取面的账单**：三个生成态一旦离开 git，硬编码 legacy 路径的读取方只剩两种结局
——读到一份无人更新的冻结副本，或什么都读不到。而"读不到"在这仓里**从来不是一个空缺，而是一个结论**：

| 读取方 | 缺失被折算成 | 真实后果 |
|---|---|---|
| `unified-health-score.py` | 运行时轴 `0.0` | 权重 0.10 的假测量拉低 UHS，`--sync` 还把 `0` 写进 `system.yaml::health_score`（实测 42 → 0） |
| `health-predict.py` | 退出码 `1` | cron 面把"没跑过"报成"坏了" |
| `maturity-align.py` | `reconciliation_score = 100.0` | 只剩一个来源时 spread 恒为 0 ⇒ 缺席冒充满分一致性 |
| `omo_doctor.py` | `status: fail` → `return 1` | 新建检出必红 |
| `check-dual-track-purity.py` | 读冻结的根 `BRIEF.md` | 用已废弃的那一份判违规（dual 档实测 rc 1 → 0） |

appetite 1 day；PR-1/PR-2/PR-0 用掉第 1 天，PR-3（读取面 10 个消费者 + 18 条测试 + A/B 夹具）
用掉第 2 天，其中相当一部分烧在**自己造的测量错误**上（见 Q3）。

## Q2 改了什么（机制层面，不是文件清单）

1. **一个表 + 两侧根**：`.omo/_truth/registry/runtime-projections.yaml` 成为读取侧唯一真源。
   `bin/lib/repo_root.py` 新增 `projection_rels` / `projection_read` / `projection_name_for`；
   `projects/omo/src/omo/omo_paths.py` 侧同样收成一张表，并删掉了此前分叉的内联 `STATE_DIR` /
   `CONTROL_DIR` 回退 —— **"两条锚定规则并存"这个形态本身消失了**。
2. **`projection_read` 不判存在性**。它只回答"该读哪个路径"，存在与否由调用方判。这条设计是整个
   BET 的支点：只有把存在性推给调用方，absent 才能不被强制折算成 0 / 1 / fail / 满分。
3. **登记表解析只用标准库**（2/4 缩进扫描，不 import yaml）。不是洁癖：`meta-doctor` 与 cron 用裸
   `python3` 跑，依赖 pyyaml 会在那里 ImportError。逐名与 `yaml.safe_load_all` 的对拍由测试钉住。
4. **两个戳口径 bug**（在 A/B 时才暴露，不是"顺手优化"）：`probe-heartbeat-monitor` 用
   `fromisoformat` 解 `system_health` 的 **epoch 浮点** `last_scan` ⇒ 30 分钟前跑过的巡检报成
   `9999h/48h` 且计入异常（生产实测 rc 1 → 0）；`meta-doctor` 用行扫描找 `"generated_at":`，
   而 JSON 里那个 key 是带引号的 ⇒ 永远匹配不到。同一份证据被两个读取方按两种口径解释，
   与"两个根各自算路"是同一类缺陷。

## Q3 教训（按可复用性排序）

1. **给门禁新增一路信号时，它的解析口径必须同一笔落地。** 我先把 `governance_data` 加进
   `meta-doctor` 心跳，再修 JSON 戳解析 —— 中间态是**我自己造出来的假红**（生产 `stale=1`，
   实际 2.8h 新鲜）。反事实测量留了痕：同一份文件，行扫描口径 `stale=1`、`json.loads` 口径 `stale=0`。
2. **继承来的数字不是证据。** 压缩后的会话笔记写着"12 passed / 453 行 / 72 passed / 192 omo passed"，
   逐项重跑后是 18 / 453 / 943 / 139+1 skipped。凡写进 closeout 的计数，必须是这一轮取到的；
   否则报表一旦与 CI 分歧，损失的是整份报表的可信度。
3. **归因用 `git log -S`，不用记忆。** 报告初稿把 `panorama-collect.py` 去掉 `BRIEF.md` pathspec
   记在 PR-1 头上；实测唯一命中是 PR-2 的 `cf6d4ac78`。台账 done_when 的编号与 spec §4 的编号
   **不是同一套**，本表未列的一条（死规则 `!.omo/state/system_health.yaml`）也得逐条验掉才能置 `done`。
4. **`write_surfaces` 是真边界，不是建议。** 两个文件需要改但不在清单里：
   `tests/unit/test_gate_health_roots.py`（猴补 `check_heartbeats(ws_root)` 的位置参数形态，
   逼我把 profile 解析放进函数体而不是提到 `main()` 的关键字参数）和
   `bin/gac/gac-local-gate.py:653 SNAPSHOT_PATHS`（仍写死三件 legacy，指纹恒空）。
   两处都**记录 + 绕行**，没有越界去改——代价是留了两条明文残留，收益是这轮没有任何一次
   "顺手扩面"需要在 review 时自证清白。
5. **原地 A/B 必须保住目录深度。** 这些脚本用 `__file__` 上溯两层取根，夹具若把 `bin/gac/x.py`
   铺成 `x.py`，before/after 测的就不是同一件事。三档形态里 **fresh 档 = 本机今天的生产形状**
   （canonical 在、legacy 已被 PR-2 摘走），这是让 A/B 有意义的核心：唯一变量是"读哪一档"。
6. **helper 的 ✅ 要复核。** `gac-worktree.sh bump-pointer` 在这个 PASW worktree 里把 gitlink
   **倒退**到 `6bbb908`（它按 `PASW_SUBTREE_DIR` 读的是另一份 omo 检出），照样打印
   "✅ 指针已更新"。squash 合并后指针应钉子仓 main 上的新对象（`e3537ca`，与 `8b0ae0f` 树逐字节相同），
   这样 `merge-base --is-ancestor` 成立且不依赖 agent 分支存活。
7. **`.omo/_delivery/agent-workflows` 是指向规范工作区的 symlink**，`affected-graph.py` 因此拒绝
   把 receipt 写进它（"output parent must not contain symlinks"）。写 `.omo/_delivery/affected-graph/`。
8. **混合暂存不是失败，是 lane 纪律。** 全量暂存时门禁唯一的 hard fail 就是
   `change-lane-check: FAIL mixed lanes=code,docs,governance_code`；一个 PR 拆成 5 笔（omo / code /
   governance_code / docs / submodule_pointer）才是可通过形态。
9. **台账里"顺带治一处既有假红"举的数字，口径是错的。** 它写 `meta-doctor stale_beats 1→2`，
   实测 absent≠stale 那半边是 **PR-1 (#4515)** 就落的（合成 fresh clone 上 before/after 均
   `stale=0 / absent=3`）；本轮真修的是 probe 的 epoch 与 JSON 戳。已作为偏差写进 closeout §7，
   没有为了让 goal 好看而把 PR-1 的账记到 PR-3 上。
10. **`bet-ledger.py complete` 的 D0 前置无法表达"摘库即交付"**（2026-09-29 撞上了才看清）：
    D0 用 `git ls-files --error-unmatch` 逐条要求 `write_surfaces` 在根 index 里，而本 BET 的
    done_when-5 判据恰恰是这三件**不在** index。也就是说：一个成功交付的摘库 BET，会被完成闸
    按其成功的证据判死。绕法不是随手 `--force` —— `--force` 会连 vision→retro 链检
    （`chain_bind.evaluate_complete`）一起跳过，而那条链是本轮真正要证的东西。判据：先用
    `in-process` 跑一遍链检拿到 `ok=True`，再 `complete --force`，并把绕过的只是 D0 这件事写进
    closeout。三条路径**保留**在 `write_surfaces` 里（删掉等于抹掉"本 BET 动过它们"的记录），
    缺口（D0 需识别 gitignored 的删除型交付物）作为后续项登记，不夹带进本轮改闸。
    同一条 lint 里的 `PHANTOM_REPORT_PATH` 检查（非阻断）顺带抓出台账计划期预填的
    `docs/reports/2026-09-28-...-closeout.md` 从未落盘 —— 注册时写下的 receipt 路径要在交付时对齐。
