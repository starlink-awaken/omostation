# BET-Y1Q4-T10-128 retrospective

## Q1. What was intended?

并发 agent 分支命名空间隔离：claim 强制 `agent/{actor}/{session}` 三段式 + 自动清理 >7 天无活动 agent 分支 + D2 branch_occupancy 从 retired 恢复为 conditional active（仅 agent/ 前缀生效）。

## Q2. What happened?

PR #3322 合并（733a28ed），四个单元全部交付并实测：
- **policy**：naming.agent 三段式 + ttl 7d + creators +human；check-branch-naming 新格式过/老格式拒
- **claim**：agent/{actor}/{session} 强制 + D2 branch lock 实测占用成功；残留分支阻断（circuit_breaker）
- **D2**：registry retired → conditional_active；BRANCH_RE 双前缀；cli branch-check 对 work/ 豁免
- **清理**：gac-branch-prune agent/ 段（policy 驱动 TTL 168h）+ D2 claim 联动清除；crontab 每日 dry-run 巡检接线

实测矩阵：新格式 claim ✓ / 不同 actor 同 session 放行（隔离语义）✓ / TTL=0 删除动作 + claim 联动 ✓ / work/ 豁免回归 ✓。

## Q3. What changed during implementation?

- **BET 条目与 policy SSOT 的格式冲突**：done_when 写 `agent/{actor_id}/`（/ 分隔）而 policy 现有 `--` 双段式。以 BET 原文为准改 policy（三段式，actor 一级命名空间显式归属）。
- **D2 恢复比预想深一层**：occupancy 核心逻辑活着，但 `BRANCH_RE = ^work/...$` 在 swarm_discipline.py 核心校验层把新格式拒了（claim 时 D2 恢复立刻"拦住合法分支"）——双侧同步原则（与 T10-03 归档同款教训）的又一实例。
- **#3241 之谜连带破案**：PR 的 interface-check 跑全量 Gatekeeper（992 文件，扫出 cockpit voice_memo 存量直写违规），main 的 post-merge-validate 跑增量——存量违规"谁撞谁倒霉"，非 required check 不挡合并但持续污染 CI 信号。
- **Explore agent 返回空报告**（"完成"两字，25 次工具调用的结果没带回来）——深侦察不能依赖不可靠委托，亲自侦察 15 分钟反而更快。

## Q4. Lessons (P73 truth-driven)

- 拓扑决策要有**回收机制**：D2/D3 退役时写的"独立 clone 消除竞争"是假设，实测证伪后要能低成本恢复（本次因 claim 侧调用代码未删，恢复成本极低——退役只标状态不删代码的设计是对的）。
- 命名空间隔离的本质是**把归属写进名字**：agent/{actor}/{session} 让"谁的尸体"可判定，清理器才能按 namespace 自动收。
