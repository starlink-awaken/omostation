## 3. 差距与坑（learned）

1. **立案定性差点被误导注释带偏（本轮最有价值的一课）**：INDEX-MCP.md 的
   frontmatter 注释自称「生成器时间戳 epoch-0 bug 手工修正」——初版 spec 和
   债条目按「生成器 bug 倒退手工修正」定性。读生成器源码
   gen-capability-registry.py:600-603 发现 **1970 是 ADR-0373 有意的 sentinel
   设计**（防 CI drift check 恒红），11-03 的「手工修正」才是设计违反方。
   **教训：frontmatter 的自我声明不是权威，立案前必须读设计注释（代码 +
   ADR）**。spec 与债条目全部重写订正。
2. **声明调查先钉真身**：日志/程序各有「声明版 vs plist 版 vs 文件系统版」
   三个面（T354 三份模板同款坑）。本案先 plutil 读 plist 再说，避免照着
   声明找「断流」的冤枉路。
3. **reset --hard 被 permission 拦是好事**：`git reset --soft origin/main +
   restore --staged + checkout 单文件` 等效且零风险——危险操作闸门逼出了
   更好的方子。
4. **债立案的完整动作 = 条目 + seed_items 登记**：debt-integrity 查孤儿
   （文件在而 seed_items 无 → 红）。spec 设计时漏了 debt.yaml 写面（接受
   claim_policy WARN，packet 重建成本不成比例——已知边界如实记录）。

## 6. Done-transition 过程坑 (2026-11-26 晚)

1. **半初始化残废 gitdir 骗过存在性判据**: worktree claim 超时后
   projects/omo 呈「.git 文件在 (判据① test -e 骗过)、gitdir 内部残废
   (rev-parse HEAD 报 ambig、src/omo 目录缺)」形态 —— 比 T359 l4-kernel
   的「gitdir 不存在」更隐蔽。**判据升级: 判据② = git -C <sm> rev-parse
   HEAD 可解析才许 checkout -f HEAD; ②不过 = deinit -f + 全新 init**。
   期间 checkout -f HEAD 在残废 gitdir 上报 pathspec 不匹配 (无害),
   但同命令在未初始化子模块上会向上解析打主仓 (pitfalls 11-25 条),
   两形态只差一个 HEAD 匹配 —— 统一按「② 不过先 deinit」处理。
2. **矩阵 SHA 手打 39 位假货**: merged_reachable_commit 写成记忆拼的
   SHA (39 位且 15 位后全编), complete 校验 COMPLETION_GIT_REF_INVALID
   拦住。**SHA 必须 rev-parse 取, 不手打**。
3. **done 态触发 non_goals 深校验**: pending 时不查的裸冒号
   (「generate: false」) 在 status→done 后被 lint 抓成 ERROR。
   翻 done 前先自查 non_goals 项含 `: ` 的裸冒号并加引号。
