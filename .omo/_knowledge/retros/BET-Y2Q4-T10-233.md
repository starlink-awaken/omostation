# BET-Y2Q4-T10-233 retro — omo.resident 写面按 profile 收敛到 state 根

## 1 intended — 本来打算做什么

把 B1 done_when 里 omo 侧那半做实：`omo.resident` 的写面在**调用时刻**按 profile 解析，
使 `OMOSTATION_STATE_ROOT=<tmp> omo resident daemon --once` 真的只写声明的 state 根，
且未声明 profile 时每个迁移点逐字节复现历史路径。同时把「读写同根」这件事从口头判断
变成一根可跑的对照检测器，并把跨仓读者的真实读数落到 spec §5。

## 2 happened — 实际发生了什么

- 根因比「import 时冻结」低一层：`resident/__init__.WORKSPACE = Path(__file__).resolve().parents[5]`
  既不读 `OMOSTATION_STATE_ROOT` 也不读 `OMO_EVENT_LEDGER_DB`。这个包原本**没有 state 根概念**，
  所以只把常量改成函数不改变任何行为 —— 这一点在动手前不成立在我脑中，是读源码读出来的。
- 交付面比台账措辞大一个量级：台账写「修 2 个钉死路径的测试」，实测要保的是 **89 处**
  setattr/属性缝消费者（`status.LEDGER` 12 处、`daemon.DEFAULT_EVENTS_JSONL` 等）。
  所以设计成「常量留在 WORKSPACE 上 + 写点经 `write_path()`」，而不是翻常量。
- 判据-2 从代理指标变成真测：一次性 canary 脚本 29 条断言，两相跑（`--once` + 循环 SIGTERM），
  两个检出的 `.omo/**`+`runtime/**` 全量 (size, mtime_ns) 集合零变化，机器级共享面
  `~/Workspace` 15 854 条目 `added=0 changed=0`，state 根出现 watermark/log/receipt/ledger。
  `expect=29 got=29`。
- **OMO_PRINCIPAL_ID 这一项在 omo 侧是空动作**：0 命中，`principal_id` 的 264 处命中全是参数
  而非 env 读取；root 侧已由 `bin/ssot/_principal_id.py` 收口且台账明确禁止重做。台账措辞的
  一个前提被实测否证，登记在 spec §5.4 而不是照抄执行。
- 首跑 CI 红在本轮新增的基线用例：`test_prechange_baseline_is_not_zero` 用
  `git show HEAD:src/omo/resident/receipt.py` 取「改前」文本。本地绿是因为跑的时候改动还没提交 ——
  那时 HEAD 确实是改前。提交 ba69696 之后 HEAD **就是改后的树**，冻结写点归零，
  `assert hits` 当场假红；根 PR 的 `cascading_test` 评的是 pinned gitlink，同一个红又出现一次。

## 3 changed — 改变了什么

- omo 侧 19 个文件（`omo_paths.py` + 16 个 resident 模块 + 3 个测试文件）；根侧 4 个交付物
  分 4 个单 lane commit（code / docs / docs_data / submodule_pointer）—— 混合 lane 会被
  `change-lane-check --staged` 直接拒。
- 判据读数的措辞与可观察事实对齐：`--once` 分支在返回前 `pid_file.unlink(missing_ok=True)`，
  log/receipt 需要一个真被路由的事件。判据不窄化，诚实边界进 spec §9.1。
- I3 的结论是**否定式**：`bin/` 侧 0 个读者走 state 根（CHECKOUT 41 / CALLER 6 / DERIVED 3 / STATE 0），
  所以读写同根未达成，本 BET 不宣布 B1 完成。把「未达成」钉成检测器里的显式集合相等 +
  允许清单，而不是留成一句待办。
- `bump-pointer` 的可达性判据在单分支 refspec 下失明：子模块 `remote.origin.fetch` 只有
  `+refs/heads/main:refs/remotes/origin/main`，`git fetch origin <branch>` 只产生 FETCH_HEAD，
  `git branch -r --contains` 看不见一个**确实已经 push 成功**的 commit。本轮用显式 refspec
  fetch 造出 remote-tracking ref 后守卫才放行。

## 4 lessons — 固化什么

- **「读 git 历史当基线」的用例会被自己的交付动作判红**：`git show HEAD:<path>` 在改动提交后
  返回的就是改动**后**的内容；这类用例的绿只在「写它的时候」成立。改前状态必须由 fixture
  自己物化（逐字嵌进用例），且断言从「非空」加强为「N 处且形状计数一致」，再配变异对照
  （把 6 处包成 `write_path()` 后用例转红）证明它真依赖该前提。与 #4606「测兜底必须先物化」、
  「已提交的 legacy 兜底不是仓库保证」同族 —— 这是第三种形态：**前提是历史，而历史会被你的提交改掉**。
- **判据-6 的失败要先证明它与 diff 无交集再定性**：10 项红全在 `tests/integration/test_bos_*.py`，
  根因是 `Path(__file__).resolve().parents[3]` 在 PASW 的 `.subtrees/omo` 布局下少一层。
  三条核验：diff 不含这两个文件、同一份文件在 `projects/omo` 布局单跑 11 passed、本轮没改
  `WORKSPACE_ROOT` 推导。不核验就会白跑一轮「修好它」。
- **一次 Bash 里 `cp` 到已存在文件打印 `not overwritten` 且 rc=1**：alias 是 `cp -iv`，
  目标逐字节未变。脚本化文件操作一律走 Python（本轮 restore 就是靠 sha256 复核才发现没覆上）。
- **判「字面判据不可满足」之前先读契约自己的范围条款**（2026-10-06 本轮自纠）：我实测
  `OMOSTATION_PROFILE` 无人读，就写下「B1 判据 (a) 按构造不可满足」，随后才被
  `0456:71-73` 否证 —— 那句明确写着它**不是 B1 交付物**。plan 表格的一行是简写，
  ADR 的 §Decision 才定义交付物边界；测量没错、推论越界。纪律：**「做不到」的结论要同时
  检索契约里有没有『这轮不做』的条款**，否则会把一次有意的推迟读成一次遗漏（并可能据此
  去补一个契约明确不想要的第二分叉）。
- 空绿的代价：检测器扫的是源码，所以「绿」必须先自证。合成违规 + 真实扫描为空 + 纯读面
  不被命中三段缺一不可。

## 5 遗留（实测后登记，不是遗漏）

- **`OMOSTATION_PROFILE` 不是任何一根的输入，而这不是本轮的缺口**（2026-10-06 实测）：
  `OMOSTATION_PROFILE=dev` 单独声明时 `repo_root.state_root() == code_root() == 当前检出`，
  `omo_paths.state_root()/event_ledger_path()` 同样落回检出 —— 两侧只读
  `OMOSTATION_STATE_ROOT`/`OMOSTATION_ROOT`/`OMO_EVENT_LEDGER_DB`，全仓代码里 `OMOSTATION_PROFILE`
  只有 3 处命中且都在端口面。我一度据此判它「B1 字面判据不可满足」，**这个结论被 ADR 本身否证**：
  `0456-dev-runtime-profile-root.md:71-73` 写明 PROFILE「是目标契约面，**不是 B1 交付物**：
  在出现第一个消费者（B3 服务注册 / B4 安装位）之前引入它，等于埋下第二个分叉」。
  ⇒ plan 里 B1 判据 (a) 的 `OMOSTATION_PROFILE=dev` 是简写，成立形式是**显式声明 state 根**，
  本轮判据-2 正是按该形式测的。留两条可核事实：① `~/.local/state/omostation/dev/` 已在盘上
  （`event-ledger.sqlite3` + `-shm/-wal` + `*.provenance.json`，`authoritative: false`），
  即「按名字选 profile」的落位早已备好、缺的只是名字；② 第一个消费者出现时该层才是新增工作，
  **形状是加一个 profile→state 根解析层**（未声明时逐字节不变，与本轮「机制先于搬家」同安全论证），
  不是再改 resident 写者。
- `bin/` 侧 32 个文件 / 15 个 STATE 族的读者仍按 checkout 根解析 —— 要翻需要新的 write_surfaces。
- `omo_paths.event_ledger_path()` 做 `.expanduser().absolute()`，`repo_root.event_ledger_path()`
  的 env 分支不做（`repo_root.py:98`）—— 登记为 `LEDGER_OVERRIDE_ASYMMETRY`。
- 额外台账口径两处：`event_ledger/surface.py:41`、`sovereignty/enforcement.py:120`。
- 推迟的 resident 写者：`task_queue.py:834/977`、`connectors_poll`、`sema_crystallizer`、
  `swarm_custodian`（后者用 `Path.cwd()` 反推检出根，是另一类写面缺陷）。
- `bin/ssot/install-resident-cron.sh:49/:53` 仍写检出相对路径（B4b 批次 2+，需逐批授权）。
- `status.resolve_ledger()` 的 env 优先级是第二份实现，与 `repo_root` 那条未收成一个源。
