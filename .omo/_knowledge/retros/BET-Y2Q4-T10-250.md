# BET-Y2Q4-T10-250 retro — 一次判据造出三份作废读数的过程

台账：`docs/plans/3y-bet-ledger.yaml` `BET-Y2Q4-T10-250`
Spec：`docs/superpowers/specs/2026-10-13-writeplane-root-pin-gate.md`
交付：`tests/unit/test_writeplane_root_pin.py` + `.github/workflows/governance-check.yml` 白名单第四件

## 1 intended（原本要什么）

B1 的完成判据（`bin/` 内 `DEFAULT_(EVENT)?LEDGER` 常量归零）已经达成，但那只覆盖**常量命名形状**。
本轮要的是 B1 的真实意图在 `bin/` 的**覆盖面**：写目标跟随 profile 声明的根。据此把「由 `__file__`
反推检出根再拼 `.omo/state/**` 或 `runtime/**`」的站点收成 shrink_only 基线，让新增一处当场变红。
范围红线：只登记，不改道任何真实写目标。

## 2 happened（实际发生什么）

- **读数被自己的尺作废三次**（全过程写进 spec §1，逐条留根因，不静默覆盖）：
  1. 「63 处 / 52 文件」—— 按路径**首段**匹配，`.omo/state/**` 整体漏认（首段是 `.omo`）。
  2. 「81 处 / 64 对 / 46 文件」—— 规则只认「链最左端是模块级 `__file__` 派生**名字**」，
     结构性看不见 `bin/plan/bet-ledger.py:477` 那种**内联**拼法。这是 AGENTS.md §7⑧ 的一面。
  3. 「154 站点但渲染成 82 / 65 / 47」—— **同一错误的另一面**：为了吃内联形状把「最外层链」
     写成「`node.left` 是 Div 就跳过」，跳过的正是外层（外层节点才是要留的），于是每条链只剩
     第一段，`.omo/state` 从 103 掉到 31。
- 第三份是**写完判据后第一次跑 ISC-2 自证用例**当场抓到的 —— 注入的分段拼法
  `W / ".omo" / "state" / "history.json"` 没有被点名。没有那条用例，第二份作废读数会以
  「基线 = 81 对、实测 = 81 对」的形式**自证通过**并写进契约。
- 最终发布读数（判据本身产出）：全 marker 460 站点；门禁纳入 **154 行级站点 / 144 个
  (文件, 整条路径) 对 / 95 个文件**；排除四类 marker 各带独立理由（读面 SSOT、全机 symlink 协调桥、
  署名文档面、`kos/` 另案）。与邻居门禁 `test_system_yaml_write_plane.py` 重叠 **1 处**
  （`bin/gac/architecture-check.py:47`，该文件在邻居侧已判死码）。
- 牙齿实测：从基线删一行 → **2 failed**（双向相等件 + marker 承重件）；还原按 sha 复核一致后
  **8 passed**。hermetic 面：`HOME=<空目录>` + `env -u OMOSTATION_*` + 最小 venv 同样 **8 passed**。
- 准入阶段两次空转，根因都不在治理代码：
  - `BET_NOT_FOUND: BET-Y2Q4-T10-250` —— `bin/agent-workflow.py` 先设 worktree 派生的 `WORKSPACE`，
    再 `from omo.workflow import (WORKSPACE, …)` 把它**重绑**到「提供 `omo` 包的那棵检出」。借来主区
    PYTHONPATH 时，`start` 读的是主区台账（还没有这条 BET）。
  - `WORK_PACKET_COMPILER_UNAVAILABLE` —— `projects/ecos` 目录存在、`.git` 在，但工作树是空的，
    `import ecos` 直接 `ModuleNotFoundError`。

## 3 changed（落下了什么）

- 一条**同源**门禁进仓：基线不是手抄名单，而是由将要发布的判据自身生成；ISC-2 三条命中形状 +
  ISC-3 三条不命中形状 + ISC-4 双向相等，一起把「检测器没命中」「宽到吞读面」「债静默消失」
  三个塌缩方向钉死。
- `governance-check.yml` 的显式 pytest 白名单多了第四件，并写明点名理由、变异对照读数与 hermetic 读数。
- 台账的 verify-1 命令**换成最小 venv 配方**。原判据写 `python3 -m pytest`，在宿主上当场
  `No module named pytest` —— 那是装置没搭对（AGENTS.md §7 hermetic 补记早已点过这一面），
  不是回归；把它留在台账里就是留一条按构造不可满足的验收。
- 零运行时效应：95 个在账文件一个字节未动。

## 4 lessons（可迁移的判断）

1. **「实测集合 = 允许清单」不是自证**：同一份名单由同一把尺产出时，尺的漏认和清单的短缺**一起绿**。
   §7⑧ 这一轮出现**两个方向**（漏认内联形状 / 链截断方向写反），所以自证必须注入**多种书写形状**并
   断言逐条点名 —— 只注入一种形状的检测器，抓到的是自己的书写习惯，不是代码。
2. **新建 BET 的首轮准入，前置是 PYTHONPATH 面而不是台账面**：`start` 报 `BET_NOT_FOUND` 时先问
   「这次读到的是哪棵检出的台账」，判据是 `python -c "from omo.workflow import WORKSPACE; print(WORKSPACE)"`
   是否等于自己的 worktree。修法是把 worktree 做成自足（init `projects/omo`、恢复 `projects/ecos`），
   不是往主区台账加条目。
3. **子模块「目录在 + `.git` 在」不等于可用**：worktree claim 可能留下空工作树。判据是**能 import**
   （`ls projects/ecos/src`），不是 `ls -d .git`。
4. **凡「先改文件再改回来」的对照实验，还原必须走 Python 并按 sha 复核**：本仓 shell 里 `cp` 是
   `cp -iv` 别名，覆盖已存在文件时打印 `not overwritten`、**rc=1 且目标逐字节未变**；
   这一步没验就会拿「变异后的红」当「修复后的绿」继续写契约。
