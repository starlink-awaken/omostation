# BET-Y2Q4-T10-207 复盘（ADR-0456 B4a · 运行时代码安装位落位）

## Q1 实际耗时 vs appetite？超出比例？

Appetite 3 hours，实际墙钟约 **2.5 小时**，但**分布与预期相反**：净代码 220 行，
而"落一个目录 + 加一个定位器"这件事的时间烧在**验前提**和**合并窗口**上——
三条 plan 前提被实测否证（release tag 不存在、主仓 shallow 导致 `--local` 失效、排除清单是空动作），
外加 base 前进逼出两个分支代际（#4438 → #4439）。

教训的形状：B4a 的难点不是"写代码"，是**在动手前把 plan 里每句"事实"当假设重测一遍**。
plan 说"detached 在 release tag"，如果照做就会去**造**一个 tag —— 那是把历史事实伪造进治理状态，
比不做更贵。同理"加排除清单"如果照做，会留下一个永远不会被触发的防御，读者还以为它有效。

## Q2 done_when 是否全部通过？哪条没过，为什么？

7 条全部通过，且**在合并后的 main + 真实安装位目录上重测**（不在分支上自证）：
D2 只在合并后可满足（clone 早于 CLI），所以流程改成"合并 → 把 clone 重新 detach 到 merge commit → 再跑"；
D3 为 852 passed；D4 为审计 JSON 中安装位 0 命中；D5 目标实测打印两段根报告。

一处**契约自身**不合格被抓出来：spec done_when #5 写了 `make install-root-check`，
实际交付的是 `make runtime-install-root`。按"修生成器不修输出"的同一原则，改的是**契约**
（spec → 1.0.1，台账 `content_digest` 同 commit 重算绑定），不是把实现改成难看的名字去迁就旧笔误。

## Q3 过程中发现的与 plan 不符的事实（打假）

1. **`~/Runtime` 与 `~/runtime` 同 inode（146632641）**，且后者是 `projects/runtime` 的 Tier-1 数据域
   （`service-ctl.sh:10` 已把它当 `RUNTIME_HOME`）。plan 的决策 1 理由 3 已经警告过大小写碰撞，
   **但结论没吸收**——这是"理由正确、结论漏改"的典型，只能在落盘前用 `stat` 逼出来。
2. **主仓 shallow**：`git clone --local` 打印 `ignoring --local`，183 MB 是复制不是硬链接。
   plan 的"成本约等于零"因此不成立。`--unshallow` 故意不跑：对共享仓做大流量网络写不是零效应动作。
3. **清扫工具看不见安装位是结构性事实**：`_candidate_dirs()` 只 glob `$HOME/ws-*` / `$HOME/workspace-*`
   + 已登记 worktree；`gac-branch-prune.sh` 删分支不删目录。于是 plan 的"排除清单"改判为"守卫测试"。
4. **台账派生计数是并发赛跑的放大器**：`meta.total_bets` 与 `len(bets)` 必须相等，所以每 mint 一条 bet
   就改一次同一行。#4438 的 CONFLICTING 不是内容分歧，是**同一个整数被两条链各自 +1**。
   唯一稳的对策是把插入推迟到 push 前、并基于最新 main 重建，而不是想办法让 merge 变聪明。
5. **`ADR-0456` 有两个文件同时声明同一 id**，被记为 ACCEPTED（PR 4413）的那条属于另一个决定。
   因此 ADR **不改 status**，引用一律带文件名。标识冲突属 principal 权限，只报告不处置。

## Q4 下次可复用的做法（固化）

- **"零运行时效应"要可证伪**：把它写成 4 个探针（reality-check `e2_undeclared=0`、
  plist 引用安装位 0、crontab 命中 0、Workspace 侧 plist 未动），交付时跑一遍并写进 receipt。
  否则"我没碰服务"只是叙述。
- **失败态必须比成功态更响**：`make runtime-install-root` 在 clone 尚未 detach 到新代码时，
  原来的写法会打印标题后**静默空输出**（旧 `repo_root.py` 无 `__main__`，`exit 0`），
  看起来像通过。改成显式打印「安装位落后于本轮」+ 指路。给"还没发生"的状态编一个诚实的输出，
  是这类定位器的必备部分。
- **定位器返回 `None` 而不是抛异常**：CI 和别人的机器上没有安装位，抛异常会让一个只读查询变成门禁。
- **先测前提再定方案**；前提被否证时，把否证**写进契约正文**（spec §2、ADR §2），
  而不是只在 PR 描述里说一句——否则下一个人会带着同一个假前提再走一遍。
