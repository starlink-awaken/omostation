# BET-Y2Q4-T10-211 Closeout Retro

## Intended

在不改变 `release` 删除护栏的前提下，为 dirty root、dirty submodule、真实 gitlink、生成物、PASW 残留和无法读取的 worktree 提供只读分类诊断。

## Happened

- `release-diagnose <session>` 保留 `0/1/2` 退出码和默认文本入口。
- root status 改为读取 `git ls-files --stage` 的 index mode；只有 `160000` 才输出 `[gitlink]`，普通 `projects/*` 修改输出 `[dirty-root]`。
- `.omo/*`、`docs/generated/*`、`docs/cli/*` 输出 `[generated]`；递归子模块内容输出 `[dirty-submodule]`。
- 配置中的无效 PASW 输出 `[invalid-pasw]`，未配置且非 Git worktree 的 `.subtrees/*` 目录输出 `[orphan-pasw]`。
- `status --porcelain=v1 -z` 按 NUL 记录解析；重命名只报告目标路径，路径空格不会拆词。
- focused shell tests 覆盖 clean、dirty root、dirty submodule、missing session、普通 `projects/*`、真实 gitlink、generated、invalid/orphan PASW、rename/space 和只读前后快照。
- focused shell test 通过；生命周期回归测试 30 项全部通过。
- `uv run --with pyyaml python bin/plan/bet-ledger.py lint` 通过（503 bets, no errors）。
- `agent-workflow verify --from-diff --execute` 执行到两个环境门禁失败：缺失 `bin/sweep/nested-with.py`，以及 `gac-local-gate` 下 checkout/runtime 相关失败。

## Changed

- 将 `release-diagnose` 的 pointer 猜测从路径前缀改为 Git index 元数据。
- 将 PASW configured-invalid 与 orphan 目录拆分，并验证候选目录的 Git top-level 等于自身，避免父仓库误判为有效 worktree。
- 保留现有 `release` 分支逻辑不变；诊断仍不执行 reset、stash、clean、remove 或 branch delete。

## Lessons

1. Gitlink 必须由 index mode 判定；`projects/*` 只是业务路径，不是对象类型。
2. `git rev-parse --is-inside-work-tree` 会把普通子目录归因到父仓库；PASW 校验还必须比较 `--show-toplevel` 与候选目录自身。
3. NUL 状态流的 rename/copy 记录有额外路径字段，必须消费第二条记录，才能避免旧路径重复告警。
4. 诊断实现通过与完整仓库门禁可运行是两类证据；本次剩余失败来自缺失 sweep 文件、cockpit-ui 构建资产、resident BOS 基线和 evidence freshness，而非变更路径。
