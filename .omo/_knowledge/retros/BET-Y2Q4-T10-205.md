# BET-Y2Q4-T10-205 复盘（ADR-0456 B2-A · 端口注册收口 + dev 端口段门禁）

## Q1 实际耗时 vs appetite？超出比例？

Appetite 2 hours。run 记录上的实测时间戳：`start 2026-09-26T17:00:14Z` → 5 条
`write_surfaces` 的 `claim 2026-09-26T23:28:05Z` → PR #4411 `mergedAt 2026-09-27T00:31:06Z`。
claim→merge 是 **1h03m**，在 appetite 内；start→claim 的 6h28m **不能**读成本 bet 的净耗时——
同一会话在这段里先跑完了 BET-Y2Q4-T10-204 的 closeout 链（#4406 / #4409），本 bet 的 spec 与
ledger 条目是在那之前落的。**诚实结论：本 bet 自身耗时无法从 run 记录分离，只有
"纯机械交付段 1h03m" 这一条可证。**

真正超出 appetite 的是**两次自我纠错**：spec 的 adjacent-findings 段先写错一次
（把 root 扫描器描述成有 `--check-ports`），合并前又写错一次（把 ci-surfaces 的登记描述成
`status: orphan`）。每次纠错都要重算 digest、重绑 ledger、并按 change-lane 拆成独立 commit，
净多付 2 个 commit + 1 轮 CI。形状教训：**这条 bet 的成本不在注册端口，在把"门禁到底执行了什么"
说准。**

## Q3 过程中发现的与 plan 不符的事实（打假）

1. **"port hardcode check 绿" 是零检查的绿。** `bin/gac/ci-check-runner.py:65` 的选择谓词是
   `surface.workflow == 请求的 workflow 且 status != orphan`，**从不读 `also_in` 与 `gate`**。
   本扫描器登记为 `status: active / workflow: mof-update.yml / gate: false /
   also_in: [port-registry-enforce.yml]`，于是
   `--workflow port-registry-enforce.yml` 恒得 `(0 checks) ✅`（每个 PR 上那个看起来在守门
   的 job 什么也没扫），真扫描只在 `mof-update.yml` 的 `schedule: "0 6 * * 1"` 下发生。
   我第一次把这条写成"登记为 orphan"，是**读数错**：orphan 是 `ci-surfaces.yaml` 里另一个
   scanner 的值。是 CI 自己（job 绿 + 我的测试红）逼着我把机制读对。
2. **门禁的"增量 enforce"三处描述、零处存在（比上一版结论更强）。** 除上述死信外，
   `.pre-commit-config.yaml` 的 `port-hardcode-check` 指向不存在的
   `scripts/check-vault-paths.py --check-ports`，而 root 扫描器的 argparse 从来没有
   `--check-ports`（只有 `--json / --threshold / --env-var-check`，本 bet 新增
   `--dev-env / --profile`）；`port-hardcode-baseline.yaml` 也没有任何执行者，只有 ecos
   MOF 节点声明它。是否翻转"门禁效力"属 principal 决定，本 bet 只把描述改准，不接线。
3. **`--scope staged` 在未 stage 时是空跑。** 第一遍门禁 `change_lane_files=0` 全绿，
   对 5 个未提交文件零覆盖。正确形状是 `--scope files --file <path>`（零 git 写）。
   紧接着暴露 **mixed lanes 硬失败**（`code,docs,docs_data`），于是 5 条路径必须拆成
   单 lane commit —— 本 PR 最终 5 个 commit 里只有 3 条是不同的 lane，另 2 条是纠错重放。
4. **`start` 之后再改契约，会把这条 run 的 claim 通道彻底焊死。** 我改了 spec（两次）
   并重绑 digest，此后任何 `claim` 都撞
   `WORK_PACKET_SOURCE_DRIFT: ledger/spec projection no longer matches the bound packet`
   （`bin/plan/bet-ledger.py:2334`）。唯一的重绑动词 `agent-workflow.py refresh-packet`
   又要求 ledger 已 commit 到 run 记录的那个 revision（实测
   `WORK_PACKET_REFRESH_SOURCE_UNMERGED: ledger differs from d2b97b2ee…`）。
   即：**harness 没有"同一 run 内合法演进契约"的路径**。后果是可执行的纪律：
   `write_surfaces` 必须在 `start` 前就把 closeout 的 receipt / retro 路径写进去
   （T10-204 就是这么做的，本 bet 漏了，于是 closeout 只能另起 run）。
5. **`gac-worktree.sh merge` 会动共享主工作区。** `:735-804` 在 `gh pr merge` 之后
   `cd $WS_ROOT; git checkout main; git pull --ff-only`。当时主工作区正停在另一个 agent 的
   `feat/panorama-mof-loops-data-pipeline` 上、带 **39 个未提交文件**，这条包装器一旦跑完
   就把别人切走分支。所以合并直接用 `gh pr merge 4411 --squash --delete-branch`（纯远端效应）。
   这是 harness 级隐患，不是本 bet 的偶发运气差。
6. **自己的中断 fetch 会留下静默毒物。** push 被 `submodule-reachability: FAIL (1 failures)`
   拦下，真因是本 worktree 的模块目录里躺着 **16 个 41 字节的 `refs/**/*.lock`**——
   第一次 push 那条 293s 被杀掉的 fetch 留下的。先用 `ps` / `lsof` 确认无持有者，再按
   路径（含 `/refs/`）+ 尺寸（==41）双条件删除，重推 45s 通过。**先查持有者，再删锁**
   这条在这里第二次救场。
7. **plan 里的 B3 基数是估的，实测另有一解。** 计划写"37 个未登记 label"，实测
   `~/Library/LaunchAgents` 里指向本 Workspace 的 plist **43** 个（41 可解析 + 2 格式坏），
   待回填面 27 个 label，当前 loaded 20，declared-not-loaded 6（含 `com.cockpit.dashboard`），
   registry 有 label 但无 plist 11。且 `gen-service-configs.py --check` 只做
   registry→plist 单向字节比较（实测 `drift_count 0`），**看不见"装了但没登记"**，
   所以 B3 的等式门禁必须新造。
7b. **上一条的"41 可解析 + 2 格式坏"本身也错，错得更贵。** 那 2 个 plist（
   `com.omostation.expiry-radar` / `com.omostation.zhixing-host-drift`）对 launchd
   **完全正常**：`plutil -lint` OK，两条都在 `gui/501` 里 loaded。"格式坏"是我用
   `plistlib`（= expat）读出来的 ExpatError —— 真因是**注释里含 `--`**（`--strict`、
   `drwx------`），XML 规范禁止，Apple 解析器宽容。教训：**"我的解析器读不了"
   不等于"文件坏了"**，用 stdlib 枚举得到 25 条 installed，而真集是 27（Workspace 口径）
   / 37（全集）—— B3 的枚举端必须走 `plutil -convert json`，严格 XML 检查只能作为
   **lint 债**报告项，不能当过滤器，否则注册表门禁天生看不见 2 个正在跑的服务。
8. **pytest 的 234s 不是测试慢，是 root conftest 慢。** `tests/test_hardcoded_ports.py`
   20 个用例本身是纯解析 + 纯计算；`python3 -m pytest` 首次跑直接吃掉一次工具默认
   2 分钟超时（转后台才拿到结果）。写 verify 时按实测时长留余量。

## Q4 改变了什么 / 教训固化

**改变的东西**

- 端口注册表从 54 → **57** 条，并把"谁在服务人类 UI"变成可表达的事实：`5173` 从外部工具豁免
  改判为本仓自有（`cockpit-ui-vite-dev`）、`4000` 注册为 aetherforge OpenAI facade、
  `43910` 注册并声明 `env_var`。`LEGACY_OK_PORTS` 从 5 项收窄到 4 项。
- 新增 **dev 端口段的机器可验形状**：registry 顶层 `dev_band` + 4 条 `dev_ports`
  （各带 `env` 覆盖变量与所指 `prod_port`），扫描器 `--dev-env --profile {dev,prod}`
  是唯一供给口（dev 打印、prod 打印 0 字节），并在每次打印前重验 段内/单射/与生产不相交/
  prod_port 已注册 四条。ADR-0456 B4 的双实例不再靠"随手 +1000"选端口。
- 端口门禁的真实执行面被**测量并写进 spec**，不再是传闻：0-check 的 PR job vs 周一才扫一次。

**固化下来的判据（比规则本身更实用）**

1. **job 绿 ≠ 检查在跑。** 读 `ci-check-runner.py` 的选择谓词，别读 job 的颜色；
   谓词不读的字段（`also_in` / `gate`）就是不存在的路由。
2. **注册事实，不要加豁免。** 让红项变绿的合法路径是把 4000 注册进去 + 把 5173 改判自有，
   而不是往 `LEGACY_OK_PORTS` 里塞。前者收窄了门禁，后者放宽了门禁。
3. **契约要在 `start` 前写全。** `write_surfaces` 漏掉 receipt/retro 路径 + 事后改 spec，
   等于自断 claim；digest 一变就必须重绑，且重绑本身也是一次 `docs_data` lane commit。
4. **共享主工作区里不跑任何会 `checkout`/`pull` 的包装器。** 合并走 `gh pr merge`，
   把副作用留在远端。
5. **端口是否"活着"要当场测**（`netstat -an -p tcp | grep LISTEN`，76 个）。
   `8090 idle` 这类事实只有测了才能成为证据；本 bet 因此把 B2-B 定性为
   "入口虚构"而不是"入口慢"。
