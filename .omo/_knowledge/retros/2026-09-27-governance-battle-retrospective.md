## 三、失败与自救（诚实清单，全部留痕）

**我的错误（6 起，全部当会话修复）：**
1. `rm -rf data/` 误删 12 个受跟踪文件（误判整目录未跟踪）——`git checkout -- data/` 秒级恢复。教训已入 memory：删目录前 `git ls-files`。
2. commit-assist 假幽灵判定——只查声明路径没查全库文件名，把活跃脚本判成"从未存在"。
3. done_when 想象口径 ×2——"doc 指向 decisions/"（ingest 不保目录）、commit-assist 的 source_ref 路径笔误。教训：**验收条款写下前先实证通道行为**。
4. `cross_walks:cross_walks:` 双写键 + PyYAML last-wins 覆盖 50 组别名——插入脚本把锚行拼进块尾、又带重复顶层键。git 秒级恢复 ×2。
5. 误挂 run——批次三 start 复制批次二参数未改 `--bet`，complete 链检查拦截后补链。
6. PR 编号竞争——把并发 agent 的 #4499 当自己的（幸其已自合并零损伤）。

**链条断点类（同一根因反复咬人）**：`grep -c` 零匹配 exit 1 断链 ×3——其中一次导致两个债务文件从未提交、worktree 释放时丢失（#4498 恢复重铸）。

**发现并修复的 main 真 bug（2）**：

## 四、沉淀（本次固化的方法论）

1. **幽灵判定双检**：全库文件名检索 + `omo.cli lint --help`（SEC×2 假幽灵实为 omo lint 已覆盖）。
2. **retired 统计口径**：弃用/收窄/并入条目移出接线候选池、注册表保留——归零不是靠删声明。
3. **插入脚本安全姿势**：新组插 aliases 段内、新顶层键追加文件尾、绝不内嵌锚行。
4. **数字双口径**：gh 分页会撒谎（100/200 触顶），计数类断言 git/gh 交叉。
5. **PR 归属核对**：编号竞争期合并前 `gh pr view <N> --json headRefName`。
6. **验证命令与门禁同语义**：裸 `ruff check` ≠ 基线口径。
