# BET-Y1Q4-T10-153 retro — A5 AetherForge 门面常驻化恢复

## What changed

- 新建 `~/Library/LaunchAgents/com.aetherforge.gateway.plist`（不在本仓库内），
  `KeepAlive`/`RunAtLoad` 均为 true，`ProgramArguments` 走
  `/bin/bash ~/.local/bin/aetherforge-gw-guard`，日志落
  `~/Library/Logs/aetherforge-gateway.log`。
- `.omo/_truth/registry/services.yaml`：`aetherforge.gateway.enabled`
  `false → true`，`config_source` 去掉"— 已移除"标注，`notes` 补充
  2026-09-11 修复记录。

## 触发背景

本次是在处理用户"审计 omlxc 模型机制/算力并接入本地 agent 工具"这个更大
请求时顺带发现的——修复 omlxc `config.toml` 里的 `context_limit` 之后，
实测 CC Switch 里已配置好的 opencode/pi omlxc provider（指向
`http://127.0.0.1:9290/v1`）时发现端口根本没人监听，才追出这条 launchd
服务缺失的根因。

## 证据（改动前 → 改动后）

改动前：
```
launchctl list | grep aetherforge   # 无输出，服务未注册
lsof -iTCP:9290 -sTCP:LISTEN        # 无监听
```

改动后：
```
launchctl list | grep aetherforge.gateway
# <真实PID>  0  com.aetherforge.gateway

curl http://localhost:9290/health          → 200
curl -H "Authorization: Bearer $KEY" \
  http://localhost:9290/v1/models          → 200, 多引擎模型列表
POST /v1/chat/completions {model: coding}  → 200, 正确文本回复
```

Spec：`docs/superpowers/specs/2026-09-11-a5-aetherforge-gateway-restore-fix.md`

  是算力路由的唯一 owner。守护脚本自身注释也显示此前一个已知 bug
  （`AETHERFORGE_M1_DIR` 静默短路模型发现）已在 2026-08-23 修复过。恢复前
  先手动前台跑了一次验证完全正常，才建的 plist，不是盲恢复。
- 没有顺手改守护脚本、网关代码或 omlxc 侧的其它问题（inventory_drop 告警
  依然存在，明确不在本 BET 范围内，留作独立后续）。
