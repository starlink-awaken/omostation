# BET-Y1Q4-T10-02 retrospective

## Q1. What was intended?

完成 BET-Y1Q4-T10-02「子模块 doc frontmatter 批量迁移收尾 + doc-index 合规收口」：将 doc-index 合规问题从 1130（839 SSOT-NO-OWNER + 291 SSOT-NO-DATE）降至 ≤800 预算内。

## Q2. What happened?

使用框架内置自愈路径 `bin/ssot/generate-docs-index.py --fix`（owner=governance-team，last-reviewed=当日）一次修复 853 个文件，硬阻塞归零；`--check` PASS（仅 UNTYPED 软信号 1930 不阻塞）；`submodule-reachability-gate.py --source index` PASS（16 gitlinks）。三条 done_when 全部满足，第三条 gitlink drift 由 reachability gate 判定。

## Q3. What changed during implementation?

基线测量发现目标本应为 1402，实测 1130（另一并行进程已消化部分存量）。修复大头是 gitignore 的工具产物目录（sediment 333 / codebase-memory 106 / subtrees 90+ / knowledge 未跟踪 360），git 跟踪面仅 4 个文件（doc-inventory 重新生成 + 3 个 docs frontmatter 由 auto-fix-loop resident 并行补全后一并入库）——因此本任务零内容变更、git 影响极小。

## Q4. Lessons (P73 truth-driven)

- **先测基线再动手**：台账口径（1402）与实测（1130）有偏差，全量 --check 重测后才定修复策略。
- **优先框架内置工具**：--fix 与 check_compliance 判定完全一致，避免自写脚本造成口径漂移（DRY）。
- **git 跟踪面先查再修**：修复前先 `git ls-files` 确认跟踪状态，避免把 untracked churn 变成 commit 噪音。
