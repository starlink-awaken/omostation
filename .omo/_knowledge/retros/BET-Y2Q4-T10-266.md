## 1 intended — 原本要发生什么

上一轮（T265）交付后，台账与 retro 的措辞是「常驻族 6 条已改道，E1=0」。本轮动手前的任务是
**复测这句话覆盖到哪一层**。原本的预期是：E1 归零 + launchd argv 指向安装位 ⇒ 改道完成，
剩下的只是把 wrapper 里的字面量清掉（任务 #143）。

实测否证了「E1=0 意味着码面跟着入口走」：

- launchd 自己的 `ProgramArguments` 确实是 `/bin/bash /Users/xiamingxing/.local/opt/omostation/lib/resident-role-tick.sh <role>`，
  6 条 `last exit code = 0`，`runs` 分别 9/9/4/4/4/2 —— 改道后跑过真实 tick。
- 但 `lib/resident-role-tick.sh` 在安装位与检出**逐字节相同**（`diff` 无输出），第 24/28 行仍是
  `exec /opt/homebrew/bin/uv run --project /Users/xiamingxing/Workspace/projects/omo …`。
  `lib/` 面共 5 个文件、6 处检出根字面量。
- ⇒ 入口 argv 指安装位、执行的 Python 码面仍是检出 —— 正是 ADR-0456 B4b 要消灭的那个谎。

## 2 happened — 实际发生了什么

现有四把尺**全部结构看不见**它，且各有具体理由（不是「没想到」）：

| 判据 | 比较对象 | 为何不命中 |
|---|---|---|
| E1 | plist 文本 vs 注册表渲染 | 入口本来就合法地改到安装位，E1=0 是真的，但它只证到 argv |
| E2/E5 | label 集合双向相等 | 与码面无关 |
| E4 | plist 可解析 + 分区闭合 | 与码面无关 |
| `assert_import_root()` | `omo.__file__` vs 加载它的那棵树 | 参照根与被检对象由同一次 `--project` 钉死，两边同时是检出，恒等成立 |

最后一项是本轮最贵的发现：plan §159 把「启动断言 `omo.__file__` 落在期望 code_root 下」写成该风险的缓解手段，
而 `git grep` 实测它在生产路径**零调用点**（只有 `bin/lib/repo_root.py` 自身与一条单测）——
**可用而未接线**。所以不能拿它当证据，只能新造一条与被检对象**不共享失效模式**的判据（AGENTS.md §7③）。

E6 的判据形状：对每条声明 `runtime_root` 的 launchd 服务，沿本机 plist 的 `ProgramArguments` 找到位于
`service_root(svc)` 之下的入口脚本，读**脚本内容**，数「另一个根」的字面量出现次数。
三种 state：`ok` / `pinned_other_root` / `undetermined`。

真实机器读数（本轮 receipt）：**6 条全部 `pinned_other_root→checkout`**，`e6_blocking=0`，`ok` 与 rc 不变。
这就是 done_when-2 要的 receipt —— 命中为零才说明检测器没接上。

## 3 changed — 因此改了什么

1. **缺省 observe-only，由注册表内容决定升级**。今天 6 条全命中，直接计入 `findings` 会让 CI 与本地门禁
   当场翻红，而翻红本身不构成任何修复（§4 的 438 commits 落后是真实前置，本轮不修）。
   升级开关 `require_kernel_root_match: true` 挂在**条目**上，于是「把某族内核也改道」与
   「声明它已经改道」是同一次注册表编辑里的两件事 —— 逐批、可回退，且与 `runtime_root` 同族校验位。
2. **`undetermined` 与 `pinned_other_root` 在阻塞面同形**。promotion 条件是 `state != "ok"`，不是
   `state == "pinned_other_root"`。理由：若开关只管理面字面量命中，那把入口改成认不出的形状
   就等于关掉这道闸 —— 这是 spec §3.1「认不出不得算通过」的另一半。
   用例 `test_e6_strict_promotes_undetermined_too` 把它钉住（变异对照：摘掉 `!= "ok"` 改回
   `== "pinned_other_root"` ⇒ 该用例当场红）。
3. **只接受 `true`**。写 `false` 就是给「缺省即不声明」造第二个真值来源。
4. 交付面的 A/B 不是「断言没变」而是**与 `origin/main` 那份生成器逐字节对拍**：同一注册表、
   同一 LaunchAgents 目录，两侧 `findings` 逐字节相同、`ok` False→False、rc 1→1，
   除 4 个 `e6_*` 新键外零字段差。

## 4 lessons — 下轮要知道的

- **「门禁绿」与「改道完成」之间可能隔着一次测量装置的选择**。E1 的参照系是 plist 文本，
  它绿只能证到 argv；要证码面就得读脚本内容。判据必须与被检对象不共享失效模式 ——
  这条在 AGENTS.md 里是抽象的，本轮的具体形状是「两边同时被 `--project` 钉在检出，所以恒等成立」。
- **plan 里写的缓解手段要 `git grep` 调用点再引用**。`assert_import_root` 是「可用而未接线」，
  把它当缓解就是拿一个没人调的函数当证据。判据：`git grep -n <fn> -- ':!tests'`。
- **fixture 的错会让被测判据背锅**。`report["ok"] is True` 一度失败，根因是我在 fixture 里把
  `workspace_prefixes` 写成 `"com.l4."`，而 `match_workspace_prefix()` 是**点分段**匹配
  （`label == prefix or label.startswith(prefix + ".")`）⇒ 该服务被归成 `unmanaged_unknown`、E4 报警。
  正确处置是修 fixture（照 `git show origin/main:<registry>` 的真实值），**不是放宽断言**。
- **A/B 类对照必须让两侧读同一份注册表**。`main()` 里 `local_root = Path(__file__).resolve().parents[2]`，
  而 `--reality-check` 从 local_root 取注册表 ⇒ 把 baseline 生成器拷到 `/tmp` 就变成「拿没有新字段的树
  比新树」。判据：显式 `--registry <canonical services.yaml>` 传给两侧，且**逐字段 diff 输出**而不是只看 rc。
- **hermetic 复跑要带 `--with pytest-timeout`**。rootdir 仍是本检出，pyproject `addopts` 注入
  `--timeout=300 --timeout-method=signal`，最小 venv 缺这个包就当场 `unrecognized arguments`（已回写台账 verify-3）。
- **一条判据的缺省必须让今天的真实命中为「观测」而不是「红」**，同时留一条由内容决定的升级路径 ——
  否则要么门禁失去意义，要么修复被门禁绑架。本轮 E6 = 6 hits / 0 blocking，就是这两种失败之间的位置。
