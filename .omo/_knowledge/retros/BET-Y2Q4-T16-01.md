# BET-Y2Q4-T16-01 Retro — launchd 平面漂移门三段式落地与存量盘点

## 交付概要

| 项 | 交付与证据 |
|---|---|
| launchd 平面 shadow 门禁落地 | `bin/scheduler-compile.py::check_drift()` 扩展 launchd 平面三项校验（C1 双向差集、C2 plistlib 可解析性、C3 目标有效性），`mode: shadow` 且 `blocks_gate: false`（Commit `21e1f45a4`） |
| 修复命令静默无操作 | `--generate launchd` 此前因 `__main__` 分发盲区导致静默退出，现已支持完整导出非空 JSON 格式的 launchd plist 集合（Commit `21e1f45a4`） |
| 显式 label 补齐 | 为登记源中全部 17 条 launchd 登记补齐显式 `label` 字段，使合成 label 到已安装 label 的命中率由 7/17 提升至 17/17（100%）（Commit `7047d1f2a`） |
| 双向差集完整化 | `check_launchd_plane` 完善返回结构，显式暴露 `missing_installed` / `missing_installed_count` 与 `undeclared_installed` / `undeclared_installed_count` 对称指标 |
| 存量分类与处置报告 | 产出 `docs/reports/2026-10-29-t16-launchd-unmanaged-inventory-classification.md`，彻底摸清 31 条 W 组存量与 36 条 E 组免除项，明确各条目的 owner 与处置建议 |
| 自动化回归测试 | `tests/unit/test_scheduler_compile_launchd_plane.py` 增补双向差集完整性断言，6 项测试 100% PASS |

## 关键收益与架构对齐

1. **消除历史治理盲区**：终结了 launchd 平面长期「既无生成也无校验」的状态，让常驻作业处于可观测状态。
2. **三段式渐进安全防护**：吸取了 E5 事故（门禁直接设硬阻断导致主干被封锁）的教训，严格遵循 shadow → warning → fail 演进路径。
3. **真实存量摸底定论**：不仅复算了 2026-09-28 发现的存量，更结合 B4b 切道后的最新格局将 31 条 W 组存量清晰分类定责，为后续转入 warning 阶段奠定了坚实基础。

## 遗留事项与后续规划

- 推动后续阶段将 `services.yaml` 与 `scheduler-compile` 的登记源融合，实现单一 SSOT 自动映射，消除双重声明开销。
- 待存量 plist 清理或自动映射完成后，适时发起 Principal 审批推进至 warning 阶段。
