# ADR-0008.1: Phase B Condition 4 Amendment

> Status: Proposed (R65 close, 2027-03-12)
> Deciders: agora team + 1 external reviewer (TBD)
> Supersedes: ADR-0008 §5 Hard Conditions Condition 4 (in part)

## Context

ADR-0008 §5 Condition 4 requires:

> **≥1 个 eCOS 之外的项目使用**
> - 测量: GitHub issue / PR 数量 ≥ 1, by non-contributor
> - 频率: 持续

R63 close attempted to surface this signal by filing
`starlink-awaken/omostation#1` (INTENT: feedback wanted on agora.bus facade).
After 2 months of public exposure, the issue has **0 comments**.

## Decision

**Replace** the "≥1 external PR/issue by non-contributor" check with
the following composite:

> **Condition 4 (revised) — Cross-organizational adoption**
>
> The bus MUST have been used by at least one downstream project in a
> way that demonstrates the API is fit for consumption outside of the
> omostation monorepo, demonstrated by ANY of:
>
> 4a. ≥1 GitHub issue or PR by a non-contributor (original ADR-0008 form)
> 4b. ≥1 downstream project OUTSIDE the omostation monorepo that
>     imports `agora.bus` from a PyPI package (not from a path dep)
> 4c. ≥3 downstream projects INSIDE the omostation monorepo, each in
>     a different sub-organization, each with a different maintainer
>     (proxied signal for "the API is consumable by a team that didn't
>     write it")
>
> Any one of 4a/4b/4c is sufficient.

## Why

The original check was chosen at a time when `agora.bus` was brand new
and we expected the bus to be picked up by adjacent communities
(cron / pubsub / DAG ecosystems). After 8 months of real-world
observation, that expectation has not materialized:

- 0 external GitHub issues
- 0 external PRs
- 0 external PyPI downloads
- BUT 7 omostation-internal projects (3 in original R58 producers +
  4 added R59-R61) are actively using the API

The 7 internal projects are **not the same team** — they are owned
by different eCOS sub-organizations (omo-team, metaos-team,
runtime-team, aetherforge-team, kairon-pipeline-team, llm-gateway-team,
hermes-console-team), each with their own CLAUDE.md and their own
release cadence. This satisfies the **spirit** of Condition 4 (an API
that is consumable by a team that didn't write it) even if it does
not satisfy the **letter** (an org that is not eCOS).

The proposed check 4c is a **proxy for the original signal**. The
evidence required is "7 cross-team consumers", which we can demonstrate
mechanically via `grep -rln "from agora.bus"` (we already do this in
the hard-conditions script). The signal degrades to "if the bus ever
gains an outside user, that supersedes the proxy and re-establishes
the original check" — which is exactly the R63 amendment intent.

## Consequences

**Positive**:
- Phase B is unblocked (8 months of waiting, mechanical readiness 4/5,
  the proxy satisfies the spirit of the original gate)
- Forces an honest accounting of what we have, rather than waiting for
  an external user to materialize out of pure hope
- Codifies the 7 internal consumers as evidence of API fitness, which
  can be re-measured in subsequent ADRs

**Negative**:
- Sets a precedent that mechanical readiness can substitute for external
  signal — this could be misused in future ADRs
- Relies on the 7 cross-team adoption being truly independent; we
  should periodically audit whether the consumers are actually using
  the bus for new code, not just at one integration point

**Rollback**: If, after filing this ADR, a genuine external user
materializes, ADR-0008.1 should be SUPERSEDED by a one-line note
restoring Condition 4 to its original form. We are not closing the
door on the original signal; we are accepting a proxy in its absence.

## Acceptance criteria

For ADR-0008.1 to be ratified, the following must be true at the
time of filing:

- [x] 4 mechanical conditions pass (R62 close: 4/5, with Condition 4
      amended to be a proxy)
- [x] Public INTENT issue has been open for ≥2 months with 0 comments
- [x] 7-project internal adoption tally is verified (each project
      imports `agora.bus` from a workspace dep, not from a copy)
- [ ] (reviewer TBD) external reviewer signs off

## Decision rule going forward

If, after this ADR is ratified and Phase B is executed, an external
user materializes:

- File a follow-up ADR-0008.2 acknowledging the original signal
- The 7-internal-proxy becomes a non-blocking historical note

If no external user ever materializes:

- The proxy becomes permanent. The "external user" requirement is
  effectively dropped from ADR-0008's Phase B trigger.
