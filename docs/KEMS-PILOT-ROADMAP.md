# KEMS 分阶段落地路线

> 对应业务输入：卫健委《KEMS场景分析与需求描述》2026-07-30。本文记录可交付的工程边界，不把需求文档中的目标指标冒充为当前能力。

生产化实施方案见 [`docs/KEMS-PRODUCTION-PLAN.md`](KEMS-PRODUCTION-PLAN.md)，其中定义 OCR 质量治理、正式 UI、持久化图谱、OMO 派发、真实评测集和预测模型的 M0～M7 交付顺序与放行门。

## 当前判断

KEMS 的正确落地顺序是“先证据闭环，再扩大场景，再接模型增强”。KOS 已经提供 Markdown、TXT、DOCX、PDF、XLSX 的通用解析与索引入口；KEMS 层负责工作空间边界、业务结构、运行记录、人工复核和评测，不把业务规则塞进通用索引器或 OMO 治理层。

## 已落地的能力链

`受控文件 -> KOS 格式 handler -> KEMS 场景分析 -> 证据化结果 -> 运行记录 -> 人工/模型增强`

输出包括：

- 标题、文种、发布单位、文号、日期、主题词
- 摘要、关键要点、行动要求
- 每个关键结果对应的原文行号和摘录
- 未识别字段的人工复核标记
- 输入文件 SHA-256，便于结果与原件绑定

规则分析是默认基线，不调用外部模型、不生成无证据的事实。模型增强只能通过 provider 接口接入，并且每条模型结论必须引用基线证据；引用不合法时自动回退到规则结果并标记复核。

## 分阶段路线

### P0：政策文件处理基线

- 完成多格式解析后的领域结构化提取
- 建立 `kems.policy-analysis.v1` 输出契约
- 结果带来源摘要和证据引用
- 用合成卫健委政策样本做回归测试

交付契约：`kems.policy-analysis.v1`。

### P1：受控导入与可追踪闭环

- 受控工作空间根目录、扩展名、大小和 symlink 校验
- 计算 SHA-256 后再进入 KOS handler
- `kems.run-record.v1` 关联 request、场景、来源哈希、证据和验证引用
- 生产模式要求人工批准，缺失证据的完成记录直接拒绝
- 用 fixture 评测报告区分“通过”和“需要复核”，不虚报生产准确率

### P2：业务场景扩展

- 行政复议：案件总量、状态/地区维度、高风险记录和证据
- AI 应用调查：反馈量、进度/单位维度、缺失字段和补报建议
- 三医信息化：会议任务、责任人、截止时间、缺失责任约束
- 每个场景使用独立输出 schema，后续再接报告模板和知识关系

### P3：模型增强与评测

- 用可替换 provider 生成自然语言摘要和结论
- 每条 claim 必须携带基线 evidence index
- 非法或无引用模型输出自动回退，并保留 `model_output_rejected`
- 用人工维护 fixture 做字段级评测，评测结果明确标记为 fixture 状态
- 只有积累真实标注数据后，才进入趋势预测和问题检测

## 验收口径

所有阶段都不验收“模型看起来很聪明”，验收以下事实：

1. 同一输入重复运行结果稳定。
2. 关键字段能定位到原文行号和摘录。
3. 缺失信息会标记复核，不会静默编造。
4. 支持的文件由 KOS handler 负责解析，领域规则与格式规则解耦。
5. 测试只使用合成数据，不把真实卫健委材料放进仓库。
6. 受控导入不能越出配置工作空间，生产运行必须有人审。
7. 每个业务场景都有稳定 schema、review flags 和 evidence。
8. 模型结论没有合法引用时不会进入最终结果。

## 当前生产化阶段

当前处于“工程核心完成，生产闭环未完成”阶段。下一步优先启动 M0 基础契约、M1 OCR 质量治理和 M2 真实标注评测集；持久化图谱、正式 UI 和 OMO 派发依赖统一运行与证据契约，预测模型最后进入影子运行。

## 仍未完成的业务能力

当前仍未完成的产品化能力包括：OCR 质量治理、协作编辑、持久化知识图谱、正式调查表单与通知工作流、任务派发到 OMO、报告模板渲染、真实数据评测集和预测模型。这些不是本次规则分析核心的隐性承诺，应分别立项并补齐权限、审计和数据脱敏方案。
