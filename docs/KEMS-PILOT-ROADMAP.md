# KEMS 第一阶段落地路线

> 对应业务输入：卫健委《KEMS场景分析与需求描述》2026-07-30。本文记录可交付的工程边界，不把需求文档中的目标指标冒充为当前能力。

## 当前判断

KEMS 目前适合从“政策文件接收与处理”切入，而不是同时铺开五类场景。KOS 已经提供 Markdown、TXT、DOCX、PDF、XLSX 的通用解析与索引入口；第一阶段的缺口是把解析结果变成卫健委业务可审阅、可追溯、可复验的结构化结果。

## 本次垂直切片

`文件 -> KOS 格式 handler -> KEMS policy profile -> JSON 结果`

输出包括：

- 标题、文种、发布单位、文号、日期、主题词
- 摘要、关键要点、行动要求
- 每个关键结果对应的原文行号和摘录
- 未识别字段的人工复核标记
- 输入文件 SHA-256，便于结果与原件绑定

当前实现是确定性规则基线，不调用外部模型、不生成无证据的事实。它对应需求中的信息提取、自动摘要和报告生成的底层可验证接口；模型增强应在这份结果之上作为可替换步骤接入。

## 分阶段路线

### P0：政策文件处理基线（本次）

- 完成多格式解析后的领域结构化提取
- 建立 `kems.policy-analysis.v1` 输出契约
- 结果带来源摘要和证据引用
- 用合成卫健委政策样本做回归测试

### P1：真实业务闭环

- 接入卫健委工作文档空间的受控导入入口
- 增加分类、归档、关联文档和版本差异
- 将分析结果写入知识捕获运行记录，关联 trace/request id
- 以人工复核结果建立字段级评测集

### P2：五类场景扩展

- 行政复议 Excel 的维度分析与风险提示
- AI 应用调查的表单、进展和汇总报告
- 三医信息化会议纪要的任务拆解、责任人和截止时间
- 知识图谱关系与跨文档检索

### P3：模型增强与预测

- 用可审计的 LLM provider 生成更自然的摘要和报告
- 所有模型结论必须保留原文证据、模型版本和人工复核状态
- 在有足够真实标注数据后再做趋势预测和问题检测

## 验收口径

第一阶段不验收“模型看起来很聪明”，验收以下事实：

1. 同一输入重复运行结果稳定。
2. 关键字段能定位到原文行号和摘录。
3. 缺失信息会标记复核，不会静默编造。
4. 支持的文件由 KOS handler 负责解析，领域规则与格式规则解耦。
5. 测试只使用合成数据，不把真实卫健委材料放进仓库。

## 仍未完成的业务能力

本次不宣称已经完成 OCR、协作编辑、知识图谱、Excel 复议分析、调查工作流、会议任务协同或预测能力。这些能力应在 P1/P2 按场景逐个形成可验收闭环。
