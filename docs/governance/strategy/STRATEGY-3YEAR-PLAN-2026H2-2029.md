# 织星 / eCOS 三年全面规划（2026H2 – 2029）

> 逐条 bet 拆解、认领协议、验收命令与复盘节律见 **[`docs/plans/3Y-BET-LEDGER.md`](plans/3Y-BET-LEDGER.md)**。
> bet 数量、窗口进度、可认领项为运行时事实，从 `bin/plan/bet-ledger.py status` 读取，不在本文硬编码（doc-ssot-contract）。

## 0. 判断先行

### 0.1 三年的主要矛盾

> **系统的表面积已经超过一个人（加 Agent）能够保持真实的极限。**

实测（2026-08-06）：

| 维度 | 实测值 | 含义 |
|---|---|---|
| 真实源码 | **src 726,412 行 / 3,204 文件**（另 test 350,854 行 / 1,827 文件）/ 18 个项目 | 相当于 50–100 人工程组织的代码资产 |
| ADR | **344 份**，2026-08 前 6 天新增 **85 份**（约 14 份/天） | 每份读 5 分钟需 29 小时；日增量已超人类阅读速度 |
| GaC 治理规则 | **134 条** | 无法逐条复核存在合理性 |
| bin 脚本 | **309 个** | 无人能记住大多数用途 |
| 标准文档 | **53 份** | 规范数量接近代码模块数量 |
| BOS 服务 URI | **200 条** | |
| 治理模式 | **19 条** | |

Review 找到的病灶不是偶发错误，是同一结构性原因的投影：

```
Agent 以机器速度产出治理与文档资产
    ↓
人类以人类速度验证
    ↓
产出 >> 验证 ⇒ 未验证资产累积
    ↓
未验证资产被后续决策当作事实引用
    ↓
战略建在未经核对的地基上
```

**这个循环不会自愈，因为每一次"加强治理"都在加大分子。**

### 0.2 三年战略主轴

| 年 | 主轴 | 核心动作 | 净方向 |
|---|---|---|---|
| **Y1 (2026H2–2027H1)** | **收敛与接通** | 表面积净负增长；接通感知面与结果面；一个场景走完真实闭环 | **减法** |
| **Y2 (2027)** | **深化与放权** | 心智模型可用；自主等级由数据驱动上升；2–3 场景稳定 | 加法（受控） |
| **Y3 (2028–2029)** | **复利与外扩** | 跨场景学习产生复利；有选择对外 | 加法 |

**Y1 的成功标志是"系统变小了"——但"小"的判据是逐项冗余清零，不是行数百分比。**

具体见 §2.2：已识别冗余（知识层双头、无消费者模块、无违规历史的 required 规则、零调用脚本、休眠项目）全部清零，
且保护量未被牺牲（`test_loc` 不低于基线、ADR 文件总数不减少）。若 Y1 结束时这些冗余仍在，整个三年规划失败——不论期间交付了多少功能。

> 不用「代码行数/ADR 数/规则数不降反增」作判据，因为这三个数字都能靠删测试、删 advisory 规则、删历史 ADR 变好看，
> 而那三件事的真实收益分别是负、零、负（详见 skill `bet-execution` §4.5 删除收益矩阵）。

### 0.3 愿景（收窄版）

> **织星是夏明星一个人的业务操作系统。它的唯一职责是：把外部进来的信号，变成他愿意署名发出去的东西，并且记住他每次改了什么。**

**证伪条件**：若到 2027-12-31 未能连续 12 周每周产出 ≥ 3 条被本人采纳的建议，则本定位被证伪，应转为纯知识管理工具或关停。

**gbrain + kairon 占全系 51%，承担的是同一件事——知识的存与取。最大可合并空间。**

### 1.2 结构诊断：中段过厚，两端缺失

分层设计自洽，依赖方向清晰。**问题不在设计质量，在形状。**

```
  【缺失】感知面          【过厚】中段 src 72.6 万行       【缺失】结果面
  真实外部信号             L0-L4 / I0 / X1-X4 / M0        人类接受/修改/拒绝
  0 条/周                  344 ADR / 134 规则             0 条记录
```

这个形状解释了几乎所有已知病症：没有输入，主动性只能主动审计自己；没有结果，价值只能用代理量冒充；没有反馈，学习只能是口号；中段过厚，治理只能靠加规则维持秩序。

### 1.3 承重判定

| 层/项目 | 判定 | 依据 |
|---|---|---|
| ecos / agora / omo / runtime / cockpit | **承重** | 删任一，Mesh 链断 |
| kairon-kos / gbrain | **承重但重叠** | 都在做知识存取 |
| aetherforge | **半承重** | 模型网关刚需，mesh/swarm 无消费者 |
| cockpit-ui | **承重且薄弱** | 唯一界面，缺 outcomes 面板 |
| metaos / model-driven / l4-kernel | **待验证** | 与主链耦合弱 |
| c2g / bus-foundation | **半承重** | 使用频率低 |
| omo-debt | **可并入 omo** | 3816 行无独立必要 |
| family-hub / observability | **休眠 / 空壳** | 10 / 1 文件 |

**M0（model-driven）**被定义为"被四层消费的横切框架"，但在 Mesh 主链（admission → dispatch → lease → evidence）里找不到必经位置。Y1 需给明确判定：接入主链，或降为库。

### 1.4 五个架构级病灶

1. **知识层双头**（gbrain × kairon-kos）：占全系 51%。MOS 本意统一控制面，但适配器成熟度实测为 Neo4j `off_until_NEO4J_URI` / mem0 `stub_optional` / memtheta `partial_simulation` / graphiti `optional_tier2`。**MOS 目前是一层未生效的门面。**
2. **治理面自我引用**：治理系统的输入几乎全部来自自身状态，构成闭合回路，回路内的任何"改善"都不携带外部信息。
3. **编排层不支持真实业务形状**：不支持长时等待、往返修订、并行会签。
4. **Agent 是无状态反射弧**：366 行，`node_output → 阈值 → 三态`。
5. **交付物可静默消失**：`journey-runner.py` 等 v10 核心产物从未 git add，工作树清理后无 blob 可恢复（2026-08-06 当天实测发生两次）。子模块指针三方漂移并存。

### 1.5 架构判定

> 结构正确，形状错误，表面积超限。不需要重新设计架构，需要：**消除已识别的冗余（而非砍固定比例），长出两端，把编排升级到真实业务形状，把 Agent 升级到有状态心智。**

「砍掉 1/3 体积」这个原始表述已废除——它是比例目标，不指向具体冗余，会诱导执行者删测试。**减法必须逐项指名道姓。**

## 2. 愿景层

### 2.1 边界（不做什么）

| 不做 | 理由 |
|---|---|
| 多租户 / 组织协作 / SaaS 化 | "一个人的" |
| 通用 Agent 平台 / Agent 市场 | 供给侧扩容 |
| 无人类出口的自动化 | 无法验收即无法证伪 |
| 无监督自我进化 | 学习须锚定人类修订差异 |
| 物理多机 / 分布式集群 | 已 deferred，三年内不解冻 |
| 追求能力/工具/场景数量 | 是成本不是资产 |

### 2.2 三年后可验收状态（2029-06）

1. **每周 ≥ 5 条主动产出被采纳**，采纳率 ≥ 40%。
2. **本人修订率逐年下降**：Y1 基线 → Y2 降 20% → Y3 降 40%。
3. **可持有性守住**：已识别冗余全部清零（知识层双头、无消费者模块、无违规历史的 required 规则、零调用脚本、休眠项目），且保护量未被牺牲（`test_loc` 不低于基线、ADR 文件总数不减少）。

> **2026-08-06 复盘修正**：本条原为「表面积 ≤ 2026-08 的 70%（代码 ≤69 万行 / ADR ≤120 / GaC ≤80）」，三个数字均为拍定且**可被有害优化**——删测试（占 33%）、建删 PASW worktree（占旧基线 33%）、删无害的 advisory 规则，都能让指标漂亮而不产生任何真实收益。已按铁律 D6 改为「逐项冗余清零 + 保护量守住」。测量口径同步从文件系统扫描改为 `git ls-files --recurse-submodules`。

三条缺一即部分失败，需在当年季度门做出关停或收窄决定。

## 3. 三年架构演进

### 3.1 目标架构：四面一脊

现有分层描述**代码归属**，不描述**信息流动**。补充按信息流动划分的四个面：

```
   外部世界 ──→ ① 感知面 Perception（新增）
                  信号源注册 / 去重 / 幂等
                        ↓ Signal
                ② 认知面 Cognition（新增薄层）
                  世界模型 / 自我模型 / 意图模型 / 因果模型
                        ↓ Intent
        ③ 执行脊柱 Workflow Mesh（已存在，需硬化）
        admission → dispatch → lease → run → evidence → verify
                        ↓ Deliverable
                ④ 结果面 Outcome（新增）
                  人类裁决 / 修订差异 / 归因
                        └──→ 回流 ② （学习闭环）
```

**三个新面都是薄层，不是新项目**：感知面 → `kairon/iris` + `signal-sources.yaml`；认知面 → `kairon/mos` 的 `agent_belief` 命名空间；结果面 → `omo` 的 `AdjudicationRecorded` + Cockpit `/outcomes`。

### 3.2 项目归并 18 → 8

| 目标项目 | 吸收 | 理由 |
|---|---|---|
| **ecos** | ecos + model-driven | MOF 与 M0 同源，M0 降为库 |
| **agora** | agora + bus-foundation | 路由与事件总线同源 |
| **omo** | omo + omo-debt + c2g | 都是治理面 |
| **knowledge** | **gbrain + kairon** | 最大归并，统一到 MOS |
| **runtime** | runtime + aetherforge | 执行与算力调度合并 |
| **cockpit** | cockpit + cockpit-ui | 人机入口本是一件事 |
| **metaos** | metaos | Y1 证明主链必经位置，否则 Y2 并入 omo |
| **l4-kernel** | l4-kernel | 保留 |
| 退役 | family-hub、observability | 归档 |

**归并不是搬文件，是删代码。**

> **2026-08-07 修正**：本条原验收标准为「合并后行数 < 原和的 70%」，与 §2.2 的减法判据直接矛盾，
> 是漏改。它是典型的可有害优化指标——达标最便宜的路径是删测试（gbrain + kairon 的测试占比高），
> 而不是消除重复。按铁律 D6 改判据：

归并验收看三条，缺一即为「拼接」，退回重做：

1. **重复能力已消除**：合并前两侧各有一份的知识存取实现（向量检索、图谱写入、记忆读写），合并后只剩一份，`rg` 可证无第二处实现。
2. **消费者无感**：调用方 import 路径统一，且不存在「新旧两套 API 并存」的兼容层残留。
3. **保护量守住**：`test_loc` 不低于合并前两侧之和（去重后的测试可以合并，但覆盖的行为不能减少）。

行数下降是上述三条达成后的**自然结果，不是目标本身**。若三条都达成而行数没降，说明本就没有重复，那么这次归并的立项依据不成立——该退回的是立项，不是实现。

### 3.3 认知面：心智模型四件套

| 模型 | 承载 | Y1 缺口 |
|---|---|---|
| 世界模型 | MOS `world_snapshot` | 无外部输入 |
| 自我模型 | MOS `capability_calibration` | 无历史表现维度 |
| 意图模型 | `goals/current.yaml` + tasks | 内容空/陈旧 |
| 因果模型 | MOS `decision_outcome` | 完全缺失 |

```yaml
world_snapshot:          # 世界模型
  scene_id, observed_at, source, facts[], delta_from_previous

capability_calibration:  # 自我模型
  capability, scene_id, invocations,
  human_accepted_as_is, human_edited, human_rejected,
  avg_edit_distance, calibration   # = accepted_as_is / invocations

decision_outcome:        # 因果模型（枢纽）
  decision_id, scene_id, node, model_used, action, confidence, cost_estimate,
  human_verdict,         # agreed | overridden | ignored  ← 结果面回填
  human_note, closed_at
```

**`decision_outcome` 是整个三年规划的枢纽**：评测集样本源 + 放权判据 + 漂移监控 + 跨场景学习输入。

### 3.4 自主性阶梯

| 级别 | 升级硬门 | 降级触发 |
|---|---|---|
| L0 观察 | 默认起点 | — |
| L1 建议 | 累计 ≥ 20 次 L0 观察 | — |
| L2 受审执行 | `calibration ≥ 0.6` + 连续 30 次无 rejected + 有回滚 | 单次 rejected 或 calibration < 0.5 |
| L3 自动 | `calibration ≥ 0.85` + 连续 100 次 + 预算上限 + 影响可逆 | 任一 override |

**放权由数据触发，不由人拍脑袋，也不由 Agent 自我声称。**

### 3.5 迁移路径与不可逆点

| 阶段 | 动作 | 可逆性 |
|---|---|---|
| Y1 Q1 | 感知面接通、结果面建立、shadow 档上线 | 可逆 |
| Y1 Q2 | omo-debt / c2g 并入 omo，model-driven 判定 | 可逆（tag 保留） |
| Y1 Q3 | **gbrain + kairon 归并** | **不可逆** |
| Y1 Q4 | aetherforge 并入 runtime | 半可逆 |
| Y2 | 认知面全量、L2 放权 | 可逆（降级机制） |
| Y3 | 跨场景学习、有选择对外 | 对外需单独 ADR |

**唯一真正不可逆点是知识层归并**，必须放在 Y1Q3：早了 MOS 未证明可用，晚了双栈维护会吃掉 Y2 全部余量。前置硬门：MOS 已是唯一读写路径 ≥ 8 周、双栈一致性 ≥ 99%、有回滚 tag。

## 4. 功能规划

三年内只承认四类功能。

**F1 收件（Y1）**：信号源管理、决策收件箱、一键裁决（采纳/改后采纳/忽略）、修订差异捕获。**没有它，其余全部无法验证。**

**F2 旅程（Y1–Y2）**：场景卡编辑（五档生命周期）、旅程时间线、长时等待、往返修订、并行会签、失败接管。

**F3 记忆（Y1–Y2）**：统一召回、召回可解释、召回被引用率、校准视图、遗忘与整理。

**F4 治理（Y1 做减法）**——唯一目标为"变少"的域：

| 项 | Y1 目标 |
|---|---|
| GaC 规则 | 134 → ≤ 80 |
| ADR | 344 → 有效集 ≤ 120 |
| bin 脚本 | 309 → ≤ 180 |
| 标准文档 | 53 → ≤ 30 |
| 合成协作场景 | 221 → ≤ 40 |

**减法配额制**：新增 1 条 GaC 规则必须删 1 条；新增 1 份 ADR 必须归档 1 份。这是唯一能对抗 §0.1 循环的机制。

## 5. 场景规划

### 5.1 生命周期五档

```
draft → shadow → assisted → supervised → routine
```

**`shadow` 是解锁一切的关键**：不产生业务副作用，因此不需要业务拍板。

### 5.2 三年场景矩阵

| 场景 | 角色 | Y1 | Y2 | Y3 |
|---|---|---|---|---|
| **公文 / 决策收件箱** | **主战场** | shadow → assisted | supervised | routine（限格式类） |
| **工程交付 dogfood** | **数据发生器**（不计价值指标） | shadow | assisted | assisted |
| **知识入库与创作** | **存量变现** | shadow | assisted | supervised |
| 中试平台与政策申报 | 扩展 | 不启动 | draft → shadow | assisted |
| 预测提醒（KEMS） | 扩展 | 不启动 | shadow only | shadow only |

### 5.3 公文场景第一版：砍到 3 node

```
fetch（取邮件） → format_check（规则可判） → inbox（条目 + 问题清单 + 原文定位）
```

不生成草案、不做敏感判断、不分发。**最快拿到 calibration 数据的路径。**

必须修正的 DAG 缺陷：`sensitive_check --escalate--> dispatch` 改为 `escalate → human_hold`（显式 waiting 节点）。

### 5.4 场景卡必须新增赌注声明

```yaml
bet: "如果系统每周替我处理 3 份公文的格式与敏感项初检, 我每周省 2 小时, 且不增加外发风险。"
falsifier: "连续 4 周, 若人类修改率 > 70% 或出现 1 次敏感项漏检, 此赌注证伪, 场景退回或关停。"
```

### 5.5 迭代三维度（每次只动一个，观察两周）

| 维度 | 动作 | 公文场景实例 |
|---|---|---|
| 输入宽度 | 1 类 → N 类 | 借调群邮件 → +OA → +纸质扫描 |
| 自主等级 | L0 → L1 → L2 | 只标注 → 出草案 → 自动格式修正 |
| 动作范围 | 只读 → 建议 → 写 → 发 | 检查 → 生成草案 → 改稿 → 直发（**永不到**） |

## 6. 应用形态

三年内只做一个形态：**一个收件箱 + 一条时间线 + 一个记忆面板**。

| 界面 | 频率目标 | 交付 |
|---|---|---|
| `/inbox` 决策收件箱 | **每日** | Y1 Q1 |
| `/journeys` 旅程时间线 | 每周 | Y1 Q2 |
| `/outcomes` 结果与校准 | 每周 | Y1 Q2 |
| `/memory` 记忆检索 | 按需 | 已有基础 |
| `/signals` 信号源健康 | 按需 | Y1 Q1 |

**判定标准只有一条：`/inbox` 是否成为每日必开的界面。** 一年后仍不会每天打开，说明未产生足以改变习惯的价值，应关停而非继续加功能。

**不做**：移动 App、聊天机器人式入口、Agent 编排可视化画布、插件市场。

## 10. 治理节律

| 节律 | 必须回答 |
|---|---|
| 每日 | 收件箱清空了吗？ |
| 每周 | 这周哪条建议真的省了时间？哪条是噪音？ |
| 每月 | 表面积涨了还是跌了？出现未验证资产了吗？ |
| 每季度 | 场景该升档、降档还是关停？ |
| 每年 | §2.2 三条是否在轨？愿景是否被证伪？ |

**治理预算铁律**：治理活动占总工作量 ≤ 25%（当前口径 40%，Y1 内下调）。

> **2026-08-07 D6 复查**：这条同样是比例目标，且分母可膨胀——达标最便宜的路径是**多写非治理代码**把分母做大，
> 而那正是 Y1 要压制的表面积增长。第二便宜的路径是把治理工作重新归类为"工程工作"，纯记账游戏。
>
> 保留本条，但补两个约束，缺一则本条不成立：
> - **分母锁定**：口径固定为「新增/修改的 git 跟踪行数」，按 `git ls-files` 计，不含生成物。分母增长本身要在月度复盘里单独解释。
> - **绝对量兜底**：治理活动的**绝对**投入（人时）逐季不得上升。比例达标但绝对量上升 = 未达标。
>
> 若两个约束都嫌重，正确做法是**降级为观察指标**（只看趋势不设阈值），而不是留着一个可被游戏的硬指标。
