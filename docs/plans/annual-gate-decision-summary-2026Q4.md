# T1-04 年度门重基线 — 决策摘要

> 目的: 供决策者快速拍板。完整论证见 `docs/plans/annual-gate-rebaseline-2026Q4.md` + `docs/adr/ADR-0200`。

## 一句话结论

**690K 的年度门已无法守住, 且守门会诱导谎报。建议调门到 1,100K + 切换净值口径。**

## 为什么需要改

| 事实 | 数据 |
|---|---|
| 当前 src_loc(总量) | 1,663,966 |
| Y1Q4 门值 | code_loc <= 690,000 |
| 缺口 | **已超门值 141%** |
| 真实业务增长(净值口径) | **~+145K** |
| gbrain 重写噪音 | +179K/-179K, 净贡献仅 **+360**(纯重写) |

核心矛盾: 门值 690K 按 Y1 初基线制定, **未纳入** ①gbrain 整体重写噪音 ②cockpit-ui/omlxc/runtime 等新项目出生。守原门 = 刻舟求剑, 会诱导 T3-01 式谎报。

## 三个情景(选一)

### ☑️ A. 守原门 (code_loc <= 690K)
- 净值口径也守不住(726K 基线 + 145K 净增长 = 871K > 690K)
- **不推荐**: 必然触发门失败, 且无法区分"真实膨胀"与"项目出生/重写"

### ✅ B. 调门到 1,100K (推荐)
- 依据: 净值承载 ≈ 1,480K(剥离 gbrain 重写噪音), 预留 20% 余量
- 效果: 允许项目出生 + 工具 churn, 仍约束"净膨胀"
- ADR-0200 已按此预写(Proposed), 批示后转 Accepted 即可落地

### 🔶 C. 拆门为分项目门
- `_root <= 700K AND 各子项目净增长 <= 预算`
- 优点: 独立预算; 缺点: 复杂, 且 _root 门本身已 677K+
- **建议作为 B 的补充观测, 不单独替换**
