## 〇、先自曝: 昨天方案的两个前提问题

### 问题 1: "964 个提案"的成色存疑 【动脉 A 前提动摇】

## 二、愿景对齐审议

用户愿景 (PREFERENCE/DA 记忆): **数字大脑 P0工作→P1健康→P2家庭→P3个人→P4教育**,
本质是"agent 为人的生活降本增效", 而非"agent 建设 agent 体系"。

| 三动脉 | 与愿景对齐? | 审议 |
|--------|------------|------|
| A 提案→行动 | ⚠️ 间接 | 管的是"体系自我改进", 不是"用户生活任务"。若 964 提案全是体系内的鸡毛, 跑通也只是内循环 |
| B 事件分级 | ✅ 直接 | 信噪比提升直接服务所有域 (含未来健康/家庭域) |
| C Cell 点火 | ⚠️ 风险 | 为体系而体系。若无真实用户任务进 Cell, 点火=烧空转引擎 |

**愿景视角的残酷问题**: 整个体系当前最大的断链不是"提案没人采纳",
是**"用户生活的真实任务没有进来"** (任务邮件 0.14%, OA/日历未接)。
数字大脑在等敌人, 敌人在别的系统里。

**因此愿景对齐的重排**: 信号源扩展 (原动脉 D/P2) 应该升到与动脉 A 同级——
没有真实输入, 内循环跑得再漂亮也是空转。

## 三、审议结论: 修正后的路线

### 原方案的问题
1. 动脉 A 前提未验证 (964 提案成色)
2. 价值方向偏"体系内循环", 与"生活降本"愿景有偏移
3. 在表面积超限的体系上继续"加连接"而非"先减后连"

### 修正: 「先减 → 接真源 → 再连内循环」三段式

```
第 0 段 (先减, 1 周) — 支付防腐债
  ├─ dormant 大扫除: Cell×10/planner/verifier/Goal-4X 逐个判定
  │   "6 个月内有激活计划?" 无 → 归档 (用户'一定要用起来'原则
  │   的正确读法: 有计划地用, 不是无限期占着)
  ├─ 提案池清淤: 964 new 做质量分层, 机器流水账批量归档
  └─ 过期 claims 清 93 个僵尸
  判据: script_baseline 从 504 下降; proposal pool 从 964 降到 <100

第 1 段 (接真源, 2-3 周) — 让真实任务流进来
  ├─ 信号源: 日历 (系统日历可本地读, 无单位网络依赖) 先于 OA
  ├─ auto-journey 首任务实弹 (等/造一封真实任务邮件)
  └─ 北极星补真指标: 工作交付从"待接入"→接 mail-journey 产出
  判据: 真实任务信号 ≥1/周; journeys ≥1; X3 工作交付有真数

第 2 段 (再连内循环, 3 周+) — 提案管道但只用真提案
  ├─ 动脉 B 事件分级 (维持, 低风险)
  ├─ 提案 triage 只对 <100 个真提案跑 BCOS 四阶段
  ├─ 首批 adopted 提案派单 → 六蜂群 Goal 模式最小启动 (1 轨道, 非四轨)
  └─ Cell 是否点火: 看第 1 段任务量 — 有稳定 DAG 需求才点, 否则继续归档
  判据: adoption 0→5 (真提案口径); claims 恢复活跃; 减法跑赢加法
```

### 与原方案的差异表

| S1 直接上 triage | 先减法清淤 | 964 垃圾提案会污染 triage |

| Cell 三周内点火 | 条件触发 | dormant 激活要有真实负载依据 |

## 四、给用户的三个决策点

1. **dormant 判定权**: Cell×10/planner/verifier 按"6 个月激活计划"判定归档——
   你之前说"一定要用起来", 是否接受"无近期计划=先归档可快速恢复"的读法?
2. **信号源优先级**: 日历 (本地可读, 快) vs OA (单位网络, 价值高但依赖环境) 先接哪个?
3. **北极星真指标口径**: 工作交付用什么算"真完成"? (journey 走完 7 步? 邮件发出?
   你人工确认?) — 这个口径只有你能定。
