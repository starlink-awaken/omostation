### 3.2 统一事件 Schema

```yaml
# 事件类型定义
events:
  governance:
    - governance:check.passed       # 治理检查通过
    - governance:check.failed       # 治理检查失败
    - governance:drift.detected     # 漂移检测
    - governance:drift.remediated   # 漂移修复

  tool:
    - tool:coverage.updated         # 覆盖率更新
    - tool:archived                 # 工具归档
    - tool:invocation.recorded      # 工具调用记录

  scene:
    - scene:activated               # 场景激活
    - scene:deactivated             # 场景停用
    - journey:started               # 旅程开始
    - journey:completed             # 旅程完成
    - journey:failed                # 旅程失败

  doc:
    - doc:stale.detected            # 文档过期检测
    - doc:refreshed                 # 文档刷新

  value:
    - value:time_saved              # 时间节省记录
    - value:outcome.recorded        # 结果记录
```

### 3.3 统一健康评分 (UHS)

```python
# 统一健康评分计算
UHS_WEIGHTS = {
    "tools": 0.20,        # 工具 CI 覆盖率
    "governance": 0.20,   # 治理规则合规率
    "scenes": 0.15,       # 场景激活率
    "docs": 0.10,         # 文档保鲜率
    "value": 0.25,        # 价值可证度 (North Star)
    "runtime": 0.10,      # 运行时健康度
}

def compute_uhs(scores: dict[str, float]) -> float:
    """计算统一健康评分 (0-100)"""
    return sum(UHS_WEIGHTS[k] * scores[k] for k in UHS_WEIGHTS)
```

## 四、North Star 可证化

### 4.1 问题根因

```json
{
  "status": "unprovable",
  "reason": "principal_id_required"
}
```

当前系统无法将工程产出（PR、测试、工具）关联到个人时间节省。

### 4.2 解决方案

```
┌──────────────────────────────────────────────────────────────┐
│              North Star 可证化架构                            │
│                                                              │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐   │
│  │ 时间追踪器   │    │ 产出记录器   │    │ 价值计算器   │   │
│  │ TimeTracker  │───→│ OutcomeLogger│───→│ ValueCalc    │   │
│  └──────────────┘    └──────────────┘    └──────────────┘   │
│         │                   │                   │           │
│         ▼                   ▼                   ▼           │
│  review_duration    draft_accepts      time_saved =        │
│  estimated_saved    revision_count     Σ(saved - review)   │
│                                                              │
│  ┌──────────────────────────────────────────────────────┐   │
│  │ 4-Week Gate (保持不变)                                │   │
│  │ - 每周 ≥3 个 qualifying episodes                     │   │
│  │ - 连续 4 周 → readiness: passed                      │   │
│  └──────────────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────────────────┘
```

### 4.3 实施路径

1. **Phase 1**: 接入 `principal_id`（从 Constitution 获取）
2. **Phase 2**: 在 Agent Workflow closeout 时自动记录 `review_duration` 和 `estimated_saved`
3. **Phase 3**: 产出物（Draft）被接受时自动发出 `value:time_saved` 事件
4. **Phase 4**: North Star 从 `unprovable` → `collecting` → `proven`

## 六、工具生命周期管理

### 6.1 问题根因

- 365 工具，19% CI 覆盖
- P3 归档是死 stub（`--archive` 未实现）
- 无减法机制，工具只增不减

### 6.2 解决方案

```
┌──────────────────────────────────────────────────────────────┐
│              工具生命周期状态机                               │
│                                                              │
│   draft → candidate → active → deprecated → archived        │
│     │         │          │          │           │           │
│     │         │          │          │           │           │
│  创建PR   CI+test    90天无调用   归档到      删除          │
│   review   接入      自动降级    _archive/    代码          │
│                                                              │
│  ┌──────────────────────────────────────────────────────┐   │
│  │ 减法配额 (Subtraction Quota)                          │   │
│  │ - 每季度至少归档 5% 的 deprecated 工具                │   │
│  │ - 新工具接入必须伴随旧工具归档                        │   │
│  └──────────────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────────────────┘
```

### 6.3 实施路径

1. **tool-governance `--archive` 实现**：
   - 将工具从 `ssot/tools/` 移到 `ssot/tools/_archive/`
   - 从 CI workflow 中移除引用
   - 更新 `ci-surfaces.yaml` 状态为 `archived`

2. **自动检测 deprecated**：
   - 90 天内无 CI 调用 → 自动标记 `deprecated`
   - 发送通知给工具负责人

3. **减法配额执行**：
   - 每季度运行 `tool-governance --enforce-subtraction`
   - 确保 deprecated 工具被归档

## 十三、总结

本方案通过 6 个 Phase 的实施，将架构成熟度从 54% 提升到 90%。核心转变：

1. **从工程度量到价值度量**：North Star 可证化
2. **从检测到修复**：告警真正阻断 + 自动修复闭环
3. **从增到减**：工具生命周期管理 + 减法配额
4. **从手动到自动**：场景激活自动化
5. **从分散到统一**：统一测量平面 + 统一健康评分
