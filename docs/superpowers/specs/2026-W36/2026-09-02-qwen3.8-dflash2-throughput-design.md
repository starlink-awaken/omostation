# Qwen3.8-27B/70B 混合精度量化与 DFlash 2 吞吐翻倍

## Intent

在 MBP M5 Max (128GB) 与 Mac mini M4 (24GB) 双机部署 Qwen3.8-27B Instruct
(Q4_K_M 主力权重) + DFlash 2 块扩散草稿模型, 通过雷雳 5 算力织网实现:

- 首字延迟 TTFT < 15ms
- 端到端吞吐量 ≥ 120 tokens/s
- 投机解码加速比 ≥ 2.4x

## Contract

- `projects/omlxc/src/omlxc/dataplane/speculative.py` 新增 DFlash 2 块扩散
  草稿引擎入口 (`Dflash2SpeculativeDecoder`), 与既有 `SpeculativeDecoder`
  接口兼容, 接受 `model_path`、`draft_model_path`、`block_size` 三个参数
- `projects/omlxc/src/omlxc/dataplane/paged_kv.py` 改造 paged_kv cache 使其
  支持 128k 上下文, 验证无显存泄漏与碎片 (通过 `make memcheck-128k`)
- `docs/reports/2026-09-03-qwen3.8-dflash2-benchmark.md` 输出双机 TTFT、
  throughput、加速比、命中率四项核心指标, 附 128k 压测显存曲线
- `.omo/_knowledge/retros/BET-Y1Q3-T10-114.md` 写入 closeout 复盘
  (含电路熔断阈值: 命中率 <40% 时降级自回归标准解码)

## Non-goals

- 不使用损失精度的极度激进量化 (保留 Q4_K_M 及以上主力权重)
- 不引入新的模型格式 (GGUF 仍为唯一持久化形态)
- 不动 `omlxc` BOS 路由 (ADR-0226 已固化)

## Risks

- **R1 显存泄漏**: 128k 上下文在 M4 24GB 上极易 OOM, 必须用 paged KV + swap
- **R2 投机命中率**: 草稿模型与主模型分布失配时命中率 < 30% 等同浪费
- **R3 雷雳 5 链路抖动**: 双机传输延迟 P99 可能拖慢首字

## Circuit Breaker

- 投机草稿命中率 < 40% → 自动降级为自回归标准解码 (no speculative)
- 显存使用 > 85% → 切到 offload 模式, 牺牲 20% throughput
- 双机链路断连 > 5s → 单机降级模式继续服务

## Verify

- `uv run python -m omlxc.cli fabric benchmark --model qwen3.8-27b --speculative dflash2`
  期望 exit 0 + report throughput ≥ 120 tokens/s + 加速比 ≥ 2.4x
- `make gac-local-gate` 期望全绿
- `make memcheck-128k` 期望无 OOM + 无 fragmentation > 5%
- `make dflash-hit-rate` 期望 ≥ 40%
