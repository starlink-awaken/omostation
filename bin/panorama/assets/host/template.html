    冻结口径

    分母、样本分区、baseline、metric version 和场景范围在窗口开始前冻结；未冻结的项（如修订负担基线）一律显示 UNKNOWN，不允许事后回填。

    排除无效样本

    测试、合成、无 HumanVerdict 绑定或重复样本独立分区。qualifying=false 的记录计入总量但不进入价值门。

    失败保持可见

    缺失与过期标记为未知；替代必须证明覆盖等价，保留原失败历史。比率型指标在样本不足时判为不可判定，不显示达标。

    📐 回路体系纲领（来自白皮书第14章，静态参考，展开查看）

    六类规范回路

    回路类型目的主要周期
    L1 主价值回路端到端闭环将真实信号变成人类认可结果分钟–周
    L2 认知增强回路Reinforcing让系统越来越理解主人和情境Episode–月
    L3 执行控制回路Balancing使实际执行回归授权目标秒–小时
    L4 信任—自治回路R+B 配对在可靠证据基础上扩大安全委托周–季度
    L5 进化回路R+B 配对改善系统而不扩大失控复杂度周–月
    L6 元体系抗熵回路Balancing维持对象、关系、权威和实现一致日–季度

    安全、可靠性和资源平面各自提供局部平衡回路，但它们只能约束上述主回路，不能另建业务目标。

    三个增强回路

    R-G1 人机认知增强：真实裁决 → 情境理解提高 → 修订负担下降 → 委托增加
    R-G2 信任与委托增强：可验证成功证据 → 信任提高 → 可授权范围增加
    R-G3 能力复用增强：通用契约增加 → 接入成本下降 → 契约成熟度提高

    五个控制回路

    B-C1 目标—结果误差控制（KR vs Outcome）
    B-C2 执行偏差控制（期望 vs 实际 Run）
    B-C3 风险—自治控制（override → 降级 tier）
    B-C4 资源与注意力控制（WIP/成本/打扰）
    B-C5 元体系抗熵控制（orphan/drift → repair/retire）

    完整定义见 白皮书指导 与 白皮书 §14。增强回路必须绑定控制回路，反方向晋升必须慢于降级。

      人类 Principal：最终主权与价值裁决 Constitution / Vision / Values / Risk / Revocation │ 定义目的、边界与授权 ▼ 真实世界 → 感知情境 → 知识与记忆 → 决策体系 │ 形成承诺 ▼ 战略目标组合 → 治理与信任 → 运行与执行 │ Deliverable/Receipt ▼ 价值与进化：Outcome → Verdict → Learning → Proposal └──────────── 反馈到知识、决策与目标 ────────────┘ 横切：安全隐私｜可靠恢复｜资源经济｜时间来源｜人机体验 元体系：本体｜边界｜权威｜关系｜契约｜生命周期｜版本｜一致性｜演进

      🔁 闭环 A：价值闭环

      回答：这次行动是否真正改善了主人的结果？

      Signal → Context → Decision → Goal/BET → Mandate/Policy → WorkflowRun → Deliverable/Receipt → HumanVerdict → Outcome → ValueRecord

      🧬 闭环 B：进化闭环

      回答：系统是否从真实结果中变得更好，而不是只变得更复杂？

      Outcome/Failure → Memory Update → Improvement Hypothesis → Replay → Sandbox → Shadow → Canary → Human/Policy Decision → Promote/Reject/Rollback/Retire

      两个主闭环描述系统的端到端目的；增强回路、控制回路、恢复回路和抗熵回路是嵌套在主闭环中的动力结构，详见 回路观测。

      🎯 八个核心体系 (S1–S8)

      S1 人类主权与宪法体系
      为谁服务、为什么存在、什么永远不能自动决定？
      拥有：Principal identity、Constitution、Values、Risk appetite、Revocation
      不拥有：日常调度、任务执行、价值数据加工
      EXTEND
      落地板块：主权中心 · 全景总览
      S2 感知与情境体系
      真实世界发生了什么，哪些变化值得进入系统？
      拥有：Signal、Source、ContextSnapshot、Freshness、Classification
      不拥有：目标决定、价值裁决、自动进化
      EXTEND
      落地板块：场景系统
      S3 知识与记忆体系
      什么被认为是真的，为什么相信，何时失效？
      拥有：KnowledgeClaim、Belief、Memory、Provenance、Conflict、Decay
      不拥有：把推断自动升级为事实、替 Principal 定义价值
      EXTEND
      落地板块：文档知识 · 知识记忆 · 架构与模型
      S4 战略、目标与组合体系
      长期要赢什么，现在承诺什么，不做什么？
      拥有：Vision、Objective、KR、Campaign、BET、Kill criteria
      不拥有：直接执行任务、把 BET done 自动解释为 KR proven
      EXTEND（先修复权威和覆盖）
      落地板块：3Y台账与甘特 · 接下来做什么
      S5 决策体系
      面对多个选项，为什么选择此行动？
      拥有：DecisionRecord、Options、Trade-offs、Confidence、Supersession
      不拥有：执行、审批高风险动作、宣告价值
      EXTEND
      落地板块：接下来做什么 · 中枢工作台
      S6 治理与信任体系
      什么行动可以发生，需要什么证据和职责分离？
      拥有：Policy、Admission、Permission、Audit、Gate、Waiver
      不拥有：业务价值裁决、普通任务生产、第二套执行状态
      EXISTS（进入 subtraction）
      落地板块：恢复准入
      S7 运行与执行体系
      如何把已授权承诺稳定变成可验证行动？
      拥有：WorkPacket、WorkflowRun、Dispatch、ActionReceipt、Recovery
      不拥有：目标、价值、历史事实重写和自我授权
      EXTEND
      落地板块：Agent 协同 · 能力与 BOS · 事件日志 · 技能清单
      S8 价值验证与进化体系
      行动是否有意义，系统应如何改变？
      拥有：Outcome、HumanVerdict、EvolutionProposal、Experiment、PromotionDecision
      不拥有：自我批准宪法、权限、价值标准和高风险能力
      BUILD-IN-PLACE（下一阶段最重要补强点）
      落地板块：价值验收 · 经验与结晶 · 指标度量

      ⚏ 五个横切平面 (CP-*)

      平面必须覆盖当前判断关键补强
      CP-SEC 安全、隐私与信任身份、数据分级、最小权限、供应链、外发EXTEND从工程权限延伸到业务数据和人类授权 · 落地板块：恢复准入
      CP-REL 可靠性与恢复健康、备份、降级、RTO/RPO、故障演练EXTEND统一关键旅程 SLO，未知不报绿 · 落地板块：健康诊断 · 事件日志
      CP-ECON 资源与经济性时间、注意力、Token、算力、并发、维护成本BUILD-IN-PLACE资源预算进入每个 Decision/BET/Run · 落地板块：指标度量
      CP-TEMP 时间、版本与来源observed_at、validity、schema、causation、migrationEXTEND统一跨体系的 temporal/provenance contract · 落地板块：因果拓扑图谱
      CP-UX 人机体验收件箱、解释、审批、通知、纠错、无障碍EXTENDCockpit 从"系统控制台"收敛为"注意力与结果界面" · 落地板块：主权中心

      横切平面不得各自再造一套业务状态机，通过公共字段、Policy、PEP、Metric 和 View 作用于八个核心体系。CP-* 不覆盖 Workspace 已有 X1=审计、X2=保鲜、X3=价值、X4=一致性 治理轴——二者是多对多实现映射，不得把同名编号原地改义。

      物理分层与唯一执行脊柱（指导）

      P-L4
      目的与主权白皮书、愿景、原则、目标、accepted Spec。

      P-L2
      OMO 控制内核Admission、claim、lease、attempt、fence、receipt。
      P-L1
      执行与恢复动态 Cell、隔离 clone、Direct Local。
      P-L0

      来源：Agent OS 总设计 / 白皮书分层摘要

      一次交付的完整路径（指导）

      意图 / 信号→BET + Spec→Capsule + Admission→claim→执行→独立验证→合并→价值验收→复盘

      Context Pack：C0 宪法指针＋C1 角色＋C2 当前任务＋C3 按需知识。

      制度连续性

      定义→编译→强制→观测→调和→学习→退役
      定义和真实副作用之间，通过 Capsule、摘要、ACK 与确定性门连接。

      价值增强回路

      真实信号 → 交付 → 人类修订/采纳 → 有来源学习 → 更可靠的下一次交付。

      执行控制回路

      期望合同 → 实际运行 → 偏差观测 → fence/调和/回滚 → 再验证。

      元治理慢回路

      制度使用与失效证据 → 提案 → 独立审议 → 修订或减法 → 冷启动复验。
